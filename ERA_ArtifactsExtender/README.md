# ERA_ArtifactsExtender

Добавление обычных артефактов и изменение параметров существующих через JSON ERA. Целевая сборка — **Win32 / ERA с адресами SoD и WoG**. Новые сборники с расширенными масками по согласованию пока не внедряются.

## JSON

Расширитель публикует владение таблицей через `ERA.Services.ArtifactOwner.v1`: `ERA_JsonOverrides` уступает ему применение общих полей. Экспорт также предоставляется самим расширителем через ConfigExport API, включая `primary`, `ai.value`, `image`/`imageFrame` и `mapDef`. Подробнее: [распределение ответственности](../ERA_RuntimeServices/Docs/CONFIG_SERVICES.md).

Разместить JSON в `Mods/<мод>/Lang/`. Пример: [examples/artifacts.json](examples/artifacts.json). Картинку из примера нужно предоставить самостоятельно; при её отсутствии появится заглушка.

Основное пространство — `era.artifacts.<ID>`. В проверенном EXE базовое количество равно 171, первый новый ID — 171. Максимальный ID — 1023. Пропуски разрешены и остаются выключенными. Количество определяется как `max(базовое количество, максимальный объявленный ID + 1)`.

| Поле | Значение |
| --- | --- |
| name, description, event | Имя, описание, текст подбора |
| cost | Неотрицательная стоимость |
| position | Индекс позиции 0–14, пояснение ниже |
| type | Маска: 1 специальный, 2 сокровище, 4 малый, 8 большой, 16 реликт |
| disabled | 0/1, запрет случайного появления |
| hasSpell | 0/1, штатный флаг пересчёта заклинаний; сам список заклинаний не задаёт |
| primary.attack, primary.defence | Бонус атаки / защиты, от -128 до 127 |
| primary.spellPower, primary.knowledge | Бонус силы магии / знаний, от -128 до 127 |
| ai.value | Добавка к оценке ИИ, от 0 до 10000000 |
| image | Картинка кадра с соответствующим ID |
| imageFrame | Кадр группы 0 для отдельного DEF, по умолчанию 0 |
| mapDef | DEF предмета на карте; без него копируется штатный прототип |

Позиции: 0 рюкзак, 1 голова, 2 плечи, 3 шея, 4 правая рука, 5 левая рука, 6 тело, 7 любое кольцо, 8 ноги, 9 прочее, 10 баллиста, 11 повозка, 12 палатка, 13 катапульта, 14 книга магии. Это индексы таблицы позиций, а не номера слотов героя. Значения вроде 65 или 1334 из enum H3API не принимаются: штатный код использует значение как индекс массива.

Отсутствующие параметры существующего артефакта сохраняются. Явные 0 и пустая строка применяются. Некорректные значения отвергаются с записью в `Debug/Era/ERA_ArtifactsExtender.log`. Для нового предмета следует указать имя, позицию и класс.

ID, механика и картинки читаются при запуске; после их изменения нужен перезапуск игры. Смена языка обновляет только тексты.

Старые объявления `<имя мода в нижнем регистре>.artifacts.<индекс>.id` также читаются. Первое объявление ID в порядке VFS побеждает; затем применяются поля общего пространства `era.artifacts.<ID>`.

## Картинки

Графическая часть использует **Graphics API v1 из ERA_RuntimeServices.era**: [контракт сервиса](../ERA_RuntimeServices/Docs/GRAPHICS.md). Обновлять API и оба расширителя следует вместе. Без подходящего API расширитель артефактов не устанавливает таблицы/хуки, причина пишется в лог: новые ID могут превышать размер нативного DEF. Собственных загрузчиков, кэша кадров и палитровых render hooks в расширителе больше нет.

Штатный ресурс — **artifact.def**. Он расширяется только в памяти. Существующие кадры сохраняются, недостающие получают видимую заглушку с вопросительным знаком. Поле `image` заменяет кадр соответствующего ID, включая уже существующий. Неудачная загрузка картинки даёт заглушку.

- PCX8: исходные индексы и палитра сохраняются; индекс 0 прозрачен, индексы 1–255 остаются обычными цветами. Для PNG-подмены ERA в `image` указывается имя PCX, например `test1.pcx`, а PNG размещается в `Data/Pcx` (допускаются подпапки и ZIP/VFS). Подмена считывается через отрисовку ERA: буфер возвращённого PCX содержит только заглушку, а не пиксели PNG.
- DEF: отдельный ресурс, группа 0, кадр `imageFrame`; ссылаться на сам artifact.def нельзя.
- Загрузка внешних PNG/BMP/JPEG/TIFF через Windows Imaging Component временно отключена; код сохранён под `#if 0`. Поле `image` принимает игровые PCX/DEF через штатные загрузчики игры/ERA. Отдельный путь к PNG и другим внешним форматам даёт заглушку; штатные подмены ресурсов ERA продолжают работать.
- Большие изображения вписываются с сохранением пропорций, маленькие центрируются.
- Цвета PNG-подмен и отдельных DEF переводятся в палитру общего DEF; служебные индексы 0–7 исключены из обычных цветов. Alpha ниже 128 и голубой фон RGB(0,255,255) становятся прозрачными. PCX8 не проходит этот перевод. Кадры кодируются RLE-сжатием DEF, чтобы нулевой индекс действительно пропускался при отрисовке; полупрозрачность ограничена форматом индексированного DEF.

Повторная загрузка ресурса обрабатывается хуком загрузки расширителя. Общий API кэширует кадры с учётом размеров и полной палитры; созданные кадры живут до завершения процесса, включая выход/загрузку карты.

Для кадров из PCX8 общий API удерживает исходный ресурс с его рабочей палитрой. Его перехватчики интерфейсной отрисовки `0x47BE90` и `0x47E880` подставляют эту палитру только для соответствующих созданных кадров; палитра общего DEF и остальные кадры не меняются. Это сохраняет оттенки, которых нет в artifact.def, и поддерживает нативные 16-битные и HD 32-битные палитры. API устанавливает хуки после инициализации графики ERA/HD с сохранением существующей цепочки вызовов, затем публикует `OnGraphicsResourcesReady`, по которому расширитель создаёт картинки.

Сборка кадров начинается после применения JSON и `OnAfterCreateWindow`: именно в этом событии ERA устанавливает загрузку и отрисовку PNG-подмен. До него `PcxPngExists` уже может вернуть успех, но вызов загрузчика PCX покажет ошибку отсутствующего ресурса и вернёт `default.pcx` размером 32×32. Ранние загрузки artifact.def не обрабатываются, чтобы не кэшировать такие ошибочные кадры. PNG отрисовывается на голубом фоне; полностью прозрачные пиксели сохраняют прозрачность, полупрозрачные смешиваются с этим фоном перед переводом в палитру DEF.

## ИИ, ERM и сохранения

Ёмкость таблиц параметров, бонусов, текстов и оценок ИИ — 1024. Перемещения публикуются через RedirectMemoryBlock для обновления указателей ERA в OnAfterStructRelocations. UN:A и SN:H для имён получают актуальную границу ID и резервные тексты.

Для ID от 144 запреты и состояние случайного выбора хранятся отдельно от коротких массивов H3Main. Учтены записи запретов из заданий и условий победы. Прототипы новых предметов добавляются в игровые objectLists после Objects.txt.

Первичные бонусы оцениваются штатными свойствами ИИ; остальные родные свойства сохраняются. Новым предметам добавляется cost / 5, либо явно заданный ai.value. Это добавка к штатной оценке. Особые эффекты Artifacts_AddingNewFeatures автоматически не оцениваются; для них можно задать ai.value.

Секция `ERA_ArtifactsExtender.v1` хранит дополнительные числовые параметры, привязки к z-переменным, запреты и состояние случайного выбора. Размер штатного блока WoG не увеличивается. Старое сохранение без секции использует JSON-значения по умолчанию. Сохранения с новыми предметами требуют того же набора модов и конфигурации ID. Смена языка обновляет тексты, сохраняя активные привязки ERM.

## Ограничения этапа

- Новые сборники с расширенными масками отложены: [COMBINATIONS_PLAN.md](COMBINATIONS_PLAN.md). Поля comboArtifactId и partOfComboArtifactId не создают сборник. Не использовать их для новых сборников, в том числе через ERA_JsonOverrides.
- Существующие сборники сохраняют прежние маски и границы обходов компонентов. Увеличивать эти обходы до 1024 до расширения масок нельзя.
- Боевые эффекты остаются в Artifacts_AddingNewFeatures, чей загрузчик рассчитывает на ёмкость 1024.
- Интерфейс редактора карт, собственные таблицы и диалоги RMG требуют отдельных изменений.
- Совместная работа с Emerald и другими владельцами перемещённых таблиц не поддерживается. Проверка отклоняет ранее зарегистрированное перемещение; обратный порядок загрузки также не делает плагины совместимыми.
- Выполнены сборка, автономные тесты и запуск установленной игры до главного меню. Полный игровой прогон ещё требуется.

## Сборка и проверка

Проект ERA_ArtifactsExtender.vcxproj, Release / Win32, C++17. Локальная сборка находится в `build/ERA_ArtifactsExtender.era`. Исправленная сборка установлена в `Mods/WoG/EraPlugins`; предыдущая сохранена в `build/ERA_ArtifactsExtender.before-startup-fix.era`. Общие Directory.Build.props по умолчанию направляют результат в игру: для локальной сборки явно переопределить PluginOutDir и IntDir.

`tests/RunTests.cmd` проверяет production-код JSON, записи сохранения и предикат совместимости на данных исходного EXE и после InitWoG. Тесты RLE, палитры, выделения таблицы и политики ресурсов перенесены в API. Общая сборка и проверки: `ERA_RuntimeServices/Verification/BuildGraphics.cmd`; проверка обоих атласов в игре: `ERA_RuntimeServices/Verification/VerifyGraphicsResources.ps1`.

`python tools/verify_executable.py "<каталог игры>/h3era.exe"` проверяет исходный EXE без изменения файла. Подтверждены 38 операндов и поток из 135 записей ИИ. Это не проверка конфликтов патчей в запущенной игре.

Проверка запуска 18.10.2026: под отладчиком достигнут вход в главное меню с тестовыми ID 171–174, количеством 175 и четырьмя PNG. Проверены также отсутствующие PCX/DEF (заглушки), PCX из LOD и отдельный DEF. Нативный вектор описаний объектов дополняется через AddObjectAttribute: H3API::Push присваивает строки в несконструированный запас массива игры и вызывал стартовый вылет. Добавление выполняется после JSON, чтобы учитывать mapDef. Отсутствующие ресурсы проверяются до штатного загрузчика с его модальными ошибками.

Проверка PNG-подмен 20.10.2026: отладчик воспроизвёл четыре обращения к ошибке загрузчика PCX по адресу `0x55AC05` до `OnAfterCreateWindow`. После исправления игра дошла до главного меню без этих обращений; `test1.pcx`–`test4.pcx` получили исходные размеры PNG 44×44 вместо запасных 32×32. Проверены данные четырёх созданных RLE-кадров: разные изображения, 53–90 цветов и прозрачные пиксели. Win32 Release и автономные тесты прошли; исправленная сборка установлена в `Mods/WoG/EraPlugins`, предыдущая сохранена в `build/ERA_ArtifactsExtender.before-png-startup-fix.era`.

Проверка PCX8 20.10.2026: на `artslot.pcx` воспроизведена потеря тёмно-коричневых оттенков при переводе в общую палитру. После сохранения исходной палитры результат игрового рендерера попиксельно совпал с исходным PCX после уменьшения 47×47 → 44×44. Проверены оба интерфейсных входа, обычная игра (16 бит) и HD (32 бита), а также отдельный PCX со всеми индексами 0–255, прозрачностью и центрированием. Во всех сравнениях — 0 отличающихся пикселей. Предыдущая установленная сборка сохранена в `build/ERA_ArtifactsExtender.before-pcx8-fix.era`; временные ресурсы теста удалены.

Справка ERA_HelpDialog использует количество из `0x717020`. H3API::H3ArtifactCount читает `0x44D1AA`, где находится граница маски компонентов (160 в WoG), поэтому для каталога эта обёртка не подходит. Граница масок не увеличивалась.

Перед выпуском проверить: получение/снятие ID 171 и 1023, обмен, рюкзак, подбор на карте, экипировку ИИ, UN:A и SN:H, сохранение/загрузку, старое сохранение, повторную новую игру, смену языка, отсутствующую картинку, короткий и уже полный artifact.def, сборку/разборку старых комплектов.

Выводы исследования: [RESEARCH.md](RESEARCH.md). Старые ArtifactsData.cpp/h в этой папке не включены в проект; действующая реализация дополнительных эффектов — отдельный Artifacts_AddingNewFeatures.
