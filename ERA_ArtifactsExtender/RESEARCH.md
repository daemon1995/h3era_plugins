# Исследование расширения артефактов

Изучены ERA_ArtifactsExtender, Artifacts_AddingNewFeatures, Yuji/emerald, HotA_ArtifactTables.cpp, WoG Sources/common.cpp и erm.cpp, игровые и редакторские обработчики JSON. В текущем дереве файлы редактора называются ArtifactHandler.h и ArtifactHandler.cpp, без суффикса _e.

Опорные адреса сверены с локальным IDA-экспортом h3era HD.exe из Documents/ChatGPT/EraPlugins/export и дизассемблированием установленного h3era.exe через dumpbin. README.md и TASK.md рядом с экспортом содержат документацию экспортёра и примеры запросов; они использованы как справка.

## Проблемы прежнего расширителя

- ArtifactData читал только ID, параметры не применялись. Количество считалось по числу деклараций, максимальный ID терялся.
- Исходные H3ArtifactSetup не копировались: memcpy был закомментирован. Оставались тестовые ID 171, имя Tome of Earth и бонус 123.
- Бонусы занимают четыре байта на ID, а не четыре DWORD. Длины исходной таблицы и обхода компонентов нельзя считать одинаковыми: у исходного EXE обход 144, после InitWoG — 160, при таблице WoG на 171 запись.
- Пример расширения DEF освобождал ресурс перед дальнейшим обращением и не создавал кадры.
- Таблица ИИ не устанавливалась. Её векторы занимают 16 байт на ID, исходный конструктор рассчитан на 144 элемента.
- Часть операндов ArtNames имела смещение +4 вместо +3. Отсутствовали некоторые ссылки на резервное описание.
- Увеличение счётчиков Saver/Loader изменяло неверсированный блок WoG.

## WoG / ERA

Массивы запретов и случайного выбора H3Main имеют длину 144. Простое увеличение проверки ArtDisabled обращается к соседним полям структуры; таблица WoG на 171 запись этого не исправляет.

Резервная таблица использует 32 байта на артефакт, привязки к z — 8 байт. Перемещать нужно прямые ссылки, размеры копирования ResetERM и границы очистки. ERA обновляет указатели в OnAfterStructRelocations через GetRealAddr и текущий 0x660B68. SN:H получает число из 0x7324BD.

У ARTEVENT смещённая база: загрузчик пишет первый текст по base + 4, потребители используют указатель уже на первый текст. В исходном EXE предел 144, но InitWoG из _B1.cpp увеличивает его до 171. Расширитель определяет текущую длину после WoG и сохраняет её. Увеличивать чтение TXT до 1024 без расширения TXT нельзя; запас таблицы заполняется JSON-событиями.

## ИИ

Отдельно существуют массив 16-байтных векторов и поток описателей свойств. Исходный поток имеет 637 int, завершается -100 и содержит 135 записей. Формат: ID, свойства с аргументами, -1. Типы 11, 16, 17 имеют по два аргумента, некоторые типы не имеют аргументов.

У переопределённых первичных бонусов заменяются только свойства 0–2, остальные сохраняются. Добавляются оценки новых предметов. Native setup вызывается по 0x4EE021, раньше перехваченного 0x4EE036, поэтому после JSON объекты свойств пересобираются.

Увеличение таблицы ИИ не разрешает увеличение обхода старой маски компонентов. Эти границы оставлены прежними.

У 0x4336C0 есть живой вход EDX: он сохраняется по 0x4336D1, при этом функция завершает вызов ret 0Ch. Поэтому мост сохраняет ECX, EDX и три стековых аргумента через FASTCALL. Указанный в IDA thiscall недостаточен для описания этого ABI.

## DEF

Штатное имя — artifact.def. DefGroup_Add_DefFrame по 0x47B1C0 лишь проверяет count < spritesSize и не расширяет массив. Нужно настоящее выделение памяти. Деструктор группы 0x47B1B0 освобождает массив указателей, а не кадры. Новые кадры создаются игровым конструктором 0x47BBD0 с собственным rawData.

RGB-картинку нельзя просто вставить в независимой палитре: её цвета переводятся в палитру общего DEF, прозрачный индекс сохраняется. Кадры удерживаются на время жизни патчей.

## Границы этапа

ArtifactHandler читает era.artifacts и динамическое число. Однако чтение comboArtifactId/partOfComboArtifactId не строит маски. Общая JsonOverridesSchema.hpp проверяет partOfComboArtifactId относительно количества артефактов, хотя это индекс комбинации. Согласованное исправление нужно выполнить вместе со схемой новых сборников. До этого нельзя создавать сборники этими полями, включая отдельный ERA_JsonOverrides.

Редактор имеет свои адреса и таблицы. RMG имеет собственные таблицы/маски и интерфейс запретов. Перенос игровых патчей туда автоматически не обеспечивает поддержку.

Win32 Release и автономные тесты выполнены, проверены 38 исходных операндов и поток ИИ. 18.10.2026 установленная игра под отладчиком дошла до входа в главное меню с четырьмя новыми артефактами и PNG-иконками. Полный цикл сохранения/загрузки и работа ИИ требуют игрового прогона.

Стартовый вылет был воспроизведён в H3String::Assign по 0x40419D при H3Vector::Push нового H3ObjectAttributes. Запас нативного вектора не содержит сконструированных строк; нужен штатный H3MainSetup::AddObjectAttribute (0x4D15F0), который корректно создаёт элементы. Вставка отложена до чтения JSON. Отсутствующие PCX/DEF проверяются в кэше, файлах и актуальных LOD-списках до обращения к штатным загрузчикам. Режим SoD+AB имеет индекс 3; предел 2 ошибочно отвергает ресурсы из архивов.

H3API::H3ArtifactCount получает число из 0x44D1AA — границы проверяемой маски компонентов, после InitWoG равной 160. Это не длина расширяемой таблицы. В ERA_HelpDialog все обходы и проверки ID переведены на 0x717020; игровые маски при этом не меняются.
