# План расширения масок сборников

**Статус: проектирование; увеличение масок и соответствующие хуки не внедрены.**

## Размеры

Запись SoD/WoG содержит ID результата и пять DWORD компонентов: 24 байта. Физическая маска вмещает 160 ID, хотя многие обходы ограничены 144. У WoG имеется 32 записи комбинаций. comboArtifactId у результата и partOfComboArtifactId у компонента хранят индекс комбинации, а не ID предмета.

Для 1024 ID нужна маска из 32 DWORD, 128 байт; запись результата с маской — 132 байта. Сначала целесообразно сохранить 32 комбинации и отдельно расширять их количество после проверки всех потребителей нового размера.

Текущий код расширяет таблицы, сохраняя прежние длины обхода масок. Нельзя подменить только предел 160 на 1024 в BuildUpCombo или конец таблицы бонусов: это создаёт чтение за концом маски.

## Последовательность

1. Ввести единую запись `id + uint32_t parts[32]` и операции set/test/clear. Перевести на неё создание штатных комплектов и WoG BuildUpCombo/CleanUpCombo. Публиковать указатель после проверки новых данных.
2. Скопировать 32 существующие записи с нулевым расширением; заменить 0x660B6C, прямые ссылки WoG и временную BUC_Str. Исключить копирование с прежним stride 24.
3. Проверить все умножения индекса на 24, включая lea с последующим масштабом 8. HotA_ArtifactTables.cpp и emerald/ArtifactCombos.cpp использовать как карту потребителей, проверяя инструкции каждого адреса.
4. Заменить локальные маски на стеке и их копирование. Особое внимание 0x4DD550, 0x4E27C0, 0x4E2E40, 0x4E32F0: согласовать смещения локальных переменных, пролог, эпилог и memcpy.
5. После этого увеличить обходы компонентов в проверке слотов, экипировке/снятии, выдаче заклинаний, описании, сборке/разборке и проверке наличия. Убирать границу 144/160 только у потребителей уже новой маски.
6. Перевести оценку компонентов ИИ на 1024. Ссылки конца в 0x433957/0x4339B1 сейчас намеренно сохраняют старый span. Избежать двойной оценки результата и компонентов.
7. Добавить список компонентов JSON, например combination.parts. Из него строить маску, связи обоих направлений, стоимость и флаг заклинаний. Не допускать независимую установку числовых ссылок. Проверять циклы, дубликаты, существование ID, конфликт наборов и слотов.
8. Добавить версионированное сохранение комбинаций, создаваемых ERM, и атомарное восстановление. Старый блок WoG с 24-байтными записями нельзя просто увеличить. Согласовать ERM UN:A и старые сохранения.
9. Отдельно расширить редактор/RMG: выбор компонентов, настройки и таблицы.

## Опорные потребители

| Область | Адреса для исследования |
| --- | --- |
| Создание комбинаций | 0x44C500, 0x44C630 |
| WoG CleanUpCombo / BuildUpCombo | 0x716F50, 0x716FE5 |
| Проверка бита | 0x44D1A0 |
| Заклинания / разборка | 0x4D95C0, 0x4D9840, 0x4D9DA0 |
| Описание, мораль, удача | семейства 0x4DC310–0x4DDF80 |
| Слоты и надевание | 0x4E27C0, 0x4E2AB0, 0x4E2C70 |
| Снятие и дополнительные обходы | 0x4E2E40, 0x4E32F0, семейства 0x4E39xx–0x4E49xx |
| Оценка ИИ | 0x4336C0 |

Это опорные точки, не готовый полный список патчей. У Emerald маска имеет 30 DWORD, 960 бит: её размер нельзя механически принять за 1024.

## Проверки

Компоненты 143, 144, 159, 160, 171 и 1023; границы DWORD 31/32 и 63/64; сборка/разборка человеком и ИИ; занятые слоты колец/прочего; обмен, рюкзак, бой; заклинания компонентов; новая игра после загрузки; сохранение ERM-комбинаций; смена языка. Сравнить навыки, заклинания и оценку ИИ до сборки и после разборки. Проверить отсутствие обращений со старым stride в дизассемблировании.
