# ERA_SystemOptionsExtension

Исправление переигровки от 16.10.2026: обработчик `OnBattleReplay` снимает временные параметры предыдущей попытки и устанавливает ручной режим на время повтора. Раньше BattleReplay обнулял только игровой флаг, а плагин настроек продолжал хранить временное значение быстрого боя. При штатной записи настроек из обработки заклинания (`0x4799FA`/`0x479A15` → `0x50C370`) оно возвращалось в игру: пропадала подсветка области, а отмена выбора цели запускала мгновенный расчёт. Теперь запись настроек возобновляет ручной режим; постоянный тип битвы и автозаклинания сохраняются для следующих боёв. Регрессионные проверки охватывают повторные попытки, вложенную запись настроек, Q/A внутри повтора, изменение автозаклинаний и загрузку во время записи.

Исправление Q от 15.10.2026: мгновенное завершение разрешено только при одном человеческом владельце стороны и локальном управлении. В сетевом PvP combatManager->isHuman может отражать лишь локальную сторону, поэтому проверяются combatManager->heroOwner и main->players[owner].isHuman. В бою двух людей нажатие и отпускание Q поглощаются до вызова окна; отмена вопроса также не передаёт Q следующему обработчику. Опция мгновенного завершения через кнопку автобоя использует ту же проверку. Против человека кнопка сохраняет штатное поведение. Целевая проверка CombatSettings.tests.exe --pvp-only охватывает обе сетевые стороны, Hot Seat, ИИ и нейтралов.

Исправление сетевой загрузки от 14.10.2026: дамп и владельцы двух блокировок подтвердили взаимную блокировку потоков VFS при переборе Games из BattleSave.OnBeforeLoadGame. RecoverOwnedFiles теперь проверяет точные имена BATTLE!.GM0–GM8/CGM/TGM, без FindFirstFile/FindNextFile. Текущая транзакция удаляет свой известный временный файл; неизвестные .new старых процессов остаются неопубликованными. Выполнены одна целевая группа run-battlesave-tests.cmd --recovery-only и Release-сборка. Для проверки обычного сетевого круга после отката обе игры нужно перезапустить с обновлённой DLL.

Дополнительные настройки плагина и параметры полоски здоровья хранятся в штатном `heroes3.ini` и записываются через ERA API. Стандартные настройки сохраняет сама игра. Язык и кодировка управляются `ERA_LocaleManager`.

При запуске плагин читает дополнительные настройки из `[Settings.Extra]`, а настройки полоски здоровья — из `[CombatHints]`. Если дополнительное значение отсутствует, используется значение по умолчанию. Стандартные игровые настройки загружает сама игра. Плагин не читает старый файл `Runtime/era_system_options.ini`.

Открытие окна само по себе не вызывает запись. Изменения применяются сразу; собственные настройки плагина сохраняются при закрытии окна, а `SetOptionValue` записывает их сразу. Стандартные настройки сохраняет игра. При ошибке записи значения остаются активными, признак несохранённых изменений сохраняется для повторной попытки. Окно показывает сообщение об ошибке; API возвращает `-3`.

Выбор языка через `ERA_LocaleManager`, включая вызов из окна настроек, сохраняет `Language` и `CodePage` только в `heroes3.ini`. Игра/ERA загружает эти значения при запуске. Плагин настроек не загружает и не сохраняет локализацию в своём файле; оставшиеся записи старой секции `[Locale]` игнорируются.

## Секции файла

| Секция | Содержимое |
| --- | --- |
| `Settings.Extra` | Дополнительные опции из таблицы ниже |
| `CombatHints` | `held`, `keyCode` (Windows virtual-key), `fillColor`, `lossColor`, `colorSaturation`, `yLabelShift` |

У полоски здоровья один сохраняемый флаг включения: `Settings.Extra.Combat.ShowCreatureHealthBar`. Цвета и насыщенность допустимы в диапазоне `0..1`, смещение — `-18..18`. Неверные числовые значения игнорируются. Ползунки включают обе границы диапазона; сброс сохраняет точные значения по умолчанию, включая `lossColor=0.975`.

## API

Экспорты с `__stdcall`: `GetOptionValue(const char*)`, `SetOptionValue(const char*, int)`, `SaveOptions()`. Типы и коды результата доступны в `headers/EraPluginsAPI/SystemOptionsAPI.h`.

`GetOptionValue` возвращает текущее настроенное значение или `-1` для неизвестного ключа. `SetOptionValue` ограничивает значение допустимым диапазоном и возвращает:

| Код | Значение |
| --- | --- |
| `1` | Опция изменена; собственные настройки плагина записаны, стандартные сохранит игра |
| `0` | Значение опции не изменилось; несохранённые настройки плагина записаны |
| `-1` | Ключ неизвестен или равен `nullptr` |
| `-2` | Изменение отклонено: очередь ходов/тип битвы во время боя либо включение звука без доступного драйвера |
| `-3` | Изменение действует в памяти, но запись не удалась; можно повторить `SaveOptions()` |

`SaveOptions` принудительно сохраняет дополнительные настройки плагина и возвращает `BOOL`. Изменения через API отражаются в открытом окне и не перезаписываются устаревшим состоянием элементов при закрытии. Временные флаги быстрого завершения боя не сохраняются; изменение настроенных автозаклинаний через API во время временного переопределения переживает восстановление после боя.

| Ключ дополнительных опций | Диапазон | По умолчанию |
| --- | --- | --- |
| `Sound.AlternativeButtonClick` | `0..1` | `0` |
| `Sound.BackgroundLooping` | `0..1` | `1` |
| `Combat.QuickAutoResolve` | `0..1` | `0` |
| `Combat.BattleQueue` | `0..1` | `1` |
| `Combat.QuickCombatType` | `0..3` | `0` |
| `Combat.ShowCreatureHealthBar` | `0..1` | `1` |
| `Combat.SaveBeforeBattle` | `0..1` | `1` |
| `AdvMap.SmoothMapScroll` | `0..1` | `1` |
| `AdvMap.ObjectGlow` | `0..1` | `1` |

«Подсветка объектов» находится на странице «Карта приключений» сразу под плавной прокруткой. Чекбокс создаётся только при загруженном `ERA_RuntimeServices.era` с экспортом `Erm_SetObjectGlowEnabled`. Изменение применяется сразу и сохраняется общим механизмом настроек; при отсутствии API значение остаётся в конфигурации. Переводы находятся в `lang/era_system_options_object_glow.json` и `lang/ru/era_system_options_object_glow.json`; их следует копировать в одноимённые каталоги мода вместе с плагинами.

```ini
[Settings.Extra]
AdvMap.ObjectGlow=1
```

При первоначальном применении настроек и на `OnGameEnter` плагин циклом регистрирует через `Erm_SetObjectGlow` все подтипы четырёх объектов из MD: мистический сад (55), водяное колесо (109), ветряную мельницу (112) и склад (142). При входе на новую или загруженную карту регистрация повторяется, поскольку API очищает переопределения при смене карты. Общий выключатель восстанавливается из `AdvMap.ObjectGlow`.

Тип битвы: `0` — ручной, `1` — быстрый с заклинаниями, `2` — быстрый без заклинаний, `3` — спрашивать. Если значение не сохранено, используется ручной бой.

Источником режима служит `Combat.QuickCombatType`. Штатный флаг быстрого боя временно меняется для выбранной битвы, поэтому окно настроек не использует его для переопределения сохранённого режима. Защитник использует тот же универсальный обработчик выбора, что и атакующий; отдельное событие защитника не меняет этот флаг. Индексы игроков проверяются до обращения к массиву; нейтральная сторона (`-1`) и отсутствие атакующего героя допустимы. Бой двух людей и обучение проходят вручную, а в сети вопрос показывается только локальному участнику.

При штатной записи настроек игра получает постоянные значения быстрого боя и автозаклинаний. После записи продолжают действовать временные значения текущей битвы. Восстановление выполняется при завершении и отмене боя, выходе и загрузке, включая загрузку из боя. Возврат старого обработчика после загрузки не восстанавливает флаги и ERM-переменные прежней игры. Отмена вопроса или неверный ответ переводят текущую битву в ручной режим, сохраняя опцию «Спрашивать».

Диалог `IF:G` возвращает в `v1` битовую маску: `1` — ручной бой, `2` — быстрый с заклинаниями, `4` — быстрый без заклинаний. Запоминается индекс выбранного пункта `0..2`; предварительный выбор следующего диалога передаётся как `1 << индекс`. Маски с несколькими установленными битами и биты отсутствующих пунктов не принимаются как ответ радиодиалога.

| Ключ стандартных опций | Диапазон |
| --- | --- |
| `AdvMap.EnemySpeed` | `2..5` |
| `AdvMap.PlayerSpeed` | `1..4` |
| `AdvMap.ScrollSpeed` | `0..2` |
| `Sound.MusicVolume`, `Sound.EffectsVolume` | `0..9` |
| `Sound.LastMusicVolume`, `Sound.LastEffectsVolume` | `0..9` |
| `AdvMap.AutoSave`, `AdvMap.ShowRoute`, `AdvMap.MoveReminder` | `0..1` |
| `System.VideoSubtitles`, `System.BuildingOutlines`, `System.SpellBookAnimation`, `System.VideoQuality` | `0..1` |
| `Combat.AutoCreatures`, `Combat.AutoSpells`, `Combat.AutoCatapult`, `Combat.AutoBallista`, `Combat.AutoFirstAidTent` | `0..1` |
| `Combat.HexGrid`, `Combat.CursorShadow`, `Combat.MovementShadow` | `0..1` |
| `Combat.CreatureInfo` | `0..2` |
| `Combat.AnimationSpeed` | `0..9` |

## Быстрое завершение боя

В бою человека против компьютера `Q` предлагает быстро завершить битву. Если включён `Combat.QuickAutoResolve`, кнопка «Автобитва» и её штатная клавиша `A` запускают тот же механизм без подтверждения. Он временно включает быстрый бой и отключает автозаклинания; исходные настройки восстанавливаются после боя. Реализация перенесена из WND, поэтому одновременно следует использовать сборку WND без старых обработчиков `Q`.

Переопределение от `Q`/`A` снимается отдельно от выбранного режима текущей битвы. Изменения постоянных автозаклинаний через API сохраняются при обоих этапах восстановления. Загрузка по `L`/`Ctrl+L` из боя доступна в одиночной игре.

## Сохранение перед боем

Начиная с версии `1.7.0`, модуль из `igrik.BattleSave` входит в плагин настроек. Переключатель «Сохранение перед боем» находится на странице «Карта приключений», под выбором типа боя. Значение `Combat.SaveBeforeBattle` хранится в `[Settings.Extra]` файла `heroes3.ini` и доступно через общий API. По умолчанию включено.

Сохранение `BATTLE!` создаётся при подтверждённом входе в бой, когда атакующий герой принадлежит локальному человеку и сейчас его ход. Отмена нападения не создаёт файл. Нападения ИИ, защита города, бой чужого сетевого героя и воспроизведение сетевых перемещений не получают новое автосохранение. Это сохраняет ограничения исходного BattleSave; переигровка битвы остаётся отдельным плагином.

Перенесены безопасная запись через временный файл и резервную копию, проверка результата сериализации и gzip, восстановление после прерванной замены, учёт отложенных событий, лодок и безопасной позиции при полёте/хождении по воде. При неуспешной записи прежний `BATTLE!` сохраняется. При загрузке секция `BattleSave.Repair.v1` восстанавливает позицию и движение героя; её чтение работает и при выключенном автосохранении. Исправлена проверка уровней карты: число уровней равно `1 + hasUnderground`, а не самому флагу подземелья.

Отдельный `BattleSave.era` следует отключить. Модуль использует прежнее имя экземпляра патчера `igrik.BattleSave`; если оно уже занято или проверка совместимости хуков не прошла, встроенное сохранение недоступно и его переключатель заблокирован. Остальные настройки продолжают работать. Хуки модуля находятся в отдельном экземпляре патчера, поэтому их откат не затрагивает другие функции настроек. Поддержаны предусмотренные исходником обёртки `HD.WoG` и `wzx_HW`; остальные изменения этих точек требуют отдельной проверки совместимости.

Подтверждение боя выполняется коротким LoHook внутри штатной `DoCombat`, после вызова оригинала внешними обёртками. BattleSave больше не перенаправляет весь вызов битвы через `THISCALL_11`. Два LoHook на обычных выходах снимают защиту от вложенных битв; при загрузке или выходе из игры она сбрасывается отдельно. Обработчик `Y_PreBattle` использует `__stdcall`, как требует `EXTENDED_`, и вызывает оригинальную функцию через `CDECL_0`.

`run-battlesave-tests.cmd` запускает проверки производственного кода из x86 Developer Command Prompt: уровни карты, формирование записи восстановления, замена реальных временных файлов, сохранение прежнего файла при блокировке/изменении подготовленного файла, проверка векторов и переключателя, привязка подготовленного сохранения к бою, отмена и вложенные битвы, сброс состояния при загрузке. Эти проверки не вызывают функции игры. Исходная лицензия сохранена в `BattleSave.LICENSE`.

Перед выпуском нужна ручная проверка в игре: обычное нападение и его отмена, быстрый бой, нападение на объект с отложенным событием, полёт/хождение по воде, высадка с лодки, загрузка `BATTLE!` с включённой и выключенной опцией, карты с подземельем и без него, локальный ход и удалённый ход в сети. Также проверить запуск с отдельным BattleSave и с несовместимым хуком: новая опция должна быть заблокирована, остальные — работать.

## Проверка в игре

`run-combat-settings-tests.cmd` запускает регрессионные проверки из x86 Developer Command Prompt. Проверяются все режимы для атакующего и защитника, нейтральные/неверные индексы, отсутствие атакующего героя, обучение, gosolo, локальность сетевого участника, отмена вопроса, восстановление ERM-переменных при исключении, смена контекста при загрузке, повторное быстрое завершение, вложенная запись настроек и изменения постоянных значений через API. Тесты вызывают производственную логику обработчика с изолированными игровыми данными и заменой ERM-меню; функции и интерфейс игры не вызываются.

Изменить настройки, перезапустить игру и проверить восстановление; вызвать API при открытом окне; проверить смену языка; проверить сброс и крайние положения ползунков; завершить битву через `Q` и через «Автобитву» с включённой/выключенной опцией. Отдельно проверить отказ от завершения боя, все четыре типа битвы, бой двух людей и сетевой бой. Для переигровки: выбрать быстрый бой без заклинаний, на результатах начать повтор, выбрать заклинание с уроном по области и проверить подсветку; отменить выбор цели — бой должен продолжиться вручную. Повторить после открытия настроек боя и ещё одной переигровки; следующий новый бой должен сохранить выбранный быстрый режим. Сценарии требуют ручной проверки в игре.

## Текстовые ресурсы

Все тексты плагина находятся в установленном моде:

- `D:\games\HoMM 3 ERA\Mods\WoG\lang\era_system_options_dlg.json` — базовые английские тексты и резервный язык;
- `D:\games\HoMM 3 ERA\Mods\WoG\lang\ru\era_system_options_dlg.json` — русский перевод.

В этих файлах объединены тексты главного окна, настройки полоски здоровья и названия клавиш, мгновенного автобоя и ошибки сохранения. Они содержат ключи `era.opt.*` и `gem_plugin.combat_hints.text.*`; форматные параметры `%s`, `%d` и `@key@` должны сохраняться в переводах. Для другой установки игры используется та же структура `Mods/WoG/lang`.

Переводы редактируются и поставляются вместе с модом WoG. Дубликаты `lang` в проекте и дополнительные JSON `era_system_options_healthbar`, `era_system_options_quick_combat`, `era_system_options_storage` для этой установки больше не нужны.
