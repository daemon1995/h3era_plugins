# WoG objects in C++

Проект ещё не выпускался. Совместимость с прежними C++-форматами сохранений не требуется.
Релиз — только по отдельному указанию пользователя.

Реализованы все **23 подтипа**, найденные при проверке активных триггеров `OB63/подтип > 0` и именованных аналогов в WoG Scripts. Полный список и особенности переноса — в [PORTING_NOTES.md](PORTING_NOTES.md).

Новые случайные карты используют тип **141**, старые карты с типом **63** по умолчанию обслуживаются теми же C++-обработчиками. Для всех 23 объектов поставляются имена, параметры РМГ и полноценные графические прототипы; они относятся к странице объектов WoG. Настоящая пирамида `63/0` сохраняет штатное поведение.

## Установка

Собрать Release/Win32 проектов `Objects_WoGObjectsExtender` и `RMG_CustomizeObjectProperties`. После закрытия игры запустить:

```powershell
.\Objects_WoGObjectsExtender\Install-WoGObjects.ps1 -GameRoot 'D:\games\HoMM 3 ERA' -Python python
```

Параметр `-Python` принимает полный путь к Python 3.10+. `-CheckOnly` проверяет комплект без изменения игры. Старый `Install-Artificer.ps1` вызывает этот же полный установщик.

Устанавливаются обе DLL, все 23 записи JSON и переводы, проверки в старых ERM-скриптах. Существующие файлы сохраняются в `Mods/WoG/Backup/WoGObjects-*`; при ошибке записи выполняется откат. Перезапустить ERA после установки. В старом сохранении нужно перезагрузить встроенные ERM-скрипты с диска.

Старые ERM-посещения и заменяющая итерация для перенесённых объектов отключаются согласно assoc текущей карты. Генерируются исключительно объекты 141. Вариант Рынка времени `140/0` для Titan's Winter сохраняет свой исходный обработчик. Другие типы объектов по-прежнему обслуживаются своими компонентами WoG и специализированными экстендерами.

## Обработчик конкретного объекта

Для всех 23 перенесённых подтипов обоих типов по умолчанию включён C++.
Ключ `wog_objects.native.plugin_handles.<тип>.<подтип>` хранится в assoc карты: `1` — плагин, `0` — ERM.
Посещение, хинт, AI и защиты в старых скриптах читают этот же ключ. Основные опции WoG больше не выбирают
обработчик объекта; дополнительные игровые правила (продажа артефактов, усиление Камеры смерти и т. п.)
продолжают учитывать свои опции.

Например, ERM-инструкция карты оставляет старый Рынок времени на скрипте:

```erm
!#VRi^wog_objects.native.plugin_handles.63.51^:S0;
```

`141/51` при этом остаётся на C++. Нулевая настройка для 141 передаёт объект скрипту соответствующего типа;
автоматического перенаправления на триггер 63 нет. Четыре гриба и два фонтана настраиваются независимо.
Для дополнительного зелья штатного Фонтана удачи используется ключ `wog_objects.native.plugin_handles.30.0`.
RMG по-прежнему генерирует только тип 141.

Значения по умолчанию записываются на `OnBeforeErmInstructions`, после очистки памяти ERA и до инструкций
карты. При загрузке сейва настройки сохраняются. Единственный служебный ключ `.version` позволяет отличать
старый сейв без настроек от сохранённого `0`: ERA может не сериализовать нулевые assoc-значения.
Сейв без `.version` получает начальные значения один раз. Глобальный реестр ERA здесь не используется.

В `setup` находятся состояния Ремесленника, Камеры смерти, недельные маски Башни тайн и Алтаря,
месячная маска Изумрудной башни, день Камней призыва и бесплатная неделя Живого черепа.
Геройские эффекты и данные, которым недостаточно четырёх байтов, остаются в assoc.
Чтения и записи фиксированных `v/w/z` и ERM-флагов из C++ отсутствуют, старый прогресс не импортируется.
Журнал Пещеры хранится в assoc героя и показывается общей записью при открытии папируса.
У всех объектов биты `[5, 13)` отведены под стандартную маску `visited`. Посещение отмечает
нативная функция `0x4FC620`, включая союзников; чтение отметки использует `0x529B70`.
Запись синхронизируется с клеткой и объектом под героем.

## Диалоги и AI

Зелья перед боем выбираются в одном окне с флажками; показаны запас, эффекты и риск смешения. Академия показывает услуги и цены одним меню. Предложения жилища и Камней призыва объединены с подтверждением покупки; отдельные вступления и повторные сообщения об успешном обучении убраны.

Ремесленник использует штатные DEF-кнопки с нажатыми кадрами, геройские шрифты и текстуры, рамки и строку подсказок. В заголовке отображается фактический DEF посещённого объекта. Названия и описания артефактов берутся из игры; доступны выбор валюты продажи и продажа всего рюкзака с подтверждением общей суммы. Надетые вещи в массовую продажу не входят.

У Пещеры приключений собственный геройский диалог развилок. Слово состояния четырёх залов хранится в assoc объекта, освобождая стандартные биты `visited` в `mapItem->setup`; дополнительные эффекты сохраняются через ERA.

AI учитывает периоды посещения, доступные услуги, ресурсы, вместимость армии и пользу награды. Для опасных боёв требуется запас силы. Для Живого черепа и Зеркала пути домой сохранён нулевой вес AI из исходных скриптов, предотвращающий зацикливание. Обычный Фонтан удачи сохраняет стандартную AI-логику; зелье добавляется отдельным наблюдателем API посещений.

## Проверки

Win32-сборки обеих DLL и автоматические проверки регистрации, транзакций, диалога, состояния Пещеры и установщика проходят. Команды и границы проверок описаны в [PORTING_NOTES.md](PORTING_NOTES.md). Предпросмотр Artificer с настоящими DEF создаётся скриптом `Verification/preview-artificer.py`; это макет, а не снимок работающей игры.

## Поведение

- Обработчик `63/51` и `141/51` выбирается соответствующим assoc-ключом карты; по умолчанию это C++.
- Обслуживаются только игроки-люди; AI получает нулевой вес посещения.
- Проверяются минимум 500 очков движения и наличие навыков; отдельного вступительного окна нет.
- Навыки идут по ID, по восемь в группе. Как в ERM, отмена группы открывает следующую; отмена последней завершает визит.
  Доступны все 28 навыков, включая последнюю группу 24–27, пропущенную исходным скриптом.
- Затем следует подтверждение с картинкой выбранного навыка и проверка золота владельца героя.
- Успешное удаление стоит 2000 золота и ровно 500 очков движения. Ограничения «один навык в день» нет,
  как нет его в исполняемых командах ERM. Отказ и нехватка ресурсов ничего не списывают.
- Warfare учитывает `wog_193_enabled` и видимую позицию навыка в структуре героя. Показывается один навык, удаляются все три связанных компонента.
- Hover показывает название, ПКМ — описание с ценой и расходом движения. Русские тексты исправлены:
  старый перевод обещал 5000 золота и потерю всего запаса движения.
  Для legacy используются отдельные хуки ветки Pyramid (`0x40C5A1`, `0x414F66`), которые пропускают
  обычную пирамиду и неперенесённые WoG-подтипы.

Рынок времени и Ремесленник больше не вызывают ERM. Навыки, порядок отображения и число занятых слотов изменяются в C++; мифрил читается из актуального массива по указателю в операнде `0x073764C + 3`. Запреты артефактов проверяются нативной функцией WoG, с учётом расширенного каталога.

Состояние героев хранится в глобальных assoc: дозы зелий, услуги разбойников, уроки, трофеи, временные эффекты и отметки посещения. Чтения и записи `w` полностью удалены; старый прогресс `w` не импортируется по решению пользователя. Контрольные слова объектов остаются в `mapItem->setup`, кроме полного состояния залов Пещеры в assoc объекта.

Выбор использует штатный многокартинный диалог ERA, тип 10, и `_SetDialog8SelectablePicsMask`. При отсутствии этого экспорта группы Рынка сокращаются до двух картинок. Подробности оставшихся служебных вызовов WoG — в `PORTING_NOTES.md`.

## Проверки

`Verification/run.cmd` запускается из x86 Developer Command Prompt. Тесты компилируют неизменённый
`MarketOfTime.cpp` и `WoGObjectsExtender.cpp` с подставными API игры и проверяют регистрацию обоих типов,
включая случай отсутствующего прототипа `141/51`, одинаковую маршрутизацию и экономику,
отдельный вход посещения WoG, независимое управление двумя типами через assoc,
генерацию только 141, специальные legacy-хинты,
запреты посещения, границы 499/500 и 1999/2000,
отмену группы и подтверждения, корректировку порядка и числа навыков, золото правильного владельца,
все четыре группы навыков, Warfare, хинты и совместимость с диалогом на две картинки.
Эти тесты не запускают игру и не проверяют работу её машинных адресов и хуков.

В игре проверить: посещение `141/51` и `63/51` без повторного ERM-диалога, hover/ПКМ, отмену,
успешное удаление с пересчётом порядка и числа навыков, повторный визит, Warfare,
переключение ключа `63/51` между C++/ERM и RMG, создающую только `141/51`.
