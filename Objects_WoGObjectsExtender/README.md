# WoG objects in C++

Перенесены **Рынок времени** (`141/51`, legacy `63/51`) и **Ремесленник** (`141/52`, legacy `63/52`).
Тип 141 используется для новых случайных карт, тип 63 (`WOG_OBJECT_TYPE`, `PYRAMID`) — для старых карт.
Используется проект `Objects_WoGObjectsExtender` из `H3ObjectExtenders.sln` и API
`RMG_CustomizeObjectProperties`. Остальные объекты добавляются отдельными обработчиками, как `MarketOfTime.cpp`,
и подключаются через общий `WoGObjectsExtender`.

## Подключение

Для обновления Ремесленника запустить `Install-Artificer.ps1` после закрытия игры. Он устанавливает DLL,
объединяет настройки и переводы Ремесленника и добавляет проверки в скрипты 52/78 с резервной копией.
Проверить подготовленные изменения без установки: `Install-Artificer.ps1 -CheckOnly`.
Основной JSON содержит прототипы `141/51` (`AVXMKTT0.def`, value=10000, density=30)
и `141/52` (`ZArtif1.def`, value=5000, density=50). Русский JSON переопределяет тексты для локали `ru`.
Перезапустить ERA после установки JSON: регистрация подтипов проходит при загрузке описаний объектов.

Один экземпляр `WoGObjectsExtender` регистрирует legacy-подтипы `63/1…max` (как минимум до 52)
и всегда объявляет перенесённые `141/51`, `141/52`, даже если их графические прототипы ещё не установлены.
Менеджер строит таблицы делегирования по прототипам и объявлениям экстендеров; отсутствие прототипа
больше не отбрасывает обработчик. Для размещения и RMG всё равно требуется JSON с графическими свойствами.
Менеджер выбирает этот экземпляр по `type/subtype`, после чего родитель вызывает обработчик субобъекта
через `switch`. `MarketOfTime` не наследуется от `ObjectExtender`: посещение, хинты и AI обслуживают
оба типа одной реализацией. Неперенесённые legacy-подтипы возвращают `FALSE` и продолжают работать через ERM.
Настоящая пирамида `63/0` не регистрируется; её поведение и генерация остаются штатными.

Для посещения `63/51` нужен отдельный вход: WoG-обёртка `0x705979` считает пользовательские пирамиды
обработанными и не доходит до общего хука RMG `0x4A819C`. Хук `0x705B18` вызывает родительский `VisitMapItem`,
а при результате `TRUE` возвращает `eax=1` и продолжает с `0x705B1D`, сохраняя очистку пяти аргументов
и завершение WoG-обёртки. Неперенесённые подтипы выполняют исходный helper, `141/51` приходит обычным путём RMG.

Генераторы WoG-семейства теперь создаются только для перенесённых подтипов типа 141 — как при настоящей RMG,
так и при подготовке списка настроек. Для типа 63 родитель возвращает `nullptr`.

В установленном `69 wog - market of time.erm` добавлены проверки ключа реестра ERA
`wog_objects.marketOfTime.handlesLegacy` перед обработкой `!?OB63/51` и заменами при итерации карты.
C++ выставляет ключ после регистрации legacy-подтипа. Поэтому старый ERM не открывает второй диалог
и не создаёт новые `63/51` заменами, пока работает C++-версия. Ключ хранится в памяти процесса,
не в сохранении: при отсутствии новой версии плагина исходный ERM продолжает работать.
Вариант `140/0` из Titan's Winter остаётся на ERM.

Для установки на другом компьютере применить к скрипту 69
`legacy/market-of-time-native-handler.patch`. В старом сохранении может лежать сохранённая копия ERM;
её нужно перезагрузить с диска, чтобы эти проверки тоже вступили в силу.

## Поведение

- Опция WoG 109 активирует legacy-посещение `63/51`. Заблокированные значения 2/3 трактуются
  как выключено/включено. Посещение и генерация `141/51` от этой опции не зависят.
- Обслуживаются только игроки-люди; AI получает нулевой вес посещения.
- Сначала показывается вступление, затем проверяются минимум 500 очков движения и наличие навыков.
- Навыки идут по ID, по восемь в группе. Как в ERM, отмена группы открывает следующую; отмена последней завершает визит.
  Доступны все 28 навыков, включая последнюю группу 24–27, пропущенную исходным скриптом.
- Затем следует подтверждение с картинкой выбранного навыка и проверка золота владельца героя.
- Успешное удаление стоит 2000 золота и ровно 500 очков движения. Ограничения «один навык в день» нет,
  как нет его в исполняемых командах ERM. Отказ и нехватка ресурсов ничего не списывают.
- Warfare учитывает `wog_193_enabled` и `w48` посещающего героя: из трёх связанных навыков показывается один.
- Hover показывает название, ПКМ — описание с ценой и расходом движения. Русские тексты исправлены:
  старый перевод обещал 5000 золота и потерю всего запаса движения.
  Для legacy используются отдельные хуки ветки Pyramid (`0x40C5A1`, `0x414F66`), которые пропускают
  обычную пирамиду и неперенесённые WoG-подтипы.

Посещение, выбор, проверки, хинты и списания выполняются в C++. Единственный мост к ERM — вызов нативного
приёмника ERA `HE<hero>:S<skill>/0` при удалении. Он сохраняет существующие хуки `HE:S`, включая синхронизацию
трёх навыков Warfare из скрипта 14. Функции скрипта 69 не вызываются. Прямой `H3Hero::UnlearnSkill` обошёл бы эти хуки.

Адреса текущих WoG-опций и массива `w` разрешаются через `Era::GetRealAddr`; схема `w` взята из
`Erm.pas`: `[0..255, 1..200]`. Выбор использует штатный многокартинный диалог ERA, тип 10, и
`_SetDialog8SelectablePicsMask`. При отсутствии этого экспорта группы сокращаются до двух картинок.

## Проверки

`Verification/run.cmd` запускается из x86 Developer Command Prompt. Тесты компилируют неизменённый
`MarketOfTime.cpp` и `WoGObjectsExtender.cpp` с подставными API игры и проверяют регистрацию обоих типов,
включая случай отсутствующего прототипа `141/51`, одинаковую маршрутизацию и экономику,
отдельный вход посещения WoG, активацию только legacy,
генерацию только 141, специальные legacy-хинты,
запреты посещения, границы 499/500 и 1999/2000,
отмену группы и подтверждения, отсутствие списания при неудачном удалении, золото правильного владельца,
все четыре группы навыков, Warfare, хинты и совместимость с диалогом на две картинки.
Эти тесты не запускают игру и не проверяют работу её машинных адресов и хуков.

В игре проверить: посещение `141/51` и `63/51` без повторного ERM-диалога, hover/ПКМ, отмену,
успешное удаление с пересчётом порядка и числа навыков, повторный визит, Warfare,
активацию `63/51` опцией 109 и RMG, создающую `141/51` независимо от этой опции.

## Следующие объекты

Для Ремесленника реализованы все четыре услуги, хинты, AI и состояние в `mapItem->setup`.
Посещение открывает нативное окно рынка с DEF объекта и артефактов, динамическими названиями,
карточкой рецепта и описаниями по ПКМ. Продажа одного предмета или всего рюкзака за золото/мифрил
доступна и после двух заказов; массовая продажа требует подтверждения общей суммы.
[Описание C++ и подготовительного ERM2-варианта](Artificer.md). Установка — `Install-Artificer.ps1`
после закрытия игры; новый графический прототип `141/52` и проверки старых скриптов входят в комплект.

С картинки: Adventure Cave, Alms House, Altar of Transformation, Arcane Tower, Battle Academy,
Death Chamber, Emerald Tower, Forgotten Shrine, Junk Merchant, Level 8 Dwellings, Living Skull,
Magic Mushrooms, Mirror of the Home-Way, Mysterious Creature Dwelling, New Creature Banks,
New Creature Dwellings, Palace of Dreams, Power Stones, Potion Fountains, School of Wizardry,
Sphinx и Summoning Stones. Их посещения ещё не перенесены. Системы существ, жилищ и банков стоит
согласовывать с соответствующими экстендерами, сохраняя общий объектный тип 141 для новых обработчиков.
