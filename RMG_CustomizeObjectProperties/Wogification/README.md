# Настройки объектов вогификации

Диалог «Объекты вогификации» зарегистрирован отдельной кнопкой меню новой игры рядом с настройками RMG. Реализация находится в RMG, размещение остаётся в ERA_RuntimeServices. DLL автоматически в игру не устанавливается.

## Четыре вкладки

- **Чем заменять:** включение цели, относительный вес, максимум экземпляров на всей карте, минимальное евклидово расстояние между одинаковыми объектами на одном уровне, уровни карты и типы карт.
- **Что заменять:** разрешение замены исходника, шанс, минимум сохраняемых экземпляров, разрешённый набор результатов, уровни и типы карт.
- **Существа:** включение замены, список уровней с независимыми галочками, максимальная агрессия только у заменённых отрядов и разрешение замены квестовых отрядов.
- **Артефакты:** включение замены, список классов с независимыми галочками, замена наград банков, добавление знамён и замена свитков отдельно по каждому уровню заклинания.

Большие вкладки используют `RMGmenbt.def`; под ними расположены вкладки категорий. При отсутствии явной категории JSON используется классификация RMG и зарегистрированных расширений. Поиск работает по имени, ID, моду и типу/подтипу. Список прокручивается штатным синим ползунком RMG и колесом мыши. ПКМ по строке показывает сведения и разрешённые наборы. Строка и общий список сбрасываются кнопками `RMG_dfmn.def` и `RMG_dflt.def`. Подтверждение, отмена, справка, фон строк и нижний хинт-бар используют те же ресурсы, что RMG.

«Чем заменять» содержит только новые пары type/subtype, отсутствовавшие в исходном ресурсе объектов до применения `AdditionalProperties`; «Что заменять» — только исходные пары, участвующие в правилах. `AdditionalProperties` хранит точные множества `originalObjects` и `addedObjects`: изменение свойств или добавление другого DEF существующей пары не делает объект новым. Пропуски в нумерации учитываются; максимальный подтип для этой проверки не используется. Исходный снимок снимается один раз, множество добавленных пар обновляется после слияния. Контейнеры содержат значения, поэтому перераспределение нативных массивов не оставляет висячих указателей.

Все добавленные пары автоматически появляются среди целей, даже без генератора RMG или записи каталога. Цель без набора замены изначально выключена; она не размещается даже после ручного включения, пока мод не задаст `targetGroups` и необходимые условия/инициализатор в JSON. Доступность по происхождению проверяется также в API вогификации, включая конкретные подтипы источников с wildcard-правилом. Прежняя цель JSON, уже присутствующая в исходном ресурсе объектов, больше не участвует в замене.

Тюрьмы, хижины провидца и стражи заданий исключены из обеих ролей независимо от JSON. Для расширений также запрещены конкретные подтипы, зарегистрированные в категории `ePagePrison/ePageQuest`. Категория «Тюрьмы и задания» в диалоге вогификации не создаётся; исходный диалог RMG сохраняет свои категории. Проверка API выполняется до возврата значений по умолчанию, поэтому wildcard-правило не разрешает замену защищённого подтипа.

Шанс источника ограничен диапазоном `0..100`, количество сохраняемых исходников — `0..65535`. Умолчание шанса берётся из первого правила по приоритету, сохранение — из максимального требования правил этого источника; JSON может задать другие неотрицательные значения. Старые `-1` в этих полях JSON/INI/профилей преобразуются в конкретные умолчания при загрузке и больше не показываются и не сохраняются отрицательными. Для веса и лимита цели `-1` по-прежнему означает исходный вес правила и отсутствие дополнительного лимита соответственно. Нулевой шанс, вес или лимит запрещает соответствующее появление. Общий множитель вероятности WoG сохраняется там, где правило его использует. Лимит карты учитывает уже существующие объекты, включая объекты под героями; превышение лимита не удаляет их.

Шанс источника использует один результат броска для исходного экземпляра во всех разрешённых наборах. Успешно заменённый экземпляр в следующие наборы уже не попадает. Замены по умолчанию разрешены только на готовых картах (`mapKinds: 1`). Пользователь может явно разрешить случайные карты. Уровни и типы карт переключаются нажатием: `1` — поверхность/готовые, `2` — подземелье/случайные, `3` — оба варианта. Сохранённый явный выбор пользователя в INI/профиле сохраняет приоритет над JSON-умолчаниями.

## Существа и артефакты

Существа и артефакты вынесены из общих таблиц в две самостоятельные вкладки. Включение замены управляет доступностью зависимых настроек; свитки включаются независимо от артефактов. Выпадающие списки уровней поддерживают несколько галочек. Tab последовательно переключает четыре вкладки. Поиск, категории и таблица скрываются на страницах общих параметров. Кнопка умолчаний сбрасывает только параметры текущей страницы, загрузка профиля меняет черновик, отмена отбрасывает его.

Общие параметры `wogify.process` сохраняются как отличия от JSON-умолчаний в разделе `[Process]` INI и профиля. Поля: `creatures.enabled`, `creatures.levels` (маска 255), `creatures.maxAggression`, `creatures.questCreatures`, `artifacts.enabled`, `artifacts.levels` (маска 31: особые, сокровища, малые, великие, реликвии), `artifacts.bankRewards`, `artifacts.bankBanners`, `scrolls.enabled`, `scrolls.level1..level5` и `mapKinds` (1 — готовые, 2 — случайные, 3 — все). По умолчанию все уровни существ и классы артефактов включены, агрессия и замена квестовых отрядов выключены. Старые индивидуальные разделы существ/артефактов в пользовательских INI/профилях не читаются и не записываются; каталог JSON остаётся фильтром допустимых ID для исходных правил.

Максимальная агрессия (`MO:R10/1`) задаётся только после подтверждения созданного отряда. Квестовые отряды определяются по координатам целей заданий `DEFEAT_MONSTER` в `mainSetup.quests`; включение их замены не снимает защиту авторских настроек отряда. После подготовки карты штатный `H3Quests_RefreshData` обновляет отображаемый тип цели.

Замена наград банков по умолчанию выключена. При включении артефакты из неразграбленных банков существ, заброшенных кораблей, утопий, склепов и кораблекрушений проходят через те же правила, шансы, классы и лимиты, что наземные артефакты. Изменяется только выбранный слот награды, объект банка сохраняется. Счётчики API учитывают артефакты в банках. Знамёна включены по умолчанию: прежний шанс 50% и дополнительное гарантированное знамя в утопиях; сохраняются требования опыта отрядов, новых артефактов и разрешённых знамён.

Для каждого уровня свитка выбирается: 0 — оставлять, 1 — случайно сундук или золото, 2 — сундук, 3 — золото. Умолчания: 1/1/0/0/0, как в исходном скрипте. Наполнение сундуков и куч золота остаётся прежним.

Дополнительные экспорты `RMG_WogifyProcessSetting` и `RMG_WogifyQuestCreature` разрешаются независимо от API версии 1. Старая DLL сохраняет исходные умолчания ERM. Эти параметры не включают запрещённые WoG-опции и не создают новые правила выбора ID. Командиры, боевые машины и небоевые слоты по-прежнему исключены из каталога замены. Гарнизоны сохраняют прежний стартовый диалог плотности.

## JSON

Текущие `wogify.objectReplacement.objects` остаются разрешёнными наборами замены. Их WoG-опции, ландшафт, направления подхода, дополнительные клетки, `preserveLast`, `skipOnRmg` и проверки переменных сохраняются. Поле `name` даёт набору отображаемое имя.

Каталог `wogify.objectReplacement.catalog` имеет `schemaVersion: 1`, массив строковых ID `order` и словарь `objects`. Имена ID состоят из ASCII-букв, цифр, `_` и `-`, не зависят от перевода и порядка строк. В одном итоговом каталоге одна пара type/subtype имеет один ID. Доступные роли автоматически обнаруживаются в исходных правилах, поэтому старый JSON работает и без каталога. Каталог добавляет имена, происхождение, категории и умолчания:

```json
{
  "schemaVersion": 1,
  "order": ["my_bank"],
  "objects": {
    "my_bank": {
      "type": 16,
      "subtype": 21,
      "provider": "MyMod",
      "category": "Creature banks",
      "requiresVariable": "my_bank_ready",
      "initializer": "MyBank_InitReplacement",
      "targetGroups": [1],
      "target": {
        "available": 1,
        "enabled": 1,
        "weight": 2,
        "mapLimit": 8,
        "minDistance": 12,
        "levels": 3,
        "mapKinds": 1
      },
      "placement": {"terrain": -1, "approachMask": 255}
    }
  }
}
```

Пример — описание формата, не автоматическое включение стороннего банка. Мод обязан предоставить реальный DEF и работоспособную игровую логику для указанной пары. `requiresPlugin` опционально задаёт имя необходимой DLL, `requiresVariable` — ненулевую ERM i-переменную готовности. `initializer` — имя ERM-функции, принимающей x/y/z/type/subtype после успешного размещения и стандартной WoG-инициализации. Имя проверяется как идентификатор. Старый самостоятельный replacer при переносе нужно отключить в самом моде, чтобы он не выполнял второй проход.

`targetGroups` присоединяет новую цель к существующим наборам без повторения списка их источников. `placement` поддерживает числовые условия старой записи цели: `optionId`, `disabledByOption`, `terrain`, `approachMask`, `skipOnRmg`, `requiredBlockedOffsets`. Строковое условие `requiredVariable` новой цели задаётся через `requiresVariable` каталога. Существующие цели сохраняют все условия своих старых записей. Для новых исходников задаётся запись `sources` разрешённого набора; произвольное наличие DEF не разрешает удалять объект.

Роль `source` содержит `available`, `enabled`, `chance`, `preserve`, `group`, `levels`, `mapKinds`. `group: -1` сохраняет все исходно разрешённые наборы; другое значение может выбирать только один из них. Для `subtype: -1` настройки источника относятся ко всем подтипам данного типа, если нет более конкретной записи источника. Списки `order` должны содержать все ID итоговой сборки; ERA объединяет одноимённые ключи согласно приоритету модов, массив не является автоматической очередью добавления.

## INI и профили

`Runtime/Wogification.ini` и профили сохраняют только отличия от текущих JSON-умолчаний. Начальная папка выбора — `Runtime/WogificationProfiles`; отдельный диалог позволяет переходить по папкам и выбирать другой INI-файл. Кнопки загрузки/сохранения взяты из WoG Options (`WOGOBTN.DEF`, кадры 6/7 и 9/10; для старых ресурсов — `WoGBttn.def`). Окно выбора повторяет компоновку WoG: 512×520, 13 строк папок и файлов, выделение, ползунок, поле имени, подтверждение/отмена. При наличии используются те же ресурсы `WOGOPRST`, `WOGOLST`, `WOGOTXT`, `WOGOPHNT`, `WOGOSCR` и `WOGOSCV`. Двойной щелчок открывает папку или выбирает файл; стрелки выбирают строку, Enter подтверждает, Escape отменяет. Backspace/Left и Home при фокусе списка переходят вверх и в папку профилей. Перезапись существующего файла требует подтверждения.

Формат профиля имеет версию 1; в изменённых записях сохраняется привязка ID к реальным type/subtype. Полностью стандартный профиль содержит только служебную версию. Неизвестные записи пропускаются с сообщением, отсутствующие значения берутся из текущих JSON-умолчаний; ошибочная версия, значение или изменение привязки ID отменяет загрузку целиком. Прежние полные профили читаются, но при следующем сохранении записываются только отличия. Возврат к умолчаниям удаляет прежние переопределения при сохранении, включая перезапись профиля. Загрузка меняет только черновик диалога. **Применить** атомарно сохраняет INI и затем меняет настройки процесса; **Отмена** отбрасывает правки. Сохранение профиля выполняется отдельно от применения INI.

Нижним кнопкам при создании назначаются штатные хоткеи: `S` — сохранить профиль, `L` — загрузить, `R` — умолчания списка, `Enter` — применить, `Esc` — отменить. `H` открывает справку, `Tab` переключает четыре основные вкладки, `1`–`9`, `0` выбирают видимые категории. При переключении основная страница скрывается и деактивируется; хоткей `Tab` назначен только следующей вкладке. Поля ввода теряют фокус при клике вне их границ, включая поиск и поле имени профиля. То же правило применяется в исходном диалоге RMG. Буквенный фильтр RMG действует только при фокусе числового поля.

Нижние кнопки обрабатываются одним маршрутом для отпускания мыши и штатного `END_DIALOG` с пользовательским ID. Рамки добавляются до кнопок и не принимают сообщения мыши. Ошибка валидации или записи не закрывает диалог. Это относится и к окну выбора профиля. Галочка, имя и изображение объекта переключают его при нажатии ЛКМ со звуком клика; отпускание не переключает повторно. Перерисовывается вся строка вместе с фоном, поэтому прозрачные кадры чекбокса не наслаиваются. Декоративные ID строки не запускают действия и валидацию. Событие ввода копируется перед сменой фокуса, а ПКМ проверяет нативный признак правой кнопки и совпадение адресата с элементом под курсором; сведения открываются через `H3Messagebox::RMB`.

## Подключение к ERM и границы

`78 wog - wogify_merged.erm` разрешает полный набор экспортов API версии 1; старые DLL сохраняют прежнее поведение. Перед проходом выполняется `RMG_WogifyBegin`, на выходе внешней функции — `RMG_WogifyEnd`, в том числе после досрочного выхода тела. Начальный снимок живых экземпляров и отметка использованных координат исключают повторную замену созданных объектов между наборами. Список новых целей расширяется адаптером чтения чисел; исходные правила читаются прежним способом.

Перед выбором цели проверяются включение, зависимости, ограничения карты и расстояния. Проверки геометрии, дополнительных клеток, нативная инициализация и обработка отрицательного результата остаются в существующем конвейере. После успешного создания обновляются счётчики и вызывается необязательный обработчик мода. Настройки не изменяют маски и не обходят ограничения RuntimeServices.

Это настройка однократной стартовой замены объектов. Загрузка сохранения не запускает проход повторно; результат размещения сохраняется обычным состоянием карты. Диалог не меняет существующий сетевой запрет геометрического API. Топология не гарантирует сохранения произвольного авторского сценария ERM; текущие разрешённые источники должны учитывать сценарные связи. Ошибка после нативного удаления по-прежнему останавливает проход, универсальный откат сторонних обработчиков не добавлен.

Публичные сигнатуры: `headers/EraPluginsAPI/WogificationAPI.h`. Проверочная сборка и автономная проверка модели не заменяют проверку диалога и новой карты в игре.
