# Сопоставления ABI: старые заголовки igrik → H3API

Таблица ABI первоначально составлялась **по тексту обоих комплектов заголовков**, а не по дизассемблированному файлу. Впоследствии получены `h3era.exe` и две IDA-базы. **Только** адресные правки модуля `MapSize` дополнительно сопоставлены с инструкциями переданного `h3era.exe` (см. `XXL_COMPATIBILITY.md`); остальные ABI-утверждения здесь не подтверждены дизассемблированием. Все адреса относятся к исходной x86-сборке, от которой отталкиваются исходники igrik.

| Данные | Старое API | Новое API | Контроль |
|---|---|---|---|
| Стек в бою | `_BattleStack_` | `h3::H3CombatCreature` | `sizeof = 0x548`; `type +0x34`, `position +0x38`, `secondHexOrientation +0x44`, `numberAlive +0x4C`, `info +0x74` |
| Параметры существа | `_Creature_` / `_CreatureInfo_` | `h3::H3CreatureInformation` | `sizeof = 0x74`; `flags +0x10`, `shootsRay` не равен обычному «нет штрафа от препятствий» |
| Герой | `_Hero_` | `h3::H3Hero` | `owner +0x22`, а не `owner_id`; первичные характеристики в `primarySkill` |
| Армия | `_Army_` | `h3::H3Army` | Массивы `type[7]` и `count[7]`; бинарную совместимость следует перепроверить |
| WoG NPC | `_Npc_` | `WoG::NPC` в `third_party/WoG_NPC.h` | `sizeof = 296`, начало массива записей `0x28620C0`; проверка с заголовком WoG |
| WoG CrExpo | `_CrExpo_` | `WoG::CrExpo` в `include/WoGCrExpo.h` | `sizeof = 0x10`, `experience +0`, `number +4`, `flags +8`, `place +0xC` |
| Результат быстрой битвы ИИ | `_AIQuickBattle_` | `QuickBattleSide` (`AI.cpp`) | `sizeof = 0x34`, `armyStrength +0x1C`, `army +0x28` |
| WAV звук | `_Wav_` | `h3::H3WavFile` | `sizeof = 0x34`. Смещение `+0x28` в старом коде именовано иначе, чем в новом — семантику необходимо подтверждать по дизассемблеру |
| Диалоги | `_Dlg_`, списки предметов | `h3::H3BaseDlg`, `H3DlgItem`, `H3Vector` | Размер/расположение для всего Graphics проверить в конкретном EXE |
| Позиция | старый packed XYZ | `h3::H3Position` | `sizeof = 4`; сдвиги `x,y,z` из `homm3.h` сверять отдельно для WoG |

## Не эквивалентны при прямой подстановке

- `_AIQuickBattle_` нельзя заменять на `H3Army` или на `H3CombatCreature`.
- Поля `WoG::NPC` не принадлежат `h3::H3Hero`, несмотря на то что данные индексируются по ID героя.
- Смещение `0x28` внутри WAV нельзя считать обычным `H3WavFile::lockSemaphore` без дизассемблирования функций Miles/WoG.
- Порядок параметров вызова функции и соглашения `__thiscall`, `__cdecl`, `__fastcall` в бинарных хуках важнее совпадения названия метода.
- Простая замена `_Hero_::spellbook` на поля H3API может изменить поведение, если старый код использует WoG-расширения.
- `GameLogic.incomplete.cpp` — **неисправленный референсный черновик**, не подключать в сборку вместо `GameLogicCore` без дополнительной работы.

Файлы `legacy/src` позволяют восстановить исходную адресацию и сравнить каждый хук. Инвентаризация — `docs/legacy_hook_inventory.json`.


## Упаковка структур (ABI)

В оригинальном `.vcxproj` igrik и перенесённом проекте для Debug/Release Win32 выбран `/Zp1`
(`StructMemberAlignment=1Byte`). **Не** меняйте этот параметр на `/Zp4` ради обхода assert:
размеры структур должны точно совпадать с EXE. При этом сам H3API локально
использует как `#pragma pack(push, 1)` (например `H3Hero`, `H3RGB888`), так и
`#pragma pack(push, 4)` (например `H3CombatCreature`). Эти директивы имеют
приоритет над `/Zp1` для соответствующих объявлений.

WoG-оверлеи теперь явно фиксируют упаковку независимо от настроек VS:

| Структура | Упаковка | Размер | Ключевые смещения |
|---|---|---|---|
| `WoG::CrExpModStr` | 1 | 17 | Type +4, Mod +5, Lvls +6; таблица с шагом 17 |
| `WoG::CrExpo` | 1 | 16 | number +4, flags +8, place +12 |
| `WoG::NPC` | 1 | 296 | parameters +28, arts +84, name +244, abilities +288 |
| `WogLuckString` | 1 | 16 | data +4, length +8, capacity +12 |
| `QuickBattleSide` | 1 | 52 | armyStrength +28, army +40 |
| `h3::H3Hero` | 1 (H3API) | 0x492 | объявление внутри H3API |
| `h3::H3CombatCreature` | 4 (H3API) | 0x548 | info +0x74 |

`__declspec(align(1))` **не заменяет** `#pragma pack(1)`: оно задаёт минимальное
выравнивание и не предотвращает padding в конце структуры. В коде WoG это
было исправлено. Во всех локальных структурах используются парные `push/pop`,
чтобы не изменить выравнивание чужих типов.

Сборка проверяет `src/AbiLayoutChecks.cpp` даже при выключенных экспериментальных
фикcах. `python tests/check_packing.py` проверяет проект и локальные объявления,
но настоящая проверка `sizeof/offsetof` требует компиляции **MSVC Win32**.

Если после пересборки остаются ошибки H3API `static_assert`, нужен полный
текст *первых* ошибок (`C2338`, `C2607`, и т. п.), имя структуры и разница размеров;
нельзя безопасно менять упаковку для всего H3API без этих данных.
