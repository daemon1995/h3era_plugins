# XXL (JackSlater/XXL) + Game Bug Fixes H3API: проверка исходников

## Вывод

Исходники `XXL(1).zip` проанализированы вместе с собираемыми исходниками
`Game_Bug_Fixes_H3API`, а оригинальный `h3era.exe` сверён с сохранёнными
сигнатурами патчей.

**Удалять `MapSizeFixes` из Game Bug Fixes на основании этих исходников XXL
не нужно.** Эти два модуля выполняют разные функции:

| Вопрос | XXL | GBF MapSizeFixes |
|---|---|---|
| Кнопки и выбор размеров H=180 / XH=216 / G=252 | да | нет |
| UI/настройки RMG и шаблоны HD_WOG | да | нет |
| Миникарта на больших картах | да | нет |
| Расширение внутренних буферов WoG AI | нет | да |
| Функции поиска пути WoG по адресам 0x706DDB, 0x70727E, 0x7074FA, 0x7083C0 | нет | да |
| Замена 144→252 в циклах WoG по 0x706E11 / 0x706E30 и др. | нет | да |
| Перенос массива WoG с 0x02933560 на 252 точек | нет | да |

### Факты статической проверки

- XXL: 14 файлов с подходящими расширениями, **75** прямых адресных записей.
  В отличие от старого анализатора учитываются семь `WriteCodePatch("%n", N)`
  с полными длинами 2–70 байт, а также `CreateHiHook`.
- GBF: 16 модулей `src/Fixes/`, **466** статически определимых записей.
- Пересечение **диапазонов байт**, а не только стартовых адресов: **0**.
- В подмножестве `MapSize` старый анализатор нашёл 0 пересечений на 28
  адресах. Данные сохраняются в `docs/xxl_mapsize_collision_report.json`.
- `h3era.exe` SHA-256:
  `451e208cb2985bca75330f0e3c52f89f9219c0c3701bc6e1f354217890c36181`.
  Это тот же хеш, что указан в `XXL/README.md` для локально проверенного EXE.
- `tools/verify_exe_mapsize.py` подтвердил исходные байты всех **28**
  проверяемых сайтов (0 несовпадений).

Подробный машинно-читаемый отчёт: `docs/xxl_full_collision_report.json`.


### Пересечение по семантике, не по адресу

**Обновление выбранной карты при показе списка** происходит из двух мест:

1. В `Graphics.cpp` GBF ставит `CALL_`-хук на **0x587272**. Оригинальная
   инструкция в `h3era.exe` — `call 0x580D40`. После default GBF вызывает
   `0x5857D0`, т.е. обновляет карту.
2. XXL ставит `SPLICE_`-хук на **0x580D40** (`HiHook_00580D40`). После
   default, если `mapListShown`, он тоже вызывает **0x5857D0**.

Если обе ветки выполняются, обновление может происходить дважды. В новой
версии `Graphics.cpp` после вызова default GBF проверяет, загружен ли
модуль `XXL.era`/`XXL.dll` **и** присутствует ли патч на 0x580D40 в
`patcher_x86`. Если так, GBF пропускает собственный дополнительный вызов
`0x5857D0`. Это не запрещает остальные графические исправления. Проверка
выполняется при самом событии, а не при загрузке Game Bug Fixes, чтобы
не зависеть от порядка загрузки плагинов.

Ограничение: если XXL переименован, установлен другим механизмом или тот же
адрес уже занят иным плагином, эта проверка не может надёжно определить
семантического владельца хука. В таком случае необходимо тестирование GUI.

### Что делать с `MapSizeFixes`

- Активные исправления MapSize удалены из GBFE: расширение линии и маршруты
  WoG находятся в XXL. Оригинальный исходник сохранён в `legacy`.
- XXL проверяет сигнатуры и устанавливает связанные хуки маршрутов одной
  группой. Прочие расширители путей или оригинальный GBF могут занимать те же
  адреса; нужна проверка фактического состава и порядка загрузки модов.
- Карты 180/216/252, AI, движущиеся монстры и сохранения ещё нужно проверить
  в игре; автономный x86-стенд не заменяет игровую проверку.

### Ограничения аудита

Анализатор не разрешает адреса динамических сигнатур и таблиц в `HD_WOG.dll`,
не доказывает сохранность цепочки вызовов при порядке загрузки, не исполняет
игровые хуки и не сравнивает все возможные бинарные патчи сторонних плагинов.
У XXL модуль `HdTemplateCompatibility.cpp` модифицирует **динамически
найденные адреса HD_WOG.dll**, поэтому они не включены в 75 адресов EXE.
Отдельная регистрация `0x587FD0` в этом модуле учтена.

**Компиляция MSVC, запуск ERA с двумя плагинами и проверка RMG 252×252
не производились.** Не используйте это заключение как гарантию полной
совместимости, особенно для сетевых партий.
