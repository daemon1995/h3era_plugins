# ERA Options Menu: опции из JSON

Плагин читает описания из загруженных ERA файлов `Mods/<мод>/Lang/*.json`, регистрирует опции по уникальным ключам и показывает их в собственном диалоге. Новые опции не требуют изменений C++ интерфейса. Поддерживаются галочки и выбор одного значения из списка.

## Быстрый запуск

1. Соберите `ERA_OptionsMenu.vcxproj` (`Win32`, C++17). Общие настройки репозитория определяют путь установки; для проверки можно переопределить `PluginOutDir` и `IntDir`.
2. Поместите `ERA_OptionsMenu.era` в `eraplugins` активного мода.
3. Скопируйте [examples/era_options.json](examples/era_options.json) в `Mods/WoG Scripts/Lang/era_options.json`. Пример добавляет пять демонстрационных опций: четыре видимых и одну скрытую. Их значения доступны через API; они сами по себе не включают игровые механики.
4. Перезапустите игру. Кнопка WoG Options открывает опции; отдельная кнопка «Object bans» над ней открывает запреты объектов. В главном меню она регистрируется через MainMenuAPI для всех его экранов, в выборе сценария размещается над WoG Options.

Для собственного мода замените корень `"wog scripts"` на имя его папки в нижнем регистре. Автоматически рассматриваются только моды из активного списка VFS. Название JSON-файла произвольное: ERA объединяет файлы Lang. Перед каждым открытием меню вызывается стандартный `ReloadLanguageData`: параметры и тексты перечитываются из актуального JSON с учётом VFS и языка. Изменения файлов во время игры подхватываются при следующем открытии меню. При обращении к API описания загружаются первоначально или после события `OnAfterReloadLanguageData`.

Мод может хранить JSON других модов: массив `include_mods` в его корне перечисляет дополнительные корни. Например, `era_options.wog.include_mods: ["wog scripts", "era scripts"]` загружает эти описания из общего Lang и показывает три разных мода. Повторные ссылки и циклы не приводят к повторной регистрации.

## Описание опции

```json
{
  "era_options": {
    "my mod": {
      "name": "Мой мод",
      "options": [
        {
          "key": "my_mod.feature",
          "name": "Включить функцию",
          "hint": "Краткая подсказка",
          "popup": "Подробное описание",
          "page": "Настройки",
          "category": "Интерфейс",
          "change_during_game": "true",
          "tags": ["interface", "heroes"],
          "default": "true"
        },
        {
          "key": "my_mod.mode",
          "id": "12000",
          "type": "choice",
          "name": "Режим",
          "page": "Настройки",
          "category": "Правила игры",
          "choices": ["Первый", "Второй", "Третий"],
          "default": "1"
        }
      ]
    }
  }
}
```

Числовые и логические поля в примерах записаны **строками**, чтобы они читались через скалярные переводы ERA. Загрузчик строго проверяет полученные значения; он не подменяет ошибочную строку нулём.

| Поле | Значение |
|---|---|
| `key` | Обязательный глобально уникальный ключ. 1–255 ASCII символов: буквы, цифры, `_`, `-`, `.`, `:`. Реестр приводит ключ к нижнему регистру; поиск ключа не зависит от регистра. |
| `name` | Обязательное непустое название. |
| `id` | Необязательный фиксированный ID: 0…2147483647. Если отсутствует, ID назначается последовательно от 1000. |
| `type` | `checkbox` (по умолчанию) или `choice`. |
| `default` | `true`/`false`, `on`/`off`, `1`/`0` для галочки; индекс от 0 для выбора. По умолчанию 0. |
| `choices` | Для `choice`: массив минимум из двух непустых названий. |
| `hint`, `popup` | Короткая и подробная подсказки. |
| `page` | Страница внутри мода, выбираемая в левой колонке. Одинаковое название объединяет опции на одной странице этого мода; без поля используется страница «Общее». |
| `category` | Сворачиваемая группа внутри страницы. Одинаковое название объединяет опции только на этой странице этого мода; без поля используется категория «Общее». |
| `category_order` | Приоритет категории, целое число, по умолчанию 0. Меньшее число идёт раньше; при равенстве сортировка по минимальному ID. Если в категории указаны разные приоритеты, используется меньший. |
| `section` | Старое название категории: используется только при отсутствии `category`. `page` больше не является заменой категории. |
| `tags` | Массив непустых тегов поиска и зависимостей. Для ID 0…999 числовой тег добавляется автоматически. |
| `disables` | Массив правил отключения других опций по `id` или `tag`; см. ниже. |
| `requires` | Массив требований к другим опциям по `id` или `tag`, по умолчанию требуется состояние `1`. |
| `enabled` | Возможность изменять значение. По умолчанию `true`. |
| `visible` | Показывать в диалоге. По умолчанию `true`; скрытые опции доступны через API. |
| `change_during_game` | Разрешает изменение на начатой карте, по умолчанию `false`. Читается из актуального JSON при открытии меню и сохраняется при экспорте; сам флаг не записывается в игровой сейв или INI. |
| `wog_option` | Необязательная явная привязка к глобальной настройке WoG, индекс 0…999. Само поле `id` такую привязку не создаёт. |
| `wog_values` | Массив сырых значений WoG для состояний 0/1 или вариантов `choices`. Например, `["1", "0"]` для инвертированного флага. Если отсутствует, используется прямое соответствие. |

Массивы `options`, `choices`, `tags`, `requires`, `disables` идут подряд с индекса 0. ERA читает известные скалярные ключи; первое отсутствующее описание завершает массив. Необязательный `option_count` на уровне мода задаёт точное число записей и позволяет диагностировать пропуски.

При ошибке отдельная опция пропускается, остальные продолжают загружаться. Подробности доступны по кнопке «Ошибки JSON» и через `OutputDebugStringA`, с указанием пути проблемной записи.

Страницы и категории создаются автоматически из полей опций: отдельные объявления не требуются. Автор может добавить несколько страниц с собственными категориями, например `"page": "Правила игры", "category": "Существа"`. Старые JSON только с `category` сохраняют свои группы на странице «Общее». Пример содержит две страницы и несколько категорий.

На карте редактируются только опции с `change_during_game: "true"`: нативные значения меняются в текущем массиве WoG, собственные — в ассоциативных переменных ERA этой карты. API читает и меняет те же значения; профиль будущих карт и INI предпочтений не затрагиваются. Перезапуска ERM-инициализации нет, поэтому автор включает флаг только для функций, читающих состояние при действии. Баны объектов на карте остаются только для просмотра. При перечитывании JSON обновляются параметры описания; ID сохраняются. Изменение типа, числа вариантов и нативной привязки требует перезапуска, как и удаление описания.

## ID и повторная регистрация

При загрузке всех активных модов сначала резервируются явно заданные ID, затем назначаются динамические. Поздняя запись с `id: "1000"` не столкнётся с динамической опцией, которая прочитана раньше в том же наборе.

Повторная регистрация ключа возвращает прежний ID и сохраняет текущее значение. Тексты, теги, видимость и значения по умолчанию обновляются. Конфликтами считаются другой мод-владелец, другой тип, другое количество вариантов, другая привязка WoG либо запрос другого фиксированного ID. Два разных ключа не могут занять один ID или один индекс WoG. Отдельный вызов регистрации не может резервировать ID неизвестных будущих вызовов: уже занятый ID вернёт конфликт.

Объекты опций хранятся динамически; ограничения 1000 записей нет. Диалог использует повторно небольшое число видимых элементов, поэтому число опций не расходует диапазон ID нативных контролов. Числовые ID сохраняются на время процесса; порядок активных модов может изменить автоматические номера после перезапуска. Для долговременных ссылок используйте `key`.

Удаление описания или изменение состава модов требует перезапуска. При обновлении переводов существующие ID не освобождаются и не переназначаются.

## Зависимости

`requires` указывает обязательное состояние другой опции, например `"requires": [{"id": "3"}]` или `[{"tag": "3", "value": "1"}]`. `when` (по умолчанию 1) должен быть ненулевым состоянием зависимой опции. Пока цель не имеет нужного значения, опция блокируется и её активное состояние сбрасывается в 0; прежний выбор восстанавливается при выполнении требования. Требуемая опция автоматически не включается.

Поле `disables` находится в описании управляющей опции. В каждом правиле задаётся ровно одна цель: ID или тег. Тег выбирает все соответствующие опции любых модов, без учёта регистра ASCII. Например:

```json
"disables": [
  { "id": "134" },
  { "tag": "135" },
  { "tag": "alternative_rules", "when": "1", "value": "0" }
]
```

По умолчанию правило действует при значении управляющей опции `1`, переводит цель в `0` и блокирует её изменение в меню и API. `when` позволяет выбрать другой индекс управляющего режима; `value` — индекс режима цели. Это логические значения меню после преобразования `wog_values`, а не сырые числа WoG. ID до 1000 автоматически получают тег со своим номером, поэтому первые две записи выше равноценны ссылкам на конкретные WoG-опции.

После выключения управляющей опции восстанавливается прежнее пользовательское значение цели. Оно сохраняется отдельно: собственные опции — в `[Options]`, привязанные цели WoG — в `[DependencyValues]` файла `ERA_OptionsMenu.ini`. Эффективные значения WoG сохраняются в профиль. Подсказка заблокированной опции показывает, кто её отключил; зависимости и числовые теги также попадают в экспорт.

Правила могут образовывать цепочки. Прямые и транзитивные противоречия требований и исключений блокируют исходную опцию с диагностикой. Циклические требования и неизвестные обязательные цели также блокируют зависимую опцию. Несовместимые одновременно активные правила или попытка изменить заблокированную цель отклоняют всю операцию до записи значений. На старой карте неизменяемые исторические несоответствия не мешают менять независимую опцию; новые конфликты запрещены.

## Значения и API

Собственные значения сохраняются по ключам в `ERA_OptionsMenu.ini` рядом с исполняемым файлом игры, секция `[Options]`. Галочка хранит 0/1, выбор — индекс. Значения, выходящие за допустимый диапазон нового описания, игнорируются при чтении. Для `wog_option` источником значения служит глобальный массив WoG, с преобразованием `wog_values`. Диалог сохраняет изменённые значения при закрытии. Внешний плагин после изменений вызывает `EraOptions_Save`.

Объявления типов функций находятся в [OptionsMenuApi.h](OptionsMenuApi.h). Экспорты имеют обычные имена без декорации, ABI — PE32/stdcall. Вызовы выполняются из основного потока после загрузки ERA/VFS/Lang, не из `DllMain` другого плагина.

| Экспорт | Результат |
|---|---|
| `EraOptions_GetId(key)` | ID зарегистрированной опции, `-1` если не найдена. |
| `EraOptions_RegisterJson(jsonPath, modFolder)` | Регистрирует описание по полному JSON-префиксу. Возвращает ID, `-1` при ошибке, `-2` при конфликте, `-3` при исчерпании ID. Повторная регистрация также возвращает ID. |
| `EraOptions_GetValue(id, &value)` | Читает предпочтение в меню или значение текущей карты во время игры. 1 при успехе, 0 при ошибке; выходной параметр меняется только при успехе. |
| `EraOptions_SetValue(id, value)` | Меняет то же значение с проверкой зависимостей. На карте требуется `change_during_game`. 1 при успехе, иначе 0. |
| `EraOptions_Save()` | Сохраняет предпочтения вне карты; на карте возвращает 1 без записи профиля/INI. При ошибке записи возвращает 0, изменения остаются для повторной попытки. |
| `EraOptions_ExportJson(pathUtf8)` | Экспорт всех зарегистрированных опций, 1 при успехе, 0 при ошибке. Путь в UTF-8; `nullptr` выбирает файл в каталоге игры. |
| `EraOptions_ShowDialog(showBans, allowEditing)` | Открыть опции (`showBans=0`) или баны (`1`). `allowEditing=0` — просмотр; `1` — разрешить редактирование. На карте доступны только опции с `change_during_game`; баны неизменяемы. Возвращает 1 при нормальном закрытии, 0 при ошибке или повторном открытии уже работающего меню. |

```cpp
#include "OptionsMenuApi.h"

// Выполнить после загрузки плагинов, например в обработчике ERA-события.
HMODULE menu = GetModuleHandleA("ERA_OptionsMenu.era");
auto getId = menu ? reinterpret_cast<EraOptionsGetIdProc>(GetProcAddress(menu, "EraOptions_GetId")) : nullptr;
auto getValue = menu ? reinterpret_cast<EraOptionsGetValueProc>(GetProcAddress(menu, "EraOptions_GetValue")) : nullptr;
if (getId && getValue)
{
    const int32_t id = getId("my_mod.feature");
    int32_t enabled = 0;
    if (id >= 0 && getValue(id, &enabled))
    {
        // Здесь плагин применяет собственную игровую механику.
    }
}
```

`id` идентифицирует настройку **этого реестра**. Только отдельное поле `wog_option` создаёт связь с глобальным массивом WoG. ERM-интерфейс для новых ключей и синхронизация multiplayer ещё не реализованы. Существующий API внешних галочек WoG Native Dialogs этот плагин не публикует и не заменяет.

## Импорт текущих WoG-опций

`tools/ImportWoGOptions.mjs` читает `zsetup01.txt` из `Mods/WoG/Data/hmm35wog.pac`, названия и описания из `Mods/WoG/lang/wog options.json`, а текущие значения — из профиля, выбранного в секции `[WoGification]` файла `WoG.ini`.

```powershell
node .\ERA_OptionsMenu\tools\ImportWoGOptions.mjs --game 'D:\games\HoMM 3 ERA' --output .\ERA_OptionsMenu\lang
```

Результат — `lang/era_options_wog.json` с ключами `wog.option.XXX`, ID, подсказками, привязками и импортированными состояниями по умолчанию. JSON содержит только поля меню; `legacy`, пути, хеши и архив значений в Lang не создаются. Необязательные поля с обычными значениями по умолчанию опущены.

Базовая таблица WoG содержит **14 опций**: 13 галочек и выбор из четырёх режимов WoGification. Опции остальных модов импортируются отдельной командой, описанной ниже.

JSON устанавливается в `Mods/WoG/lang`. Импортёр требует профиль размером ровно 4000 байт и завершает работу с ошибкой при неизвестных сохранённых состояниях или конфликтующих строках.

После сборки Release установку выполняет `tools/InstallWoGOptions.ps1 -GameDirectory 'D:\games\HoMM 3 ERA'`. Игра должна быть закрыта. Установщик сохраняет старые DLL/PDB/JSON/ERM в `build/era-options-menu/install-backup-*`, проверяет SHA-256 шести установленных файлов, включая скрипт управления банами и удаляет устаревшие `era_options_wog_snapshot.json` и `era_options_script_collections.json` из Lang. Ошибка установки откатывает изменения.

Параметр `-JsonOnly` копирует только три JSON. Обновлённое меню перечитает Lang при следующем открытии; замена DLL требует перезапуска игры.

Опции 1–4 хранят в WoG флаги отключения: галочка «включено» соответствует сырому 0. Импорт использует `wog_values: ["1", "0"]`. Для прямого соответствия состояний `wog_values` не нужен.

Изменение привязанной опции обновляет **глобальные предпочтения для будущих карт**, через перемещённый ERA массив `GetRealAddr(0x2771920) + 1000 int32`. Настройки уже начатой карты не изменяются. Перед открытием меню значения перечитываются из игры; `EraOptions_GetValue` также читает живое значение.

При сохранении изменённых WoG-опций создаётся отдельный профиль `WoGSetup_ERA_OptionsMenu.dat` со всеми 1000 глобальными значениями. При первом выборе `WoG.ini` получает копию `WoG.ini.before-era-options-menu`, затем выбирает новый профиль. Если профиль уже выбран, INI не заменяется. Исходный `.dat` сохраняется. Новые данные готовятся во временных файлах; ошибка изменения INI откатывает профиль. Если читатель разрешает запись, но запрещает переименование файла, профиль записывается через общий файловый дескриптор с восстановлением предыдущих данных при сбое. Ошибка сохранения показывает конкретную операцию и код Windows; меню остаётся открытым для повторной попытки.

Перехват показа WoG находится в `0x779170`, после проверки нажатия кнопки и до старого копирования массивов. Выход идёт через эпилог `0x77925F`. Перехват только внутреннего вызова `0x779213` здесь непригоден: следующий вызов `0x778ECC` пересобирает значения из старых `ItemState`, после чего игра копирует их обратно. Эта схема проверена по дизассемблированному `h3era.exe` данной установки.

## Дополнительные опции WoG Scripts и ERA Scripts

```powershell
node .\ERA_OptionsMenu\tools\ImportScriptOptions.mjs --game 'D:\games\HoMM 3 ERA'
```

Импортёр читает `Mods/WoG Scripts/Data/zsetup01.txt` и восемь файлов ERA Scripts (`script60.ers`–`script63.ers`, `script70.ers`–`script73.ers`). Тексты встроены из стандартных JSON исходных `lang`; значения по умолчанию взяты из выбранного профиля. Импорт не меняет профиль и список модов.

- `lang/era_options_wog_scripts.json`: **202 дополнительные опции**. Исходная таблица содержит 216, из них 14 уже описаны базовым WoG JSON. Два новых списка выбора сохраняют все варианты: 8 для ID 229 и 6 для ID 101.
- `lang/era_options_era_scripts.json`: **83 опции** из восьми `.ers`. Отрицательные номера скрипта и элемента `-1` допустимы; ERM ID остаётся исходным.

Файлы пока лежат в `Mods/WoG/lang`, но имеют отдельные корни `era_options.wog scripts` и `era_options.era scripts`, названия модов и ключи `wog_scripts.option.XXX` / `era_scripts.option.XXX`. WoG подключает их через `include_mods`. В списке видны WoG, WoG Scripts и ERA Scripts; зарегистрировано **299 опций**, из них видимы 259: 40 прежних настроек банов заменены отдельным экраном.

У каждого скриптового мода шесть страниц с двумя-тремя сворачиваемыми категориями. Разделение основано на действии опций, а не на старых номерах страниц и общей группе `Custom Scripts`:

| Страница | Категории WoG Scripts | Категории ERA Scripts |
|---|---|---|
| Adventure Map | New Objects; Object Improvements; Map Generation and Replacements; World Rules and Events; WoGification Messages | Objects and Dwellings; Neutral Armies and Rewards; Map Exploration |
| Heroes and Skills | Secondary Skills; Hero Balance; Commanders and War Machines | Secondary Skills; Hero Development; War Machines |
| Creatures and Combat | Creature Balance and Upgrades; Battle Changes; Stack Experience and Neutrals | Creature Abilities; Army Balance and Upgrades; Battle Rules and Experience |
| Towns and Economy | Town Development; Economy; Mithril | Town Development and Recruitment; Economy |
| Artifacts and Magic | Artifact Enhancements; Artifact Restrictions; Spell Enhancements | Artifacts; Magic and Scrolls |
| Map Rules / Rules and AI | Rule Selection and Messages; Gameplay Modifiers | Artificial Intelligence; World Events |

В WoG Scripts последняя страница называется `Map Rules`, в ERA Scripts — `Rules and AI`. Назначения задаются в `tools/ImportScriptOptions.mjs` по ID и сохраняются при повторном импорте. У каждой опции в JSON есть `page` и `category`; ID, ключи и привязки остаются исходными.

Для переноса достаточно переместить соответствующий JSON в `lang` своего активного мода и убрать его из `include_mods` WoG. Менять внутренние ключи, ID и привязки не нужно.

Состояния обычных галочек WoG `2`/`3` означают заблокированные «выключено»/«включено». Меню показывает 0/1 и сохраняет исходные значения. Инвертированные ID 1–4 и списки выбора обрабатываются по своему отображению. Новые связи задаются через `requires` и `disables`. В импортированных JSON: 6 и 186 требуют включённых командиров (3), 742 — опыта отрядов (900), 10 — оставления войск (2); ERA 764 исключает WoG 199. Метаданные хранятся в `tools/OptionBehavior.mjs` и сохраняются при повторном импорте.

## Экспорт в JSON

Кнопка **Export JSON** сохраняет `ERA_OptionsMenu.export.json` рядом с исполняемым файлом игры. Экспортируются все зарегистрированные опции всех модов, включая скрытые и недоступные; поиск и выбранный мод на экспорт не влияют. Текущие состояния записываются в `default`, ID фиксируются, тексты преобразуются из кодировки игры в UTF-8. Моды, варианты, теги и привязки WoG сохраняются. Для иного пути используется `EraOptions_ExportJson(pathUtf8)`.

Экспорт не меняет профиль и исходные JSON. Новый файл сначала записывается во временный файл; ошибка записи или замены сохраняет предыдущий экспорт. Файл находится вне Lang, поэтому автоматически не загружается. Для использования как описания опций замените соответствующие исходные JSON и откройте меню снова.

## Текущее меню и проверка

Слева расположен раскрываемый список «мод → страницы». Нажатие раскрывает/сворачивает страницы и выбирает первую. Категории находятся справа; `[-]` сворачивает, `[+]` раскрывает содержимое. По умолчанию группы и опции сортируются по ID, `category_order` меняет приоритет категории. WoGification идёт перед Hard-Coded Options. Состояние категорий и прокрутки сохраняется до закрытия меню. Всего 13 страниц, 36 категорий, 259 видимых опций. Map Rules содержит только режим выбора правил, их объявление и сами правила.

Страница заполняется сверху вниз: сначала левая колонка, затем правая. Категории вместе с заголовками переносятся вправо до появления прокрутки. Если целая категория не помещается, её можно разделить между колонками с повтором заголовка справа. Высота каждой колонки считается отдельно: перенос длинной подписи слева не добавляет пустые строки справа. Опция выбора показывает все варианты с нативными радиокнопками `radiobttn.def` вертикально в одной колонке. Радиогруппа никогда не разделяется; при совпадении названия единственной радиогруппы с категорией заголовок показывается один раз. ID, ключи, теги и служебные описания не занимают строки списка. Минимальная высота строки — 24 пикселя; длинные подписи переносятся. У каждой страницы своя позиция и нативная полоса прокрутки, которая создаётся при необходимости и восстанавливается при переходах. Колесо прокручивает только панель под курсором. Состояние поиска отдельно. Контролы опций переиспользуются; кеш полос ограничен 64 страницами, после вытеснения позиция страницы сохраняется в модели. Это ограничение кеша, а не числа страниц или опций.

Кнопка «Full screen» и F11 переключают обычный размер (800×600, с ограничением по игровому экрану) и размер игрового экрана. Режим сохраняется в `ERA_OptionsMenu.ini`, секция `[Dialog]`, ключ `FullScreen`. При переключении сохраняются поиск, выбранная страница, свёрнутые категории и позиции прокрутки; они ограничиваются новой доступной областью. Размер определяется разрешением игры, включая HD. Нативная тень включается только при наличии восьми свободных пикселей справа и снизу; при нехватке места отключается в меню, каталоге банов и предпросмотре.

Поиск через `H3DlgEdit` обновляет результаты сразу при вводе и ищет по всем модам: название, ключ, ID, страница, категория, подсказки, теги, варианты выбора. Несколько слов должны присутствовать одновременно; регистр и лишние пробелы не влияют. `101`, `#101`, `option 101` ищут точный ID. Найденные категории раскрываются независимо от состояния исходной страницы, их тоже можно свернуть. Очистка поиска возвращает страницу с прежними состояниями категорий. `Ctrl+F` переводит фокус в поиск; `Esc` сначала очищает активный поиск, следующее нажатие закрывает меню. Выбор мода/страницы также очищает поиск. «По умолчанию» применяется ко всей выбранной странице, включая свёрнутые категории, или к результатам поиска.

ПКМ показывает описание на время удержания кнопки. Предпросмотр использует шрифт `medfont2.fnt`, размеры и оформление WoG Native Dialogs (`WOGODARK`, `WOGOP*`, `WOGOT*`, `WOGOB*`); без этих ресурсов используется стандартное оформление. Короткая подсказка остаётся в нижней строке. Выпадающий фильтр тегов ещё не реализован.

## Баны объектов

Отдельная кнопка «Object bans» открывает каталог заклинаний, артефактов, героев и вторичных навыков. В диалоге опций есть переход «Object bans», в каталоге — «WoG / ERA options». Переход сохраняет изменения и заменяет окно без вложенных диалогов; страница, поиск, фильтры и прокрутка сохраняются до возврата в игровое меню. Самостоятельное закрытие каталога сохраняет только JSON банов. Ошибка записи оставляет текущий диалог открытым.

ЛКМ по иконке, названию или галочке переключает бан; красная рамка показывает выбранные объекты. ПКМ показывает предпросмотр на время удержания через `era_help::ShowObjectHint(page,id,TRUE)`. При отсутствии API используется обычная всплывающая подсказка. Поиск ищет название и точный ID объекта (например, `#72`). Фильтры школы/класса/города, уровня и состояния сочетаются; ПКМ на фильтре переключает его назад. «Ban shown» / «Allow shown» меняют все результаты фильтра. Каждая вкладка сохраняет свои поиск, фильтры и прокрутку, пока открыт каталог. При 800×600 артефакты и навыки показываются в четыре строки; высота ячейки учитывает размер изображения каждой вкладки.

Для заклинаний отдельно выбираются источники: гильдии магов и пирамиды, святилища, учёные, свитки и ящики Пандоры, стартовые книги героев. Способности существ отображаются для справки, но не участвуют в этих источниках и не переключаются. Артефакты читаются из текущей таблицы игры, включая расширение её количества; бан исключает объект из случайного пула и не удаляет специально размещённые предметы. Сборка составных артефактов — отдельная механика: прежние опции 178 и 237 остаются на обычной странице.

Баны героев (ID 0–155) запрещают найм для всех игроков через `H3Main::heroMayBeHiredBy`; уже выбранные предложения таверны заменяются разрешёнными свободными героями через `OW:V`. Если свободных кандидатов нет, соответствующее предложение пустое. Стартовые, размещённые на карте и находящиеся в тюрьмах герои не удаляются и не заменяются. Баны вторичных навыков (ID 0–27) используют `H3Main::bannedSkills`: запрещают предложения нового навыка при повышении уровня, сохраняя уже изученные навыки, их улучшение и явно заданные награды объектов/скриптов.

Правила хранят **ID объектов**, независимо от реестра опций и его лимита, в `ERA_OptionsMenu.bans.json` рядом с EXE игры:

```json
{
  "version": 1,
  "spells": [9, 26],
  "artifacts": [72, 90],
  "heroes": [8, 155],
  "skills": [27],
  "sources": {
    "guilds": true,
    "shrines": true,
    "scholars": true,
    "scrolls_and_pandora": true,
    "starting_heroes": true
  }
}
```

Первое открытие при отсутствии файла переносит старые выбранные баны и источники. Закрытие диалога или переход в другой сохраняет этот JSON атомарно; ошибка записи оставляет меню открытым. Следующее открытие перечитывает внешние изменения. Ошибочный JSON сообщает причину и не заменяет предыдущие данные.

Существующие файлы версии 1 без `heroes` и `skills` совместимы: оба новых списка пусты до выбора банов. `EraOptions_MapObjectBanned(kind,id)` поддерживает типы 0 — заклинание, 1 — артефакт, 2 — герой, 3 — вторичный навык.

Правила применяются **только при старте новой карты**. Плагин фиксирует её собственный список в ассоциативных переменных ERA; сохранение/загрузка карты сохраняет этот выбор. Клики до старта карты и редактирование файла меняют предпочтения для будущих карт. Старые сохранения без такого списка не получают новые баны. При загрузке восстанавливается запрет случайного пула; объекты и книги героев повторно не переписываются.

Контекст определяется через `ERA::GetGameState`: корень карты/боя и загруженные данные карты. Остатки памяти в главном меню не включают игровой режим. Аргумент `allowEditing=0` запрещает все изменения и сохраняется при переходах/F11. При `allowEditing=1` на карте доступны только опции с `change_during_game`; баны и их источники остаются неизменяемыми. Открытие, просмотр и экспорт не применяют предпочтения к карте. В готовом JSON флаг включён для ID 2, 4, 10, 902: оставление войск, снос зданий, возвращение оставленных войск владельцу, оставление артефактов.

WoG-опции на карте читаются из **текущего**, а не глобального массива WoG. Каталог банов читает `disabledSpells`, `bannedSkills`, флаг `disabled` таблицы артефактов, `artifactsAllowed` и доступность героев для найма с учётом владельцев и текущих предложений таверн, по правилам ERA_HelpDialog. Поэтому учитываются ограничения карты и других модов. Для источников заклинаний дополнительно читается зафиксированная политика этой карты: замена заклинаний в святилищах, наградах и книгах не имеет общего нативного флага. Предпочтения из внешнего JSON для будущих карт не используются. На старых сохранениях без политики плагина источники берутся из текущих WoG-опций карты. Экспорт из меню просмотра использует показываемые значения, не меняя глобальные настройки.

Полная установка включает `scripts/00 era options - object bans.erm` в `Mods/WoG/Data/s`. Скрипт заменяет запрещённые заклинания в выбранных источниках после инициализации карты **только разрешёнными заклинаниями того же уровня**. Если замены нет, удаляет святилище/свиток либо меняет награду учёного на основной навык. Запреты гильдий и артефактов используют стандартный `UN:J` / `UN:A`; отдельный перехват учитывает Грааль Сопряжения. Служебные stdcall-экспорты `EraOptions_MapObjectBanned(kind,id)`, `EraOptions_MapBanSource(source)`, `EraOptions_ReplacementSpell(level)` читают только зафиксированные правила текущей карты. Подбор замены принимает уровни 1–5 и возвращает `-1`, если разрешённых заклинаний этого уровня нет.

При наличии WoG Scripts установщик точечно обновляет три файла в `Mods/WoG Scripts/Data/s`, сохраняя их исходную кодировку, остальное содержимое и резервные копии. `78 wog - wogify.erm` переключает общую проверку выбранного бана на API текущей карты; имена функций, битовая маска результата 0/1/2/3, `y-94`, `y-99` и параметры генератора сохраняются. Поэтому новые ID учитываются в остальных выдачах заклинаний WoG, даже если источник «Гильдии» выключен. Проверка нативных ограничений `UN:J` сохраняется. В `53 wog - map options.erm` список выбранных банов охватывает все обычные ID; обработчики старых источников и старый перехват Грааля пропускают карты с новой политикой, чтобы не повторять работу нового ERM/плагина. В `51 wog - spell book.erm` три выдачи второго уровня учитывают новые баны. Для сохранений без `era_options.bans.version=1` остаются прежние опции и поведение. Неизвестный или частично изменённый код останавливает подготовку установки без изменения файлов игры; повторная установка уже применённых правок не дублирует их.

Для проверки установщика и настроек откройте игру, проверьте доступность нового меню параметров WoG и корректность отображаемых значений, затем измените параметры на карте и проверьте их после перезапуска. Для проверки применения настроек на новой карте требуется запуск игры.
