## Проверка по 0x528520 и Objects_CommonHotaObjectsPack

Повторная проверка 28 октября 2026 года привязана к фактическим потребителям:
`GazeboExtender.cpp:12` и `WarehousesExtender.cpp:119`. Оба файла через
`framework.h` → `headers/header.h` используют проверяемый single-header
`H3API.hpp`. Исходники плагина не изменялись.

### Указатель действительно адресует H3Player

`0x528520` — `AIHero::CalculateMapPosWeight`: герой в ECX, адрес дистанции
в EDX, упакованная позиция в стеке. На `0x52852D` вызывается `0x4E5920`
(GetHeroOwner); `0x528538` сохраняет полученный H3Player* в `[EBP-4]`.

`0x4E5920` читает owner из героя `+0x22`, затем вычисляет:

```
player = *(0x699538) + 0x20AD0 + owner * 5 * 9 * 8
       = H3Main + 0x20AD0 + owner * 0x168
```

Это независимое подтверждение sizeof(H3Player) = 0x168 и правильной базы
для последующего обращения к AI-полям. В
`RMG_CustomizeObjectProperties/ObjectExtenderManager.cpp:432` обработчик
на `0x528559` передаёт расширению именно `[EBP-4]`. Имя параметра
`activePlayer` в API не меняет его происхождение: это владелец героя.

### Прямые обращения к ценности ресурсов

В ветви CAMPFIRE функции 0x528520:

```asm
00528A14  mov  eax, [ebp-4]                ; H3Player*
00528A26  fmul qword ptr [eax+158h]        ; GOLD, double
00528A35  fmul qword ptr [eax+esi*8+128h]  ; ресурс ESI, double
```

Ветвь FLOTSAM на `0x528E07` читает золото с `+0x158`, а на `0x528E13`
дерево с `+0x128`. Ветвь MYSTICAL_GARDEN на `0x5295B7` читает золото
с `+0x158`, на `0x5295C3` — самоцветы с `+0x150`.

Общий помощник `0x527150`, вызываемый для наград Pandora/CreatureBank,
начинает массив на `0x527162` как `player + 0x128`, выполняет семь итераций,
читает QWORD и увеличивает указатель на 8 (`0x527185`). Следовательно, это
именно семь double, а не FLOAT или INT32.

смещений начала массива 0x128, золота 0x158 и размера массива 7 * 8.
