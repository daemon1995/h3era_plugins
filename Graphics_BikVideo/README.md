# Video playback in BIK format — исправление для ERA 3.9.31

Плагин восстановлен из предоставленной DLL и пересобран на x86 MASM. Исходный плагин тоже был написан на ассемблере. DLL ERA на диске не изменяется.

**Обновление 2: исправлен вылет при запуске видео кампаний.** В первой пересборке при отсутствии BIK передавался адрес переменной `SmkExtension`, хотя восстановленная ветка SMK ожидает указатель непосредственно на Delphi-строку `.smk`. Это приводило к чтению неверного заголовка строки и вылету в `System.Move`. Ошибка воспроизведена на `H3x2_ELa` (ID 113) из предоставленного `exception context.txt`. Теперь SMK получает сам указатель на строку. Исправленная DLL занимает 9728 байт.

## Установка

1. Закройте игру.
2. Сохраните резервную копию старой `Video playback in BIK format.dll` вне папки `EraPlugins`.
3. Замените её файлом из `build` или из архива выпуска в `Mods/<ваш видеомод>/EraPlugins/`.
4. Используйте `binkw32a.dll` из исходного видеомода: новая DLL использует тот же кодек и видеоархивы. Кодек не включён в выпуск.

В активной сборке должна загружаться одна копия этого плагина. Если он есть в нескольких включённых модах, замените копию в моде с наивысшим приоритетом или отключите остальные копии.

Проверки выполнены на установленной ERA **3.9.31.0**, 32-битном `h3era.exe` с адресами SoD и имеющемся `binkw32a.dll`. Другие версии не проверены. При неизвестной сигнатуре обработчиков DLL показывает сообщение и не устанавливает игровые хуки.

## Что исправлено

Старый код вычислял адреса внутренних процедур ERA, разбирая машинный код мостов на `0x44D270` и `0x598A90`. Он поддерживал старые мосты `Core.Hook` / `HookCode`. Сгенерированный `ApiJack.StdSplice` мост имеет другой порядок инструкций и другую передачу аргументов; старый разборщик попадал в ветку ошибки.

Новый код ищет проверяемые последовательности внутри **самих обработчиков** `SndVid.Splice_OpenBik` и `SndVid.Splice_OpenSmack` в загруженном образе ERA. Из них извлекаются адреса ANSI-строк `.bik` и `.smk`, преобразования PChar, конкатенации, перенаправления ресурсов и поиска в таблице видео. Все извлекаемые адреса проверяются на принадлежность образу ERA. Для текущего Delphi явно передаётся нулевой параметр codepage в `@LStrFromPChar`.

Инициализация происходит через событие ERA `OnAfterStructRelocations`, после установки собственных видео-хуков ERA и патчей `AfterWoG`. Старый перехват загрузочной процедуры игры не используется. Сохранены оригинальные выбор BIK/SMK по заголовку, работа с VID-архивами, видео меню, варианты `_loop`, переключение старого и нового Bink и настройка `Settings/BinkSoundType` в `heroes3.ini`.

Для изменения игрового кода используются `VirtualProtect` с восстановлением защиты и `FlushInstructionCache`. CRT-зависимость `malloc` заменена на `HeapAlloc`. Производственная DLL полностью написана на ассемблере; C++ используется только в отдельной проверочной программе.

## Сборка

Нужны Visual Studio 2022 с x86 MASM и Windows SDK. Из PowerShell:

```powershell
.\build.ps1
```

Для сборки достаточно `video.asm`, `recovered.inc` и `build.ps1`. Исходная DLL, Python и библиотеки анализа для сборки не нужны.

`recovered.inc` содержит восстановленные инструкции и таблицы исходной DLL. Метки с исходными адресами служат для сверки дизассемблирования; DLL поддерживает перемещение адреса загрузки. `analysis/recover_asm.py` воспроизводит восстановление исходной DLL. Неиспользуемый старый разборщик мостов исключён из сборки.

## Проверки

- Реальный образ ERA 3.9.31.0: поиск обработчиков и адресов при двух разных базах загрузки DLL и ERA.
- Воспроизведение отказа старого разборщика на формате моста `StdSplice` и успешный поиск новым кодом.
- Отказ при повреждённой сигнатуре без записи в игровой код.
- Переключение Bink и восстановление 38 операндов вызовов, сохранение регистров.
- Открытие архивного BIK: флаги Win32 HANDLE `0x08000000` для старого Bink и `0x00800000` для нового; отсутствие ресурса возвращает NULL.
- Инициализация всех пяти игровых хуков с правильными адресами переходов, повторное событие не меняет хуки.
- Воспроизведён дефект первой пересборки в переходе на SMK для `H3x2_ELa`. Проверка исполняет реальные `@LStrFromPChar`, `@LStrCat3`, `@LStrSetLength` и `System.Move` из ERA; строковые функции не заменяются заглушками.
- Исправленная сборка: 78 идентификаторов роликов кампаний, четыре варианта (BIKi, BIKb, SMK, отсутствие файла), первый и повторный вызов через кэш, две базы загрузки DLL и ERA. Всего 1248 вызовов. Проверяются имена ресурсов, выбор проигрывателя, баланс стека, сохранение регистров и целостность расширений.
- Нативный процесс x86 загрузил новую DLL и нашёл обработчики в установленной ERA.
- Установленный `binkw32a.dll` открыл через HANDLE реальный `acredit.bik` из `RandomSkin wog.vid`: 800×600, 1743 кадра; три кадра декодированы, дескрипторы закрыты.

Игровое окно с полной сборкой модов не запускалось. В проверке кампаний выделение памяти, поиск ресурса, чтение заголовка и конечные игровые проигрыватели заменены стендом. Полный запуск кампании и визуальное воспроизведение меню и таверны в самой игре ещё требуют проверки.

Проверочные скрипты используют `pefile`, `capstone` и `unicorn` из `build/python`. Пути к локальной игре и тестовым архивам заданы в скриптах и при переносе на другой компьютер требуют изменения.

```powershell
python verify.py
python campaign_regression.py
python campaign_regression.py --expect-broken # Внести старую ошибку только в эмулируемый образ и подтвердить её обнаружение
python analysis/prepare_native.py
.\run-native-check.ps1
```
