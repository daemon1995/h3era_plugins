# Combat_BattleReplay

Переигровка битвы для Heroes III ERA/WoG на основе `h3era_plugins_by_igrik/all/BattleReplay.cpp` (igrik).

Проект включён в `../H3EraPlugins.sln`, конфигурации `Debug|x86` и `Release|x86` соответствуют `Win32` проекта. Используются общие `Directory.Build.*`, H3API, ERA API и структура командира WoG из `../headers`. Исходный файл в репозитории igrik не изменён.

На экране результатов кнопка с крестиком запускает новую попытку. Перед повтором восстанавливаются герои, обе переданные армии, гарнизон города, командиры по исходному условию WoG и золото участников. Последняя принятая попытка сохраняет свои результаты. События `OnBeforeBattleReplay` и `OnBattleReplay` сохранены.

Сетевые бои человек–человек и бои без людей не переигрываются. В сетевом бою ИИ–человек армия сохраняется независимо от наличия героя, в том числе когда сетевой обработчик передаёт отдельно выделенную копию армии.

Выход из боя через ERA FastQuit и загрузка любой игры сбрасывают контекст переигровки на событиях `OnBeforeFastQuitToGameMenu`, `OnGameLeave`, `OnGameLeft`, `OnBeforeLoadGame`, `OnGameEnter`. Следующий бой получает новый контекст, поэтому кнопка повтора не исчезает после загрузки `BATTLE!` из боевого окна. Временные значения быстрого боя игры и HD восстанавливаются до загрузки; старый кадр не может перезаписать настройки новой игры. Проект использует `/EHa`, чтобы системное исключение ERA освобождало принадлежащие снимкам ресурсы.

## Отличия от оригинала igrik

| В оригинале | В этом проекте |
| --- | --- |
| Сохраняется герой **или** переданная армия | Герой и фактическая армия сохраняются независимо; отдельная сетевая армия восстанавливается и при наличии героя. Дополнительно сохраняется гарнизон города |
| Золото обеих сторон сохраняется только при владельце защитника `0..7`, атакующий герой разыменовывается без проверки | Золото каждой стороны сохраняется независимо, владельцы проверяются; поддержан бой без атакующего героя |
| Общие флаги повтора живут между вызовами; запрос сбрасывается на каждом сообщении результатов | Отдельный контекст боя сохраняет запрос до новой попытки; вложенные бои не переигрываются. Выход и загрузка явно сбрасывают контекст |
| `result_dlg_item_id == DLG_CANCEL` не меняет результат окна | Используется присваивание ID кнопки переигровки |
| Настройка игры и `HD.QuickCombat` восстанавливаются из одного значения | Их исходные значения сохраняются и восстанавливаются независимо, в том числе перед загрузкой; поздний старый кадр не меняет новую игру |
| Герой копируется полностью через `MemCopy`, вместе с указателями строки биографии | Биография копируется как принадлежащая объекту строка; остальные поля копируются с проверкой размера и расположения |
| Пропуск хвоста StartBattle пропускает и служебную очистку | Перед переходом восстанавливаются текущий игрок и `bShowIt`, сбрасываются служебные флаги боя и продолжается таймер |
| Для запрета сетевого PvP используется `gameType == 2` | Проверяется штатный флаг сетевой игры; PvP в сети и бои без человека не переигрываются |
| Один исходный файл на старых заголовках | Проект Visual Studio в общем решении, общие H3API/ERA/WoG-заголовки, лицензия, анализ адресов и регрессионные проверки |

WoG-точка запуска, обработка командиров и астрального духа, а также события переигровки сохранены. Полного отката мира, ERM-переменных и действий сторонних плагинов эта реализация не обещает. Подробности и непроверенные сценарии приведены в `ANALYSIS.ru.md`.

## Сборка

Из Developer Command Prompt для Visual Studio:

```bat
msbuild Combat_BattleReplay\Combat_BattleReplay.vcxproj /p:Configuration=Release /p:Platform=Win32
```

Обычная сборка, как у соседних проектов, помещает `Combat_BattleReplay.era` в `$(LocalGamePath)\Mods\$(PluginModName)\eraplugins`. Release также создаёт `.map` и `.dbgmap`. Для сборки без установки задайте абсолютные `/p:OutDir=...\` и `/p:IntDir=...\` внутри рабочего каталога.

При проверке 10.10.2026 собраны Debug и Release с установленным `v141_xp`; файлы находятся в `../build/Combat_BattleReplay/Debug/` и `../build/Combat_BattleReplay/Release/`. Release установлен в мод WoG с резервной копией прежнего плагина. Единственное предупреждение MSBuild — стандартное предупреждение о прекращении поддержки Windows XP.

## Проверки

```bat
Combat_BattleReplay\run-tests.cmd
```

Запускать из x86 Developer Command Prompt. Девять групп регрессионных проверок покрывают отдельную сетевую армию, армию внутри героя, обе стороны и город, отсутствие героя/объектов, сохранение результата принятой попытки, допустимые режимы переигровки, сброс незавершённого контекста при загрузке, восстановление независимых настроек игры/HD и освобождение ресурсов при настоящем Windows SEH-исключении. Проверяются также несколько повторов и восстановление принадлежащей герою строки.

Эти проверки не запускают игровой движок. Сетевой сценарий в двух экземплярах игры и WoG-интеграцию нужно проверить по плану в `ANALYSIS.ru.md`.

## Установка и совместимость

Для испытания используйте Release-файл. **Отключите старую версию BattleReplay** перед установкой: обе версии используют имя экземпляра патчера `igrik.BattleReplay`. Новая версия не устанавливает хуки повторно, если экземпляр уже существует, поэтому при загрузке старой версии первой исправление не включится.

Нужны ERA, WoG и совместимые с исходником WoG-адреса. Адреса WoG сохранены, но не подтверждены экспортом базы исполняемого файла. Совместимость с конкретным WoG и скриптами, меняющими мир в обработчиках боя, не подтверждена запуском.

Подробный анализ и границы исправления: `ANALYSIS.ru.md`. Извлечённые инструкции базы: `ADDRESS_CHECKS.json`. Лицензия исходного репозитория сохранена в `LICENSE`.
