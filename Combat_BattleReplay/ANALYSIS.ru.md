## Причина пустой армии

В исходнике используется взаимоисключающий выбор:

```cpp
if (HrD) {
    // сохранить и восстановить только 1170 байт героя
} else {
    // сохранить и восстановить MArrD
}
```

Для атакующего сделан такой же выбор. Он корректен лишь при условии, что переданная армия действительно расположена внутри соответствующего героя. В сетевом пути это условие нарушается.

1. `NetworkBattleInfo2Defender`, `0x4ACA60`, получает данные боя через `Get_OnlineEnemiesBattleInfo`, `0x4AEBD0`.
2. В `0x4AECAA` и `0x4AECE2` выделяются два самостоятельных блока по `0x38` байт. В `0x4AECD7` и `0x4AED1E` в них копируются армии из пакета. Герои выделяются отдельно, по `0x492` байт. Это разные объекты, даже если содержимое армий первоначально совпадает.
3. В `0x4ACC37` сетевой обработчик передаёт эти отдельные армии и героев в `AdvMgr::StartBattle`, `0x4AD160`, с `combatIsLocal = 0`.
4. `PrepareBattlefield`, `0x4635D0`, записывает именно аргументы армий в `BattleMgr + 0x54C4` и `+ 0x54C8` (инструкции `0x46365F`, `0x46366E`). Подмены на `&hero->army` здесь нет.
5. `BattleMgr_SetWinner`, `0x476DA0`, вызывает `Battle_Make_AfterBattle_Army`, `0x463DD0`, до окна результатов. Последняя функция очищает переданную армию (`0x463DE9`, `0x463DF8`) и заполняет её выжившими. После полного поражения она остаётся пустой.
6. Нажатие переигровки восстанавливает героя, но в исходнике пропускает отдельную армию, поскольку герой существует. Новая попытка получает пустую армию. После неполного поражения или победы повтор может получить только остаток войск — тот же дефект без полной потери армии.
7. После окончательного возврата из боя сетевой обработчик отправляет результат на управляющий ходом компьютер; при атаке ИИ это вызов `BattleMgr_CopyTownsAndHeroesStruct`, `0x4AE840`, после `0x4ACC4D`. Поэтому важно восстановить именно исходные объекты аргументов, которые затем попадут в пакет.

Эта цепочка объясняет зависимость от ожидающего игрока: он обрабатывает бой через сетевые копии, тогда как компьютер, управляющий ходом ИИ, работает с другим контекстом данных. В коде нет условия «последний завершивший ход». Связь именно с порядком завершения ходов соответствует описанию пользователя, но без воспроизведения распределение ролей ERA/HD на конкретной карте не доказано.

Для города **без защищающего героя** исходник уже сохраняет `MArrD`, поэтому описанная ошибка выбора `if/else` сама по себе не объясняет потерю его гарнизона. Если проблема воспроизводится и в таком случае, нужно отдельно проверить WoG-точку запуска повтора, городские копии и применение сетевого результата. Новый код дополнительно сохраняет `town->guards` и возвращает служебный контекст, но это не доказательство устранения всех вариантов боя без героя.

**Исправление:** сохранять героя и переданную армию независимо друг от друга, на обеих сторонах; восстанавливать сначала героя, затем армию. Это работает и при совпадении адреса армии с `&hero->army`, и при отдельном сетевом объекте. Для города дополнительно сохраняется `town->guards`; при совпадении с аргументом повторное восстановление записывает те же исходные данные. Результат принятой попытки не откатывается.

## Проверка адресов и ABI

| Адрес | Что подтверждено экспортом |
|---|---|
| `0x4AD160` | `__thiscall StartBattle(advMgr, position, attacker, attackerArmy, defenderOwner, town, defender, defenderArmy, seed, combatIsLocal, isBank)`; 10 аргументов после `this`, `retn 28h` |
| `0x46FE20` | Конструктор результатов, `__thiscall`, 6 аргументов после `this`; параметры исходника `dlgDef`, `a6`, `allHPLoserLose` фактически означают сторону игрока, осаду, опыт |
| `0x4716E0` | Обработчик результатов принимает сообщение в ECX; присваивает результат окна и заменяет сообщение на `512/10`, `itemId = 10`, возвращает 2 |
| `0x477254 -> 0x477303` | Пропуск опыта, орлиного глаза и показа полученных артефактов после закрытия окна; освобождение временного вектора сохраняется |
| `0x4173E2 -> 0x41742D` | Пропуск части обновления панелей карты; последующий общий redraw остаётся, поэтому исходное имя «SkipAllRedraw» было бы неточным |
| `0x4ADFE8 -> 0x4AE67C` | Переход от возврата из боевого менеджера к эпилогу StartBattle; исходник пропускал также служебное завершение вызова |
| `0x558170 / 0x558190` | Приостановка/продолжение таймера; старт новой попытки перезаписывает `BattleStartTime`, поэтому каждый пропущенный хвост нужно завершать по таймеру |
| `0x6977D4` | `timeClick`, таймер автоматического закрытия результатов |
| `H3Hero = 0x492`, `H3Army = 0x38` | Размеры согласуются с базой и заголовками; установлены compile-time проверки |

Установка повтора в WoG-точке `0x75AEB0`, её hex-патч и режим `CALL_/SAFE_/THISCALL_` сохранены. По этой базе нельзя подтвердить, что установленная версия WoG проводит через эту точку все локальные и сетевые вызовы.

## Другие найденные ошибки и изменения

| Проблема исходника | Изменение |
|---|---|
| Сохранение армии только при отсутствии героя | Независимые снимки героя и армии на каждой стороне |
| `HrA->owner_id` читается при сохранении золота без проверки `HrA` | Золото сторон сохраняется независимо, с проверкой владельца `0..7`; ID владельца запоминается до боя |
| При нейтральном защитнике золото атакующего вообще не сохраняется | Золото атакующего сохраняется независимо от владельца защитника |
| Проверка человека допускает некорректные индексы игроков | Проверка диапазона до обращения к игроку |
| `result_dlg_item_id == DLG_CANCEL` ничего не изменяет | Присваивание `resultItemID = REPLAY_BUTTON` |
| Флаг повтора сбрасывается на каждом сообщении результатов | Сброс только перед запуском очередной попытки; запрос сохраняется при последующих уведомлениях |
| Флаги глобальны и могут протечь в вложенный вызов боя | Контекст с восстановлением предыдущего контекста; вложенный бой проходит без повтора |
| Флаг повтора потенциально остаётся от предыдущего вызова | Каждый контекст создаётся с `requested = false` |
| Настройка HD восстанавливается из значения другой настройки | Отдельное сохранение и восстановление игры и `HD.QuickCombat`; отсутствующая переменная HD не создаётся |
| Полный `MemCopy` героя копирует указатели H3String биографии | Побайтовое копирование частей героя вокруг биографии и отдельное присваивание её текста, включая пустую строку |
| Обычное присваивание H3Hero в текущем H3API не компилируется | Локальная специализация копирования обходит дефект `H3Bitset<48>::operator=`; общий H3API не изменён |
| Пропуск хвоста StartBattle теряет восстановление контекста и учёт таймера | В low-hook возвращаются `bShowIt`, активный игрок из локальных переменных, сбрасываются `gAdvDisposeLevel` и флаг боя; вызывается `ContinueTimeAfterBattle`; ESI получает `winnerSide` перед эпилогом |
| В исходнике нельзя переигрывать только при `gameType == 2` и двух людях | Используется подтверждённый флаг сетевой игры `0x69959C`; сетевой PvP запрещён, бои без людей исключены |
| Возможная двойная установка новой версии при уже загруженном плагине | Проверяется существующий экземпляр `igrik.BattleReplay`; старую версию всё равно нужно отключить для включения исправления |

Восстановление служебных значений при пропуске хвоста основано на `0x4AD3B6..0x4AD3D6` (сохранение локальных переменных), `0x4AE58D..0x4AE59F` (их возврат), `0x4AE006`, `0x4AE605`, `0x4AE62C`, `0x4AE632`. Проверка победы/поражения карты, удаление героев и выдача наград для отменённой попытки по-прежнему пропускаются.

## Границы исправления

- Исправлена доказанная потеря содержимого отдельных армий. Это не полная транзакция состояния всей игры: ERM-переменные, произвольные ресурсы и изменения карты сторонних обработчиков не снимаются автоматически.
- `OnBeforeBattleReplay` вызывается после возврата из отменённой попытки, `OnBattleReplay` — после восстановления и перед новой попыткой. Скрипты, которым нужен собственный откат, должны учитывать эти события.
- `GetNpc`, условие `on == 1 && alive != 1`, `CheckForCompleteAI`, `BACall_Day/Turn` и перехват астрального духа оставлены по исходной логике WoG. Их корректность не подтверждена этой базой.
- Полный хвост StartBattle имеет и другие действия (мобилизация героя, интерфейс, AutoSolo). В промежуточных попытках они не выполняются, как и в исходнике. Работа с AutoSolo и выход в главное меню требуют проверки в игре.
- Не изменены генератор случайных чисел и семантика `seed == -1`: повтор не обещает идентичную случайную последовательность.
- DLL собрана и логика снимков протестирована; реальная сетевая игра не запускалась. Исправление следует считать кандидатом для игровой проверки, а не подтверждённым сетевым релизом.

## Загрузка из битвы: исправление 10.10.2026

В прежней реализации `currentReplay` указывал на локальный `ReplayContext`. Он обнулялся только деструктором `ContextScope`. `FastQuitToGameMenu` в ERA поднимает Windows-исключение, перехватываемое в `Splice_ExecuteManager` (`Triggers.pas`); обычный возврат через кадр BattleReplay отсутствует. Без `/EHa` C++-деструкторы не гарантированы. После такого выхода оставшийся указатель делал следующий бой «вложенным»: проверка `!nested` запрещала переигровку, а чтение флагов старого контекста могло обращаться к уже недействительному стеку.

Состояние теперь сбрасывается явно на событиях выхода, загрузки и входа в игру. Сброс обнуляет указатель без разыменования старого кадра и меняет поколение контекста. Возврат старого деструктора или обработчика ERM после загрузки не может восстановить этот указатель, продолжить повтор с прежними героями/армиями или перезаписать новую настройку быстрого боя. Резервные значения игры и `HD.QuickCombat` хранятся отдельно от кадра боя и восстанавливаются обработчиком жизненного цикла до загрузки. Повторный сброс безопасен. `/EHa` дополнительно обеспечивает освобождение скопированной биографии героя и других принадлежащих снимкам ресурсов при исключении ERA; исключение не подавляется.

Добавлены проверки брошенного кадра, нормального вложенного боя, позднего деструктора после создания нового контекста, двух различных настроек игры/HD, повторного сброса, отсутствующей переменной HD и настоящего `RaiseException` с перехватом во внешнем SEH-кадре. Все девять групп прошли; Debug/Release собраны. Загрузка из реального игрового окна требует ручной проверки: загрузить `BATTLE!` через L/Ctrl+L или меню настроек во время первой и повторной попытки, снова начать бой и проверить кнопку повтора. Повторить с обычным сохранением и с выходом в главное меню.

## План игровой проверки

На двух компьютерах или экземплярах игры с одинаковой новой DLL и отключённым старым BattleReplay:

| Сценарий | Проверяемый результат |
|---|---|
| ИИ нападает на героя игрока, который не завершал ход последним | После проигрыша и 2–3 повторов исходные типы/численности всех 7 слотов и мана возвращаются |
| То же для игрока, последним завершившего ход | Поведение совпадает; проверить обе сетевые роли, включая хост/клиент |
| ИИ нападает на город с героем в гарнизоне или гостевым героем | Армия боя, армия героя и гарнизон соответствуют состоянию до боя; повторить после победы и после поражения |
| ИИ нападает на город без героя | Армия гарнизона восстанавливается; командир и герой не разыменовываются |
| Победа с потерями, затем повтор, затем принятие результата | Повтор получает полную исходную армию, принятый бой сохраняет реальные потери на обеих машинах |
| Отступление/откуп, затем повтор | Армия и золото возвращаются; после принятого откупа расход золота происходит один раз |
| Сетевой бой человек–человек | Кнопка повтора отсутствует; обе машины продолжают обычный бой |
| Одиночная игра, hotseat, быстрый бой и ручная попытка | Повтор работает, исходные настройки игры/HD восстанавливаются независимо |
| Включённый таймер хода и несколько долгих повторов | Отменённые бои не списывают время хода, после принятия таймер продолжает работу |
| Командиры, астральный дух, опыт стеков, события ERM | Нет дублирования наград/призывов; это отдельная непроверенная WoG-часть |
| Выход в меню через HD во время попытки | Нет нового боя, зависания или сохранения флага повтора |

После принятия результата сверить армии, золото, опыт, артефакты, владельца города и продолжение хода ИИ на обеих машинах, затем сохранить/загрузить игру и повторить сверку.
