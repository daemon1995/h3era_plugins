# ERM-интерфейс описаний заклинаний, версия 1

Плагин вызывает `!?FU(OnQuerySpellDescription)` через ERA. Без обработчиков
действуют текущие флаги и обычный расчёт. C++ не проверяет названия модов,
опции WoG или их переменные. Прогноз не меняет механику самого заклинания.

| Аргумент | Значение |
| --- | --- |
| x1 | Версия интерфейса, 1 |
| x2 | Фаза: 0 — классификация, 1 — готовое число для книги, 2 — длительность |
| x3 | Контекст: 0 — книга, 1 — боевое наведение/API |
| x4 | ID заклинания |
| x5 | Текущие флаги заклинания |
| x6 | ID героя, -1 при отсутствии/касте существа |
| x7 | Номер кастующего стека для BM (сторона × 21 + индекс), иначе -1 |
| x8 | Номер стека под курсором для BM, иначе -1 |
| x9 | Сила магии |
| x10 | Уровень школы, 0..3 |
| x11 | Тип описания; вход/выход в фазе 0 |
| x12 | Готовое число после бонусов героя; в фазе 2 — число раундов, в фазе 0 — -1 |
| x13 | Показывать дополнительное описание: 1; вернуть 0 для отключения |
| x14 | Сторона кастующего, -1 для книги |
| x15 | Целевой гекс, -1 для книги |
| x16 | В фазе 2 — тип длительности; в других фазах резерв, 0 |

Типы x11: 0 — без дополнительного описания; 1 — урон; 2 — восстановление;
3 — лечение; 4 — жертва; 5 — гипноз; 6 — призыв; 7 — телепорт;
8 — удаление препятствия; 9 — мина; 10 — огненная стена; 11 — длительный эффект.
Телепорт и удаление препятствия оставляют штатные подсказки: численной строки
для них нет. Возврат типа не переопределяет геометрию, иммунитеты и выбор
целей движком; они по-прежнему берутся из текущих флагов и игровых функций.
В фазе 0 x8 — стек под курсором до дополнительного выбора трупа/цели жертвы.

Обработчик меняет x11/x13 в фазе 0 либо x12/x13 в фазе 1 через `!!VR`.
Остальные поля доступны для чтения. Отрицательное число в фазе 1, неизвестный
тип, версия или значение x13 приводят к использованию исходного результата.
Ноль в x12 — корректный эффект, а не признак отсутствия обработчика.
Число фазы 1 уже окончательное: бонусы героя повторно не применяются.

## Длительность, фаза 2

Расширение сохраняет версию 1 и размер x1..x16; прежние фазы не меняются.
Фаза 2 вызывается для книги и боевого наведения у длительных эффектов,
включая гипноз (x11=5). x9 содержит исходную силу магии, x12 — готовый срок
после бонусов экипировки. Для одиночной цели x12 также учитывает более
долгий уже действующий эффект: обычный повторный каст его не сокращает.
Для массового эффекта показывается срок нового наложения; текущие таймеры
разных отрядов могут отличаться. ERM получает в x8 отряд под курсором.

Типы x16:

| x16 | Значение |
| --- | --- |
| 0 | Не показывать длительность |
| 1 | Число раундов в x12 |
| 2 | До конца боя |
| 3 | До следующей атаки отряда |
| 4 | До следующего хода отряда |
| 5 | Число раундов в x12; снимается атакой по отряду |
| 6 | Число раундов в x12; снимается при получении урона |

В фазе 2 можно менять x12/x16 или отключать строку через x13=0. Для типов
1/5/6 требуется положительное x12. Неизвестный тип или неверный срок
оставляют исходный расчёт. Тип 0 отключает только длительность, сохраняя,
например, порог здоровья гипноза в книге. Все формулировки берутся из JSON.
Мод может классифицировать своё заклинание как x11=11 в фазе 0, а в фазе 2
вернуть собственный срок, даже если текущие флаги не дают штатного таймера.
Ограничивайте обработчики нужной фазой: x12/x16 имеют разный смысл в них.

```erm
!?FU(OnQuerySpellDescription)&x1=1/x2=2/x11=11;
; Пример: добавить два раунда к обычному численному сроку.
!!VRx12&x16=1:+2;
```

Это меняет только отображаемый прогноз. Фактическую механику мод реализует
сам; обработчик запроса должен быть чистым, без выполнения реального каста.

Например, мод может отключить неточный прогноз призыва в книге:

```erm
!?FU(OnQuerySpellDescription)&x1=1/x2=1/x3=0/x11=6;
!!VRx13:S0;
```

Пример проверки передачи численного результата — удвоить только отображаемое
число призыва в книге (это демонстрация протокола, реальный каст не меняется):

```erm
!?FU(OnQuerySpellDescription)&x1=1/x2=1/x3=0/x11=6;
!!VRx12:*2;
```

Или установить свой тип для изменённого заклинания в фазе 0:

```erm
!?FU(OnQuerySpellDescription)&x1=1/x2=0;
; Здесь скрипт проверяет x4, свои опции и другие входные параметры.
; После успешной проверки выбирает, например, лечение:
; !!VRx11:S3;
```

Готовый адаптер прежнего поведения ReMagic —
`examples/remagic_spell_description.erm`. Он отключает строку призыва только
при включённой опции этого мода. Установить его можно в `Data/s` мода ReMagic;
в основной C++-плагин он не вшит. Для точного количества ReMagic должен
вместо отключения вернуть свою чистую формулу в x12; вызывать обработчик
реального каста, добавляющий существ, во время запроса нельзя.

Боевой урон проходит через уже работающие MR0/MR1; фаза 1 для боя не
вызывается, чтобы не дублировать поправки сопротивления. Все видимые тексты
продолжают поступать из JSON `interface_spells_description.*`; ERM возвращает только числа.

ERA получает аргументы из `GetArgXVars()`, а возвращает их через
`GetRetXVars()`. Плагин копирует результат и восстанавливает оба массива
по 16 значений, включая вложенные вызовы. Запрос по имени разрешается каждый
раз: числовой ID не остаётся устаревшим после перекомпиляции ERM. Повторный
вход в запрос/форматирование блокируется. Безопасность обработчика зависит
и от его кода: не меняйте постоянные переменные, армию, RNG и не открывайте
диалоги. Плагин не выполняет транзакционный откат произвольных ERM-команд.

Все обработчики одного события выполняются в порядке ERA. Если несколько
модов меняют одно поле, действует последнее значение; используйте условия,
ограничивающие обработчик своим заклинанием/режимом. Общего приоритета модов
этот интерфейс не вводит.
