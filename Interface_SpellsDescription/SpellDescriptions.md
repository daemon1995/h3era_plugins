# Подробные описания заклинаний

`Interface_SpellsDescription` — самостоятельный плагин. Его `dllmain.cpp` публикует
API при загрузке DLL и вызывает `SpellDescriptions::Install(_PI)` в `HooksInit`
на прежней точке инициализации игры `0x4EEAF2`. Плагин не зависит от настроек.
Использует структуры H3API и методы героя/боевого стека. Боевой урон считается
через `H3CombatManager::CalculateSpellDamageOnTarget`, включая штатные
перехваты WoG/ERA. Получение силы магии командиров и игровые функции, для
которых в этой версии H3API нет обёртки, вынесены в вспомогательные функции.

Возможности:

- В полном описании по ПКМ в книге: урон с бонусами героя, лечение, восстановление, гипноз, мины,
  огненная стена, первая цель цепной молнии и количество призываемых элементалей.
- При наведении на цель: урон после сопротивления големов/командиров,
  опыта стеков и защитных заклинаний; число погибающих или воскрешаемых существ;
  фактическое лечение раненого существа и обе стадии жертвы.
- Подсказки архангелов, высших архангелов, пит-лордов, волшебных драконов и командиров.
- Для площадного урона: число затронутых отрядов, сумма урона и погибающих
  существ по всем целям обеих сторон. Двухгексовый стек считается один раз;
  пустой центр не мешает расчёту, центр ледяного кольца исключается.
- Для цепной молнии: подсветка гексов целей и номера порядка попаданий
  поверх существ; в хинтбаре — общие суммы. Внешний API сохраняет текстовую
  последовательность, урон и потери каждой цели. Следующий удар получает половину исходного
  урона предыдущего прыжка до бонусов героя и защит конкретного стека.
- Совместимый API `ERA.SpellsDescription.BattleHint.Api.1`. Явно переданные
  сила и уровень магии существа используются и для площадного урона/цепи.
  Для площадных и глобальных заклинаний `targetStack` может быть нулевым;
  область определяется по `targetHex`.

Обычные одиночные касты существ исключают бонусы героя, как в игровом
`CombatManager::CastSpell`; на волшебных равнинах учитывается экспертный уровень.
Функции площадного урона `0x5A4C80`, армагеддона и цепной молнии `0x5A6670`
сами берут боевого героя, включая касты существ. Прогноз учитывает это
поведение, включая вызовы через API.

Тип выбирается по текущим `H3Spell::flags`, `type` и `spEffect` при каждом
показе. Флаг `damageSpell` имеет приоритет. ID используются только там, где
флаги не различают механику: две стадии жертвы, телепорт/клон, мины/стена,
выбор живой или неживой цели для восстановления. Цепная молния определяется
по сочетанию `damageSpell`, `aiAreaEffect` и `singleTarget`.

Площадная геометрия берётся из игрового `0x5A4480`, который вызывается при
настоящем касте через `0x5A4A00`. Радиус инферно и исключение центра ледяного
кольца повторяют `0x5A4C80`; эти ID различают геометрию, а не тип строки.
Заклинания без одиночной цели и `targetAnywhere` рассчитываются по всему полю.
Проверка применимости/сопротивления — `0x5A83A0`, без вызовов `Random`.

Выбор прыжков сверён с `0x5A6500`, вызываемой из `0x5A6670`: расстояние между
`H3CombatCreature::GetX/GetY` округляется вниз, при равенстве выигрывает первый
стек в порядке стороны и индекса. Попадание в уже выбранный стек исключено.
Число ударов берётся из таблицы `0x642284` по текущему уровню школы, а не
зашито как 4/5. Сам прогноз не применяет урон, анимации и не вызывает RNG.
Обработчики ERM выполняются; их побочные эффекты зависят от самих скриптов.

Если есть случайное сопротивление, JSON-шаблон явно указывает условие:
все проверки сопротивления пройдут. При реальном касте сопротивление может
изменить число потерь и маршрут цепи; заранее узнать будущие случайные значения
без вмешательства в RNG нельзя. Полный иммунитет исключает стек из прогноза.
Сумма урона — сумма вычисленных ударов, включая избыточный урон; число погибших
ограничено численностью каждой цели. Слишком длинная цепь в текстовом ответе API заменяется
полными общими суммами, чтобы не обрезать текст в буфере.

Числа выводятся полностью, без округления в `k`/`M`. Восстановление учитывает
ранение верхнего существа; для мёртвого стека старое `healthLost` игнорируется.
Для клона любой положительный урон означает гибель всего стека.
Формула жертвы сверена с игровым кодом: `(HP из таблицы существ + сила магии +
baseValue уровня) × число существ`, с учётом частично воскрешаемой последней
особи. Призыв использует `baseValue уровня × силу магии`. Скрипты с другой
формулой могут переопределить число или отключить строку через ERM-запрос,
описанный в [SpellDescriptionErm.md](SpellDescriptionErm.md).

Все шаблоны описаний находятся только в JSON установленного мода:
`D:\games\HoMM 3 ERA\Mods\WoG\lang\interface_spells_description.json` и
`D:\games\HoMM 3 ERA\Mods\WoG\lang\ru\interface_spells_description.json`.
Ключи принадлежат отдельному плагину: `interface_spells_description.*`.
EN/RU JSON не хранятся в репозитории и не включаются в проект.
`tools/validate_spell_texts.py --game-dir <путь>` проверяет установленную
локализацию: соответствие ключей исходникам, printf-форматы и полноту EN/RU.
Полоса здоровья и её переводы остаются в ERA_SystemOptionsExtension.

Строки читаются через `EraJS::read` непосредственно при показе, как в
`SystemOptionsDlg` и `DlgPanels`. Выбор локализации выполняет ERA. В коде нет
встроенных текстов, проверки языка, кэша переводов и обработчика смены языка.
Старый `SpDescr.txt` не нужен. Книга использует один `%d`, боевые подсказки —
`%s` в порядке, указанном в исходнике. Если ключ отсутствует или формат
несовместим, дополнительное описание не подставляется; API возвращает
`FORMAT_DECLINED`.

Новые ключи `battle.areaDamage` (5 × `%s`), `battle.chainDamage` (6 × `%s`),
`battle.chainTarget` (5 × `%s`) и `battle.resistanceCondition` (без параметров)
находятся в тех же JSON. Порядок параметров: имя заклинания, число стеков,
суммарный урон, число погибших, затем цепь (если нужна) и условие сопротивления.
Для шага цепи: номер удара, имя существ, гекс, урон, число погибших.

ПКМ использует игровой сборщик описания `0x59BDA0` (вызов `0x59D3BA`).
Подробная строка добавляется к его локальному `H3String` через `Append` в
`0x59BFB3`, до копирования в результат. Второе полное окно (`0x59D7B6`)
получает ту же строку. Краткое описание при наведении (`0x59DA42`) сохраняется.
Штатная строка урона пропускается переходом к `0x59C084` только после
успешного добавления новой строки. При отсутствии/ошибке JSON или отказе ERM
сохраняется штатное описание; дополнительная строка не дублируется.

При установке используйте **Interface_SpellsDescription** вместе с обновлённым
**ERA_SystemOptionsExtension**, из которого полностью удалены хуки описаний.
Старый **Spells_Description** должен быть отключён. Прежнюю версию настроек
с описаниями нельзя загружать одновременно: эти модули ставят хуки на одни адреса.
Остальные модификации должны сохранять стандартные правила расчёта или
перехватывать соответствующие игровые функции; произвольные ERM-формулы
нового заклинания нельзя вывести только из его флагов.

Поддержка ERM MR (02.10.2026): `ReducedDamage` вызывает полный игровой
расчёт с настоящей целью (`H3CombatManager::CalculateSpellDamageOnTarget`,
`0x5A7BF0`, `showLog=false`). Бонусы героя уже учтены перед этим вызовом,
поэтому `atkHero=nullptr` предотвращает их повторное применение.
В установленном `h3era.exe` таблица патчей WoG связывает вызов `0x5A7C3B`
с обёрткой `0x75D88D`: MR0 -> сопротивление обычного существа/командира ->
опыт стека -> MR1. Защита заклинанием применяется затем внутри `0x5A7BF0`.
Прямые повторные вызовы сопротивления/опыта/защиты удалены.

`!?MR0` и `!?FU(OnMagicBasicResistance)` — один триггер ERA 30307;
`!?MR1` и `!?FU(OnMagicCorrectedResistance)` — триггер 30308. Движок сам
выполняет оба вида записи. Указатель настоящей цели в EDI задаёт правильный
`MR:N` (исправление ERA `Erm.pas`, `Hook_MR_N`). Один путь используется для
одиночных, площадных и цепных боевых подсказок и API.

При прогнозе временно задаются `BG:A` (герой/существо), номер заклинания,
целевой гекс, сторона и `i^battle_current_side^`. Это нужно, например,
для обработчика в `7 wog - enhanced artifacts.erm:303`, который проверяет
`BG:A = BATTLE_ACTION_HERO_CAST` перед процентной поправкой `MR:D`.
Обработчик `28 wog - enhanced monsters.erm:557` изменяет `MR:F` для мумий
и призраков; его результат теперь проходит в расчёт потерь. Рядом найденный
обработчик в `30 wog - enhanced secondary skills.erm:525` относится к MR2,
то есть к шансу полного сопротивления, а не к проценту уменьшения урона.

`ScopedSpellPreview` восстанавливает поля действия, сторону, ассоциативные
переменные и восемь служебных полей MR0/MR1/MR2 после расчёта. Адреса WoG
разрешаются через `Era::GetRealAddr`, с учётом переноса расширенной памяти.
Повторный вход в форматирование из обработчика MR отклоняется.
Поля `MR:D`, `MR:S`, `MR:M`, `MR:F`, указатель цели и служебные значения
внешнего MR сохраняются также при вложенном вызове.

Для ERM во время прогноза доступен `i^era.opt.spells.preview^ = 1`;
после него прежнее значение восстанавливается. Чистые поправки D/F, как
в проверенных скриптах, выполняются без изменения их исходников.
Произвольные скрипты, меняющие постоянные переменные/армию или вызывающие
диалоги/RNG, должны сами пропускать такие действия при этом флаге, сохраняя
формулу D/F. Плагин не откатывает произвольные побочные эффекты ERM.
Последующие изменения в MF, например MF1 для волны смерти, в прогноз MR
не входят. Книга без выбранной цели показывает базовый эффект без MR.

Справка: [триггер MR](https://asmedian.github.io/modding-guide/ru/erm/triggers/mr/)
и [ресивер MR](https://asmedian.github.io/modding-guide/ru/erm/receivers/mr/).

Для проверки интерфейса
в игре нужны книга заклинаний, живые/мёртвые цели, обе стороны боя, жертва,
касты существ, защита от магии и мод, меняющий флаги заклинаний.
Для MR: опция улучшенных артефактов с Кольцом мага (50%), обычная цель
и голем под защитой; обе стороны; площадной удар и цепная молния.
Сравните число потерь с реальным кастом. Для улучшенных существ проверьте
MR1 на мумиях и призраках. Убедитесь, что простое наведение не применяет
урон и после него остаются прежние поля действия и `battle_current_side`.
Без запуска игры подтверждены сборка, алгоритмы и восстановление контекста;
исполнение обработчиков в живом бою требует этой проверки.

Оптимизация и повторная проверка (02.10.2026):

- Числа форматируются в собственном буфере без `std::to_string`/printf;
  проверены ноль, отрицательные значения, границы int64 и копирование.
- Цепь собирается в ограниченном буфере до 1024 байт с учётом ёмкости
  конкретного запроса. Неполный шаг не добавляется; при переполнении остаются
  полные итоговые суммы. Растущего `std::string` в боевом форматировании нет.
- JSON-шаблон шага читается и проверяется один раз для всей цепи. Общего кэша
  переводов/результатов нет: текущие флаги, язык, ERM и MR учитываются заново.
- Цели хранятся в одном массиве, без дублирования 42 указателей. ERM-массивы
  сохраняются как непрерывные значения, без дополнительных массивов указателей.
- Положительный шанс ниже 1% больше не превращается в иммунитет из-за
  округления. Для цепи условие случайного сопротивления учитывает выбранные
  цели, а не любой отряд, рассматривавшийся как кандидат следующего прыжка.
- Книга использует один хук вместо двух; возврат к штатному тексту сохраняется
  при отказе обработчика или непригодном JSON. Пустой перевод необязательного
  условия сопротивления допускается, опасные printf-форматы отклоняются.
- Формулировки EN/RU сокращены. Призыв описывает количество существ, поскольку
  мод может менять их тип. Названия клавиш полосы здоровья также берутся из
  JSON; ширина поля определяется по переводам. Старые варианты ключа
  `toggable`/`toggleable` сохранены в переводах для совместимости.

Работа MR при наведении подтверждена пользователем до этой оптимизации.
Новый возврат к штатной строке книги и локализованные клавиши требуют
визуальной проверки в игре; автоматические проверки этих экранов не проводились.

Подсветка цепи на поле (02.10.2026):

`SpellDescriptionOverlay.cpp` рисует золотой контур и лёгкую подсветку
каждого целевого гекса; номер от 1 рисуется на контрастной плашке поверх
существ. У двухгексового стека выделяются обе клетки, номер остаётся один.
Шаблон номера `interface_spells_description.battle.chainIndex` хранится в EN/RU JSON.
Размеры клетки соответствуют стандартной графике поля 45×52. Координаты
берутся из H3CombatSquare с учётом смещения диалога; H3API поддерживает
16- и 32-битный холст, рисование ограничено его границами.

Маршрут передаётся из уже выполненного MR-прогноза после восстановления
контекста заклинания. Рендер не вызывает MR/ERM, не пересчитывает урон
и не изменяет генератор случайных чисел, доступность клеток или анимацию.
Хранится не более 42 целей (числовые гексы и BM-индексы) в фиксированном массиве.
Обычный текстовый API не создаёт/не очищает подсветку.

Предыдущая версия принудительно копировала весь фон при частичном обновлении
боя; пользователь подтвердил исчезновение существ. Эти перехваты полностью
удалены: `0x493FC0`, `0x49403E`, `0x4940EF`, `0x494641` больше не меняются.
Подсветка не вызывает `H3CombatManager::Refresh` и не перерисовывает боевой фон.

Хайхук `0x43DE60` накладывает подсветку в экранный буфер после штатной
отрисовки стека, включая обновление одной плашки численности. Сигнатура
проверена по дизассемблированию `h3era.exe` (`ret 0Ch`), месту вызова
`0x494468` и `NH3API::DrawToBuffer`: `void __thiscall (stack, x, y,
BOOL numberBoxOnly)`. Все исходные аргументы передаются без изменения.
Отметки остаются в холсте и попадают также в вывод, обходящий `H3Redraw`.
Хук стека не вызывает вывод на экран, перерисовку боя или расчёт MR.

Перед очередной отрисовкой стека убирается прежний слой отметок. Для этого
сохраняются пиксели клеток до и после рисования: восстанавливается только
пиксель, всё ещё совпадающий с нашим последним изображением. Новые пиксели
анимации/фона внутри этих областей сохраняются. После штатного вызова
контуры и номера рисуются заново поверх текущего кадра всех целей: крупное
соседнее существо тоже может перекрыть целевой гекс. `H3Redraw` (`0x603190`)
обновляет слой перед выводом пересекающего цели прямоугольника и передаёт
исходный прямоугольник без изменения. Снимки всех пересекающихся областей
делаются до рисования; осветление не накапливается. Плашка номера ограничена
шириной гекса. Замена холста или разрядности сбрасывает старый снимок.

При смене/отмене маршрута выводятся только отдельные клетки старой и новой
цепи, без повторной отрисовки существ, всего поля или строки подсказки.
Маршрут хранится в фиксированном массиве. Снимки пикселей используют повторно
ёмкость двух буферов: максимум 2×84 клетки 45×52×4 байта (1 572 480 байт), обычно
существенно меньше. Запросы вывода, не пересекающие цели, обходятся без снимков.

Смена курсора (`0x50CEA0`), неподходящий прогноз и начало настоящего каста
(`0x5A0140`) очищают отметки. Новый бой, завершение боя и выход из игры
сбрасывают состояние. Перед рисованием проверяются сторона, ход, действие,
параметр действия, курсор и положение/жизнь каждого стека; при модальном окне подсветка не
рисуется. При отмене выбора цепи штатный возврат курсора очищает её.

Курсор сравнивается по фактическому состоянию **после** `SetCursor`, а не
по запрошенным аргументам. В штатном `0x50CF4B` для типа 3 передаётся кадр 0
в `0x50DAB0`, который сохраняет его в `cursorFrame`, хотя обработчик наведения
`0x59FA10` запрашивает `spellId + 1`. Повторный запрос того же заклинания и
аргументы -1 не сбрасывают маршрут. Изменение параметра действия проверяется
отдельно: общий кадр 0 сам по себе не различает выбранные заклинания.

Проверки: сборка, тесты маршрута (включая двухгексовые цели, границы 187/42,
повторы и соседние строки поля), сигнатуры JSON, разбор штатного конвейера
отрисовки. Визуальная проверка в живом бою ещё нужна: смена первой цели,
пустой/иммунный гекс, ESC, реальный каст, две стороны, двухгексовые существа,
случайное сопротивление и разрешение HD. Нестандартная геометрия клеток
или мод, полностью заменяющий штатную отрисовку, требуют отдельной проверки.


Регрессионная проверка после замечания о перерисовке: восстановление пикселей
16/32-битного холста с дополненными строками, пересекающихся областей,
краёв экрана, 20 последовательных кадров без накопления изменений и предела
84 областей. Проверяется также частичная запись нового кадра внутрь отметок,
сохранение всего 16/32-битного пикселя при изменении одного его байта и
повторная очистка пересекающихся областей. Визуальное отсутствие бликов
в предыдущей сборке подтверждено пользователем; новый хук стека требует
проверки в живом бою.
Диагностическое логирование, дампы кадров и наблюдающие хуки удалены из
исходников. Рабочие хуки отрисовки сохранены; плагин не создаёт файлы логов.

# Длительность эффектов

В книге по ПКМ и при боевом наведении поддерживаются длительные эффекты.
Обычные баффы/дебаффы определяются по текущему `timeScale`; срок равен силе
магии с бонусом экипировки из функции движка `0x4E5020`. При обычном касте
существа бонус героя не добавляется; клон использует отдельный расчёт движка
от боевого героя. Повторный одиночный каст не сокращает более
долгий уже действующий таймер. Для массового каста указан срок нового эффекта.

Особые правила из движка: разрушающий луч действует до конца боя, берсерк —
до следующей атаки, бешенство — до следующего хода. Слепота/окаменение/паралич
показывают только срок в раундах; клон — также только срок в раундах.
Дополнительные пояснения о снятии атакой или уроном в EN/RU JSON удалены.
ID нужны только для этих неразличимых по флагам механик движка;
обычная классификация и изменённые модами флаги остаются приоритетными.
Гипноз в книге сохраняет порог здоровья и получает строку длительности.

ERM `OnQuerySpellDescription` дополнен фазой 2 для изменения срока и условия
завершения; версия/ABI прежних фаз сохранены. Тексты — только в EN/RU JSON.
Если нет проверенного расчёта или обязательного JSON-ключа, остаётся штатное
описание. Произвольные изменения таймеров ERM при реальном касте требуют
соответствующего обработчика прогноза фазы 2.
