# API_ErmFunctions

Плагин `API_ErmFunctions.era` добавлен в `H3EraPlugins.sln` (Debug/Release, x86). Он направляет зарегистрированные объекты в штатную отрисовку DEF с цветом владельца. Подходящие пиксели флага должны уже присутствовать в DEF; плагин не добавляет отдельную картинку флага. Изменение игровых наград, посещение и захват остаются задачей скрипта.

При отрисовке ERM не вызывается: два горячих хука option 879 заменены C++ LoHook. Получение владельца кэшируется в памяти. Нативная отрисовка сохраняет анимацию, границы экрана и порядок слоёв. Мини-карта получает цвет объекта внутри штатной проверки видимости, после проверки маркера героя.

Для HD_WOG добавлены отдельные хуки его 16/32-битного рисования: плагин передаёт цвет в штатную ветку HD-маркеров, сохраняя изменяемый размер мини-карты и окраску при уменьшении больших карт. Точки находятся по сигнатурам загруженной DLL; файл HD-мода не изменяется. Адреса, способ подключения и проверки описаны в [HD_MINIMAP.md](HD_MINIMAP.md).

Отрисовка вынесена в `ObjectRendering.cpp`/`ObjectRendering.h`. Мини-карта окрашивает занятые клетки и вход реального объекта, сохраняя штатное масштабирование HD; фон и проходимая часть DEF не увеличивают маркер. Диагностический лог установки HD-хуков удалён.

## API

Добавлен API замены объектов по действующим маскам и координатам входа. Контракт, JSON-правила, ограничения v1 и проверки описаны в [OBJECT_REPLACEMENT.md](OBJECT_REPLACEMENT.md).

Все экспорты имеют недекорированные имена и соглашение `__stdcall`. Заголовок для C++: `headers/EraPluginsAPI/ErmFunctionsAPI.h`. Через ERM вызываются `SN:F^API_ErmFunctions:ИмяФункции^/...`; результат находится в `v1`. Такой синтаксис требует ERA 3.9.29 или новее. В более ранних версиях DLL можно вызывать через адрес экспортированной функции и `SN:E`.

| Экспорт | Аргументы | Результат |
|---|---|---|
| `Erm_RegisterObjectType` | `type, subtype, drawOnMinimap` | `1` — зарегистрирован, `0` — ошибка |
| `Erm_SetObjectOwner` | `x, y, z, owner` | `1` — назначен (включая прежнего владельца), `0` — ошибка |
| `Erm_GetObjectOwner` | `x, y, z` | `-1` — нейтральный, `0..7` — игрок, `-2` — ошибка |
| `Erm_RegisterReplayEvent` | `redoFunction, undoFunction, x1, x2, x3, x4` | `1` — событие записано, `0` — ошибка |
| `Erm_RegisterReplayEventArgs` | `redoFunction, undoFunction, int* args, argCount` | `1` — событие записано, `0` — ошибка |
| `Erm_ReadJsonInt` | `const char* key, defaultValue` | целое из JSON либо переданное значение по умолчанию |
| `Erm_ReadJsonIntArray` | `const char* key, int* output, capacity` | размер при `output=0/capacity=0`; иначе число записанных целых |

JSON-читатели используют текущие данные языка ERA без собственного кэша. Числа проверяются как знаковые 32-битные целые; пустые, дробные, переполненные и некорректные значения отклоняются. Массив читается из последовательных ключей `key.0`, `key.1`, ... до первого отсутствующего индекса; скаляр тоже поддерживается. Некорректный элемент возвращает `0` без записи части массива. Запрос размера не собирает временный массив; при заполнении буфера временно хранятся только помещающиеся в него числа, но проверяется вся последовательность. Строка индексированного ключа используется повторно. Переданный буфер принадлежит вызывающему коду и должен вмещать `capacity` целых; функция записывает не более этого количества.

В `wogify_merged` общий `WOG_IFY_ReadIds` определяет размер, выделяет ERM-массив и заполняет его вторым вызовом API. Это убирает отдельные ERM-вызовы чтения, преобразования и добавления каждого ID. `WOG_IFY_ReadInt` использует нативный числовой читатель. Адреса обновляются после загрузки карты и перед вогификацией; при отсутствии новых экспортов сохраняется прежний ERM-путь. Изменения времени выполнения в игре пока не измерены. Проверки обоих читателей включены в `run-tests.cmd`. Горячий путь замены теперь напрямую вызывает удаление WoG из EXE, использует геометрию без копирования векторов и локальный буфер выбора прототипа. Замеры отдельных операций и их ограничения приведены в `OBJECT_REPLACEMENT.md`.

Координаты обозначают вход объекта (жёлтую клетку), а не нижний правый угол DEF. Поддерживается объект под стоящим на входе героем. Недопустимые координаты, отсутствующий подземный уровень и незарегистрированные объекты отклоняются. Допустимые владельцы: `-1..7`.

Типы: `0..231`; подтипы: `0..32767`, либо `-1` для всех подтипов. Точная регистрация имеет приоритет над `-1`. Повторная регистрация обновляет настройку мини-карты; флаг `drawOnMinimap` принимает только `0` или `1`. На мини-карте используются штатные цвета владельцев, включая нейтральный цвет для `-1`. Отрисовка флага действует для объёмных объектов, проходящих штатную ветку отрисовки; плоские объекты сохраняют поведение игры.

Регистрация нужна при каждом входе на новую/загруженную карту, например в `!?FU(OnGameEnter)` или при создании ERM-хуков опции. Для option 879 регистрируются водяная мельница, ветряная мельница, мистический сад и склад (`142`). Автоматической регистрации нет: плагин работает только с запрошенными скриптом типами.

```erm
!!SN:F^API_ErmFunctions:Erm_RegisterObjectType^/(OBJ_WINDMILL)/-1/1;
!!SN:F^API_ErmFunctions:Erm_SetObjectOwner^/(x)/(y)/(z)/(owner);
!!VR(success:y):Sv1;
!!SN:F^API_ErmFunctions:Erm_GetObjectOwner^/(x)/(y)/(z);
!!VR(owner:y):Sv1;
```

## Сохранение и выход

Владелец хранится в `i^API_ErmFunctions.Owner.<packedCoords>^` через `Era::SetAssocVarIntValue(name, owner + 1)`. Упаковка: `(x & 1023) | ((y & 1023) << 16) | ((z & 1) << 26)`. Отсутствующая переменная/значение `0` означает владельца `-1`; игроки кодируются как `1..8`. Нейтральные объекты не создают переменных при чтении.

Переменная обновляется при смене владельца и сохраняется штатным механизмом ERM вместе с картой. Собственная savegame-секция не требуется. На `OnAfterLoadGame` кэш владельцев сбрасывается и далее читается из восстановленных переменных. На `OnGameLeave`, `OnGameLeft`, `OnBeforeLoadGame` очищаются регистрации, кэш и replay. Сами ERM-переменные загружаются/сбрасываются движком ERA. Менять их следует через API, чтобы кэш соответствовал сохранению. `PO:O` — отдельное хранилище и автоматически с API не синхронизируется.

## Replay хода

Изменение владельца через API записывается автоматически. При replay владельцы откатываются перед начальным кадром и затем меняются между соответствующими штатными действиями. Воспроизведение использует временные значения: ассоциативные переменные и итоговое владение не переписываются.

Для произвольного события вызовите `Erm_RegisterReplayEvent` после выполнения настоящего события. Регистрация только запоминает callback и копирует параметры; сразу callback не вызывается. `redoFunction` — числовой ID ERM-функции, `undoFunction` — ID функции отката либо `0`. Callback получает записанные параметры в `x1..x4`; остальные `x` обнулены. Вариант `Args` принимает до 16 целых значений и копирует их, поэтому исходный массив можно освобождать. Аргументы — целые значения, а не сохраняемые указатели на временные строки/объекты.

```erm
!!SN:F^API_ErmFunctions:Erm_RegisterReplayEvent^/(MyEventRedo)/(MyEventUndo)/(x)/(y)/(z)/(value);
```

Undo вызывается в обратном порядке, redo — в прямом, включая несколько событий между одними и теми же действиями. Для callback, меняющего игровой мир, откат реализует скрипт. Для уведомления/эффекта можно передать `undoFunction = 0`. Повторная регистрация событий во время replay отклоняется; вызов `Erm_SetObjectOwner` из callback меняет только временное владение. Буфер аргументов ERA восстанавливается после callback, в том числе при системном исключении выхода/загрузки (`/EHa`).

События очищаются вместе со штатным списком действий при начале нового периода записи, а также при выходе/загрузке. Они **не записываются в сейв и не передаются по сети**. После загрузки воспроизведение старого штатного журнала не содержит событий плагина. Кнопка replay и скорость просмотра остаются штатными; нужны действия в штатном журнале, чтобы игра разрешила просмотр. Прерывание анимации просмотра клавишей по-прежнему применяет все действия и callbacks.

## Перевод option 879

В `examples/option 879 - capture mills and gardens.erm` находится адаптированная копия приложенного скрипта: убраны ERM-хуки отрисовки и их обработчики, добавлена регистрация типов, все обращения к `PO:O` переведены на API. Остальные хуки опции, замены DEF, сетевой вызов функции захвата, награды и подсказки сохранены. Скопировать нужно **вместо** исходного скрипта, с тем же именем, а не загрузить оба одновременно.

Для старых сейвов есть однократный импорт владельцев из `PO:O` при первом входе с новой версией. Маркер `API_ErmFunctions.Migrated879` сохраняется в ERM. Значения `PO:V0/V1` остаются в исходном хранилище.

По запросу пользователя адаптированная копия установлена в `D:/games/HoMM 3 ERA/Mods/ERA Scripts/Data/s/option 879 - capture mills and gardens.erm`, а Release-плагин — в `Mods/WoG/eraplugins/API_ErmFunctions.era`. Исходный скрипт сохранён в `build/API_ErmFunctions/Backup/option 879 - capture mills and gardens.before-api.erm`; хеши резервной копии и установленных файлов проверены.

## Проверка

`run-tests.cmd` запускается из Developer Command Prompt Visual Studio. Проверяет точные/общие регистрации, границы параметров, порядок undo/redo, временное владение и выбор клеток мини-карты. Также проверяет геометрию замены, кэш и выделения памяти; отдельный `Verification/run-object-replacement-hooks-tests.cmd` проверяет ABI с настоящим patcher. Если передать путь к `HD_WOG.dll`, проверяются также сигнатуры на реальном файле, ASLR и отказ при изменённом контракте. `Verification/verify_hd_marker_path.py` проверяет исходные инструкции HD в эмуляторе (48 случаев). Бинарники тестов помещаются в игнорируемый `API_ErmFunctions/build`.

Сборка отдельного проекта:

```text
msbuild API_ErmFunctions\API_ErmFunctions.vcxproj /p:Configuration=Release /p:Platform=Win32
```

По общим настройкам репозитория такая сборка устанавливает файл в `Mods/WoG/eraplugins`. Для проверки без установки задайте абсолютные `OutDir` и `IntDir` внутри рабочего каталога. Здесь сборки находятся в `build/API_ErmFunctions/Debug` и `build/API_ErmFunctions/Release`.

Debug и Release собраны с локальным `v141_xp`, экспортные таблицы проверены; тесты состояния прошли. Единственное предупреждение сборки — стандартное предупреждение MSBuild о прекращении поддержки XP.

Адреса сверены с локальным IDA-экспортом `h3era HD.exe`: `410B60` (флаг, `EDI=H3ObjectAttributes`, координаты `[EBP-44h]`), `412BA0` (мини-карта, `EBX=H3MapItem`, цвет `SI`), `4FF280` (вход DEF), `49D410` (undo/redo штатного журнала), `49D2A0` (очистка). Хуки: `410DCA`, `410F7C`, `412F33`, `49D4F8`, `49D50D`, `49D5A5`, `49D608`; HiHook: `49D410`, `49D2A0`. Начальные инструкции в 11 точках хуков/переходов дополнительно совпали с установленным `D:/games/HoMM 3 ERA/h3era HD.exe`. Требуется совместимая адресная база ERA/SoD. Визуальная проверка новой HD-совместимости в запущенной игре ещё нужна.

Игровые проверки: новый объект без владельца → захват двумя разными игроками → нейтрализация; подтипы с разными настройками мини-карты; объект под героем и закрытый туманом; сохранение/загрузка; выход и новая карта тех же координат; два просмотра одного хода; события до первого/после последнего штатного действия; выход/загрузка из callback; передача хода в сети. При обычной перерисовке ERM-log не должен получать вызовов функций отрисовки option 879.
