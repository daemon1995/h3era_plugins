# Общие кадры DEF: Graphics API v1

`API_ErmFunctions.era` владеет загрузкой PCX/DEF, созданными RLE-кадрами, кэшем и выбором палитры PCX8 при отрисовке. `ERA_ArtifactsExtender` и `ERA_DwellingsExtender` используют этот сервис. JSON, ID предметов/жилищ и расположение кадров в атласе остаются в соответствующих расширителях.

## Подключение и готовность

Публичный заголовок: [GraphicsAPI.h](../headers/EraPluginsAPI/GraphicsAPI.h). Экспорт `Erm_GetGraphicsApi(uint32_t version)` имеет C linkage и `__stdcall`. Версия 1 возвращает постоянную таблицу функций, неизвестная версия — `nullptr`. Между DLL передаются только структуры с упаковкой 4, целые числа, заимствованный указатель `H3LoadedDef*` и непрозрачные 32-битные `FrameHandle`. STL, исключения и освобождение памяти потребителю не передаются.

`era_graphics::GetApi()` получает таблицу из переменной патчера `ERA.Services.Graphics.v1`, проверяет версию, размер таблицы и функции. Имя DLL и поиск экспорта для обнаружения больше не нужны. Отсутствие сервиса не кэшируется. Экспорт `Erm_GetGraphicsApi` сохранён для старых двоичных клиентов.

Таблица доступна до готовности графики, но `isReady()` возвращает 0, а корректные `createFrame`/`applyFrames` — `NotReady`, не обращаясь к объектам движка. На `OnAfterCreateWindow` сервис подключает палитры к существующей цепочке ERA/HD и публикует `OnGraphicsResourcesReady`. Только после этого можно создавать кадры. Подписка на событие дополняется проверкой `isReady()`, поскольку потребитель может подключиться позднее.

Это сохраняет исправление PNG-подмен: до инициализации графики `PcxPngExists` уже может видеть PNG, тогда как PCX-загрузчик ещё возвращает `default.pcx` с ошибкой отсутствующего ресурса. Неудачные загрузки не попадают в кэш.

## Создание кадра

```cpp
const auto *api = era_graphics::GetApi();
if (!api || !api->isReady()) return;
era_graphics::FrameRequest request;
request.targetDef = target; // H3LoadedDef*, действителен во время вызова
request.resource = "myicon.pcx";
era_graphics::FrameHandle frame = 0;
if (api->createFrame(&request, &frame) != era_graphics::Ok) return;
```

Размер определяется `targetDef` (1–512 пикселей по каждой оси). Большой источник уменьшается ближайшим соседом с сохранением пропорций, маленький центрируется; увеличение отсутствует. Источник ограничен 4096×4096. Пустое имя создаёт вопросительный знак. Имена ресурсов регистронезависимы, как в игре.

Поддерживаются игровые `.pcx`, PNG-подмена ERA с именем `.pcx`, отдельный `.def` с `sourceGroup`/`sourceFrame` от нуля. Загрузчик сначала проверяет наличие ресурса, чтобы отсутствующий файл не вызывал модальное сообщение игры. Самоссылки и вложенное создание из обрабатываемого DEF отклоняются. Внешние PNG/BMP/JPEG/TIFF не декодируются; прежний WIC-код сохранён выключенным в `GraphicsBitmapDecoder.disabled.h`.

| Режим | Результат |
| --- | --- |
| `PreserveNativePcx` (по умолчанию) | PCX8 сохраняет индексы 0–255 и родную рабочую палитру. Индекс 0 прозрачен, 1–255 — обычные цвета в literal RLE1. |
| `TargetPalette` | Цвета переводятся в ближайшие индексы 8–255 палитры целевого DEF; голубой фон/прозрачность становятся индексом 0. Возможна потеря оттенков. |

PNG-подмены и отдельные DEF в обоих режимах используют `TargetPalette`. Они сначала рисуются штатным рендерером на голубом холсте; PNG-stub не читается как массив пикселей. Частичная прозрачность смешивается с фоном и затем квантуется.

Сохранение родной палитры PCX8 **использует render hooks** `0x47BE90`/`0x47E880`. Единственный владелец хуков и реестра — API. Для зарегистрированного кадра передаётся палитра удерживаемого исходного PCX; остальные кадры проходят существующую цепочку с переданной палитрой. Это совместимо с активной палитрой RGB565 и HD BGRA, но не превращает кадр DEF в 32-битный массив пикселей.

Ключ кэша включает имя, группу/кадр, размеры, режим и полную RGB888-палитру цели. Повторный запрос возвращает тот же handle. `output` обнуляется при ошибке. `capabilities` сообщает поддержку PCX8, ERA PNG, DEF и родной палитры PCX.

## Изменение таблицы атласа

`applyFrames(UpdateRequest*)` принимает **полную** результирующую таблицу группы. `FrameBinding.frame != 0` ссылается на созданный сервисом кадр. При `frame == 0` пара `sourceGroup/sourceFrame` заимствует исходный кадр того же DEF. Все ссылки разрешаются до изменения таблицы: перестановки и алиасы не зависят от порядка записей.

```cpp
std::vector<era_graphics::FrameBinding> bindings(target->groups[0]->count + 1);
for (int i = 0; i < target->groups[0]->count; ++i) bindings[i].sourceFrame = i;
bindings.back().frame = frame;
era_graphics::UpdateRequest update;
update.targetDef = target;
update.bindings = bindings.data();
update.count = static_cast<uint32_t>(bindings.size());
const int result = api->applyFrames(&update);
```

Буфер bindings и строки нужны только на время вызова. `structSize` должен быть не меньше размера v1; `bindingStride` позволяет читать расширенные записи. Уменьшение таблицы, нулевые/чужие handles, несовместимые размеры или палитра квантованного кадра отклоняются. Максимум — 65536 записей. Ошибка проверки или выделения памяти сохраняет прежнюю таблицу. При успехе обновляются `frames`, `count`, `spritesSize`, целевой DEF удерживается сервисом.

`Result`: `Ok=1`, `NotReady=0`, `InvalidArgument=-1`, `MissingResource=-2`, `UnsupportedFormat=-3`, `InvalidFrame=-4`, `OutOfMemory=-5`, `RecursiveSource=-6`. Это API для основного потока игры; одновременные вызовы из рабочих потоков не поддерживаются. Передавать произвольные адреса вместо действительных объектов движка нельзя.

## Время жизни и зависимости

Успешные handles, кадры, палитры исходных PCX и удержанные DEF живут до завершения процесса. Освобождение отдельного handle и выгрузка провайдера во время игры не поддерживаются: атлас может продолжать хранить указатель. Графические ресурсы не очищаются событиями выхода/загрузки карты, в отличие от map-local владельцев/replay в том же API.

Все три плагина обновляются согласованно. При отсутствующем/старом API расширители записывают понятное сообщение в лог. Расширитель артефактов не устанавливается: дополнительные ID без расширенного DEF небезопасны. Жилища продолжают работать с родным запасным кадром; новые картинки/расширение таблиц требуют Graphics API v1. Отдельные кэши кадров и палитровые хуки в потребителях удалены.

## Проверки

`Verification/BuildGraphics.cmd` собирает три проекта Release/Win32 локально и запускает тесты API и потребителей. `run-tests.cmd` проверяет production RLE, все 256 индексов, границы 256-пиксельных серий, палитру, отказ выделения таблицы, перестановки, ABI/версию/размеры и обращения до готовности графики.

`Verification/InstallGraphics.ps1` устанавливает согласованный комплект из трёх `.era`, PDB и DBGMap, сверяет хеши и сохраняет прежние файлы в `build/before-graphics-api` без перезаписи исходной резервной копии.

`Verification/VerifyGraphicsResources.ps1` запускает временный диагностический плагин в обычной игре и HD, используя probe жилищ. Требуются установленные актуальные API и артефакты, локальная сборка жилищ, MAP-файл и существующая PNG-подмена `test1.pcx` 44×44. Создаваемый PCX8 со всеми индексами и probe удаляются в `finally`; диагностический процесс завершается после проверок. Проверяются оба атласа, оба интерфейсных рендерера, fit/центрирование/прозрачность, PNG, кэш, самоссылки, неизвестный handle, атомарность обновления и сохранение графики после `OnGameLeft`. Логи: `Debug/Era/graphics-api-h3era.exe.log` и `graphics-api-h3era HD.exe.log`. Настройка NewTrue32 не меняется.

Проверено 20.10.2026: Release/Win32 и автономные тесты прошли; в обычной игре и HD — по 143 runtime-проверки. PCX8 (`artslot.pcx` и тест всех индексов 0–255) в обоих атласах/рендерерах дал 0 отличающихся пикселей. PNG совпал с ожидаемым переводом в палитру DEF. Без RMG — 74 проверки жилищ. Со старым API без графического экспорта — 9 проверок безопасного отказа; дополнительные ID артефактов не публикуются. Стартовый отладчик достиг главного меню с пятью созданными кадрами и без обращений к ошибке отсутствующего PCX. Комплект `.era`/PDB/DBGMap установлен, хеши сверены, временные ресурсы удалены. Полный игровой прогон карт/сохранений этим тестом не заменяется.
