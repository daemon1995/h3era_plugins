# Замена объектов по действующей геометрии, API v1

Новый ERM-конвейер работает с явными парами `type/subtype` из `wogify.objectReplacement.objects`, вместо таблиц `Y/RY/YR/RYR` и фиксированных поправок к координатам DEF. JSON определяет допустимые цели, частоты, веса, WoG-опции, ландшафт и дополнительные условия размещения. C++ проверяет конкретный экземпляр исходного объекта и конкретный графический вариант цели.

## Что делает v1

Внешние координаты всех методов — основная жёлтая клетка. Источник определяется через `objectDrawing → objectDetails → objectAttributes` текущей карты. Разные графические варианты одного `type/subtype` проверяются отдельно, в обратном порядке каталога, как у штатного селектора. Координата размещения вычисляется как `вход + column/row входа выбранного шаблона`.

После совмещения входов должны **полностью совпадать блокирующие клетки и все входы**. Размеры картинок и позиции входа внутри DEF могут различаться. Проверяются границы карты, допустимый ландшафт, подход к входу и перекрытие чужих входов видимой частью нового объекта. Нормализованные маски кэшируются по их значениям, а не по имени или указателю DEF; кэш очищается при выходе/загрузке карты.

Нативные маски имеют обратный порядок: клетка нижнего правого угла — бит 47, верхнего левого — бит 0. Для клетки `(column,row)` применяется бит `47 - row*8 - column`. Это проверено по `4FF280` и исходникам/коду WoG `712CEB`. Обычный вызов `H3ObjectMask(column,row)` из этого SDK не выполняет такой разворот.

Одинаковые `type/subtype` не означают одинаковые маски. Перед удалением исходного объекта выбранный прототип регистрируется и его DEF загружается штатным селектором. Во время самой замены селектор получает именно подготовленный шаблон, а WoG `FindEnterShift` — его оффсет входа. Обычные вызовы остальных скриптов проходят через исходные функции. Размещение идёт через WoG `71299E`, сохраняя инициализацию жилищ и банков и существующие хуки плагинов.

## Горячий путь вогификации

Удаление вызывает непосредственно WoG `DelObject(x,y,z)` по адресу `0x712B8A` (`__cdecl`). Это та же точка EXE, которую вызывает `UN:O x/y/z/0/0`: сохраняются нативные хуки и удаление через AdvManager, но больше нет форматирования команды, входа в ERM и разбора ресивера. При установке проверяется инструкция вызова из `UN:O` и очистка трёх аргументов вызывающей стороной; пролог общей функции не проверяется, поскольку его могут законно менять HiHook других плагинов.

`ObjectShapeCache.h` хранит неизменяемую геометрию и возвращает стабильный указатель. Попадание в кэш больше не копирует три вектора клеток. Ключ учитывает только используемые 48 бит каждой маски; невалидные формы тоже запоминаются. Сброс карты очищает кэш и меняет поколение; после нативной подготовки, удаления и размещения проверяется, что карта и её поколение прежние.

Ландшафт читается при разрешении источника один раз, а не для каждого варианта каталога. Неподходящие типы и подтипы отбрасываются до работы с геометрией. Временный выбор прототипа хранит до 16 конкурирующих вариантов в локальном буфере; больший набор использует дополнительный вектор. Изменение подтипов начинается только после полного сбора, поэтому отказ выделения памяти не оставляет испорченный каталог.

Штатная подготовка DEF и размещение `0x71299E` сохранены ради инициализации объектов и хуков ERA/IP. Сохранение `x1..x16` необходимо: эти хуки могут вызывать ERM. Вызов `FireErmEvent` в replay также нужен для явно зарегистрированных скриптовых событий; это не часть цикла замены.

## Ограничения первого этапа

- Разные блокировки или наборы входов отклоняются. Режим изменения геометрии с проверкой связности проходов ещё не реализован. Старое заполнение клеток брёвнами для дворца/академии удалено; несовместимая замена оставляет исходную утопию.
- Сетевой режим отклоняется: штатный пакет ERA не передаёт выбранный вариант DEF. Обычные правила остальных частей вогификации сохраняются. Для сетевого этапа нужен отдельный протокол передачи шаблона; неподтверждённый локальный выбор здесь не применяется.
- Объекты под героями, объекты без основного входа и геометрия вне штатной маски 8×6 не заменяются. Новая привязка должна помещаться в нативные байтовые координаты 0–255. Формат расширенных координат больших карт требует отдельной интеграции.
- Совместимость сторонних хуков, самостоятельно изменяющих геометрию после нативного размещения, требует игровой проверки. Возвращаемый результат проверяется после размещения; API не обещает откат произвольных изменений стороннего плагина или аварии нативного движка.

## Экспорты

Все методы `__stdcall`, имена недекорированы. Заголовок — `headers/EraPluginsAPI/ErmFunctionsAPI.h`. ERM может получать адрес через `SN:A` и вызывать `SN:E` с `CALLCONV_STDCALL`, включая ERA до появления `SN:F^Plugin:Export^`.

| Метод | Аргументы | Результат |
| --- | --- | --- |
| `Erm_GetObjectReplacementApiVersion` | нет | 1 после успешной установки проверенных хуков, иначе 0 |
| `Erm_GetObjectGeometry` | x, y, z, int* output, capacity | 1: записаны 15 целых; иначе 0 |
| `Erm_FindObjectReplacement` | x, y, z, type, subtype, terrain, approachMask | непрозрачный положительный токен подходящего варианта; 0 — нет подходящего |
| `Erm_ReplaceObject` | те же аргументы и prototype token | 1 — объект размещён, вход и геометрия проверены; иначе 0 |

Токен действует в каталоге текущей карты. Перед применением все условия проверяются заново. `terrain=-1` убирает ограничение конкретным ландшафтом, но маска допустимых ландшафтов шаблона всё равно учитывается. `approachMask` — восемь бит по часовой стрелке: N, NE, E, SE, S, SW, W, NW. `255` разрешает все направления; `124` разрешает E/SE/S/SW/W для потерянной бутылки.

`GetObjectGeometry` пишет: `[type, subtype, originX, originY, level, width, height, entranceColumn, entranceRow, blockedLow32, blockedHigh32, entrancesLow32, entrancesHigh32, attributesIndex, detailsIndex]`. Маски возвращаются в нативном порядке битов; учитываются только младшие 48 бит. Буфер принадлежит вызывающему скрипту и должен быть доступен на запись.

## JSON и ERM

Раздел `wogify.objectReplacement.objects.order` содержит порядок числовых ID наборов правил. Каждый набор содержит:

- `requiresReplaceObjects`: учитывать опцию 195; для замены ульев по опции 165 — 0;
- `preserveLast`: число исходных экземпляров, оставляемых нетронутыми; 1 сохраняет прежнее ограничение количества;
- `sources`: записи `type`, `subtype` (`-1` — любой), `chance`, `scaleChance` (учитывать `wog_195_objReplaceMult`); дополнительно `requiredTerrain`, `excludeWater`;
- `targets`: записи `type`, `subtype`, `weight`, `terrain`; дополнительно `optionId`, `disabledByOption`, `skipOnRmg`, `requiredVariable`, `approachMask`, `requiredBlockedOffsets`.

`requiredBlockedOffsets` — массив `[dx,dy]` относительно сохранённого входа: там должны быть заблокированные клетки, не вода. Так прежние требования задней стены выражены явными координатами, без категорий размеров. Мод может изменить или удалить эти условия для своих вариантов графики.

Вероятность бросается для исходного экземпляра один раз. Затем выбирается цель с учётом веса только среди подходящих кандидатов. Позиции источников фиксируются до замены; новые объекты не попадают в текущий цикл. Инициализация мельницы/костра/обычного сундука/золота/хижины использует сохранённый вход, без поправки `x-1`. Специальные сундуки и рыбацкие колодцы, включая предварительно размещённые, перебираются в `WOG_IFY_Objects_InitSpecialChests` внутренними циклами с локальными координатами. Они передаются в именованные функции соседних скриптов: `WOG_29_InitChestContents`, `WOG_31_InitChestContents`, `WOG_107_InitWellContents`. В самих соседних файлах сохранены входы 5211 для исходного wogify; в merged числовых функций и вызовов FU/DO нет.

Все шесть обходов карты в merged используют экспорт ERA `FindNextObject` через `SN:F` с локальными x/y/z и выходом по флагу успеха в v1. Предварительного подсчёта через `UN:U` нет. Для источников геометрической замены сначала собираются все координаты, затем из числа записей вычитается `preserveLast`; этот снимок защищает от включения новых объектов в текущую итерацию. Направления обхода сохранены: источники, банки и свитки — вперёд (`Direction=-1`, начальный x=-1); артефакты, монстры и специальные сундуки — назад (`Direction=-2`, начальный x=-2). Начальные значения соответствуют реализации WoG `FindNextObjects`, которую вызывает экспорт ERA.

Из исходного `merged` перенесены 16 наборов, 44 правила источников и 67 записей целей. Настройки артефактов в ключе `5` и раздел `RMG` сохранены. JSON-читатели переименованы в общие `WOG_IFY_ReadInt`/`WOG_IFY_ReadIds`, поскольку теперь используются обеими подсистемами.

## Проверка

`Verification/run-object-replacement-hooks-tests.cmd "D:\games\HoMM 3 ERA\patcher_x86.dll"` запускается из x86 Visual Studio Developer Command Prompt. Тест включает настоящий `ObjectReplacement.cpp`, устанавливает `FindEntranceShift` через загруженную `patcher_x86.dll` и проверяет ESP/EBP, передачу параметров и результат штатного вызова, выбранный прототип, посторонний объект во время выбора и 1000 повторных вызовов. Дополнительно 1000 вызовов моста удаления проверяют координаты и сохранность ESP/EBP через тестовую cdecl-функцию; сброс карты во время удаления очищает кэш и увеличивает поколение. Это проверка ABI моста, не запуск удаления внутри игрового EXE. Для временного возвращения старого `__stdcall` тест падает с `frame changed=1`; с `__cdecl` проходит.

Исправление от 15.10.2026: callback хука `CDECL_` на `0x712CEB` обязан сам использовать `__cdecl`. При прежнем `__stdcall` повреждался EBP вызывающего кода. В дампе опции «Гарнизоны» это приводило к записи через неверный адрес на `0x713B91` после `UN:I18/12/0/33/0/33/0/-1/0`. Тот же дефект исправлен в `Objects_CreatureBanksExtender::WoG_PlaceObject` на `0x7133E2`. Экспортируемые методы API сохраняют свой `__stdcall`.

`Verification/ObjectGeometry.tests.cpp` исполняет настоящий общий код: порядок битов, все 48 оффсетов входа, разные позиции привязки при одинаковой геометрии, несовпадающие маски, границы, чужие входы, направления подхода и восстановление временного выбора прототипа при исключении.

`run-tests.cmd` дополнительно выполняет `ObjectReplacementAllocation.tests.cpp`: нулевые выделения на 10 000 попаданий в кэш, стабильность указателей, нормализация масок, невалидная геометрия, отказ памяти, восстановление 0–63 конкурентов и полная проверка JSON с маленьким буфером. `Verification/verify_object_replacement_native.py` принимает пути к EXE и проверяет 13 участков нативного кода; прошёл на локальных `h3era.exe` и `h3era HD.exe`.

Число обращений к кэшу выбрано как `252*252*2*12` для нагрузки стенда. Это не измеренное количество вызовов на реальной карте и не ускорение всей вогификации. Время удаления через EXE и итоговая длительность в игре не измерялись. Исходники стенда, CSV и резервные копии: `D:/updates/wogify_native_optimization`.

Скрипт подготовки в `D:/updates/wogify_geometry_migration` содержит резервные копии ERM/JSON, перенос правил, 12 проверок выполнения нового ERM-текста на эмуляции приёмников и проверку нативных инструкций двух установленных EXE. Такая эмуляция не заменяет компиляцию и запуск ERM в игре.

Игровая проверка ещё не выполнена: нужны новая карта с несколькими источниками одного вида, два DEF одного `type/subtype` с разными входами, несовместимая маска, берега/края карты, потерянная бутылка и проверка содержимого новых жилищ/банков/сундуков. После установки DLL требуется перезапуск игры. Сохранение/загрузка должны сохранять выбранный шаблон через штатные структуры карты.
