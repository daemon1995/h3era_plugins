# Combat_SwitchingCreatureAction

Нажатие ALT или кнопки переключает доступные действия по кругу. Удержание клавиши
не вызывает повторных переключений. Кадр кнопки — **следующее** действие (`ID * 3`),
а выбранный режим хранится отдельно для каждого стека до конца битвы. При одном
доступном действии переключатель скрыт.

После выбора обновляются сетка и поле боя, сбрасывается сохранённая клетка курсора
и вызывается штатная постановка сообщения движения мыши (`0x4ECCD0`). Во время
действия, автобоя и чужого хода переключение и дополнительные перерисовки запрещены.

Меню ALT + цифра сохранено отдельно в `HeldAltMenu.cpp`, методе
`SwitcherDlgPanel::HandleHeldAltMenu`. Основная процедура боя его не вызывает.

Пара «колдовать на точку / шагать» добавляется, когда найдена пустая клетка
с подходящим союзным трупом, на которую существо может применить способность
и физически переместиться на текущем ходу. Доступность перемещения проверяет
штатный курсор/поиск пути с временно отключённым колдовством. Целевые поля стека
после этой проверки восстанавливаются. Заклинания по живым целям проверяются отдельно.

Вызов игрового расчёта курсора сохраняет EBX/ESI/EDI явно. Это совместимость с
фиксом шага назад `game bug fixes extended` в `0x476020`: при наведении на собственный
отряд он снимает сохранённые значения регистров со стека, но не восстанавливает
EDI/ESI. Защита применяется и в обработчике курсора, и при проверке доступности клетки.

## ERM API

```erm
!?FU(OnStartOrLoad);
!!SN:F^Combat_SwitchingCreatureAction:SetOnBattleStackActionDetermination^/(OnBattleStackActionDetermination);
```

Экспорт `BOOL __stdcall SetOnBattleStackActionDetermination(INT functionId)`
регистрирует один обработчик; `0` отключает его. Возвращает `1` при успехе,
`0` для отрицательного ID. Регистрацию повторяют при старте/загрузке карты.

Обработчик вызывается после штатного определения действий при получении управления
стеком и при пересчёте после завершившегося действия. В автобою, во время анимации
и на обычных сообщениях окна вызова нет.

| Параметр | Значение |
| --- | --- |
| `x1` | ID стека `side * 21 + sideIndex`, 0–41; ID сохраняется при гипнозе |
| `x2` | ID текущего героя владельца, с учётом гипноза; `-1` без героя |
| `x3` | Число доступных действий, 0–7; изменяемый параметр |
| `x4..x10` | Массив из семи ID действий; используется первые `x3` элементов |

```erm
!?FU(OnBattleStackActionDetermination);
!#VA(stackId:x) (heroId:x) (actionCount:x) (actions[7]:x);
; Индексы массива: actions[0]..actions[6].
```

| ID | Действие |
| --- | --- |
| 1 | Рукопашная атака |
| 2 | Выстрел |
| 3 | Колдовство существа |
| 4 | Перемещение без воскрешения |
| 5 | Атака с возвращением |
| 6 | Атака без возвращения |
| 7 | Выстрел по площади |

ERM может убрать действия или изменить их порядок. Неизвестные, недоступные
и повторяющиеся ID отбрасываются. Число вне 0–7 отменяет изменения обработчика.
Это настройка переключателя: ERM не выдаёт существу новые способности и не обходит
штатные ограничения целей. Значения входных и выходных `x1..x16` внешнего вызова
сохраняются и восстанавливаются вокруг обработчика.

Рабочий пример с журналированием и именованным массивом — `BattleStackActions.erm`.
