# XXL

Плагин перенесён из `JackSlater/XXL` в `H3EraPlugins.sln`. Использует общий
`../headers/header.h`, H3API, ERA и настройки сборки этого решения.
Оставлены работавшие в исходном плагине хуки размеров карт; отключённые
экспериментальные обработчики не подключаются.

Миникарта без HD Mod: `Minimap.cpp` дополняет штатную `0x412BA0` для H/XH/G.
В исходной игре переключатели шага строки и записи пикселей поддерживают только
36/72/108/144: на 180/216/252 цвет вычисляется, но пиксели не записываются.
Штатная рамка также выбирается как для XL и получает масштаб 1. Обработчики
мыши используют тот же неподходящий масштаб. XXL ранее менял выбор размера
карты, но не эти участки рисования и ввода.

Хук `0x4130DF` переносит уже вычисленный игрой цвет в координаты миникарты
пропорционально размеру карты, используя фактический шаг строки экрана.
Туман войны, владельцы и обработчики цветов других плагинов остаются в штатной
цепочке. При уменьшении несколько клеток попадают в один пиксель; остаётся цвет
последней клетки в порядке обхода.

Установленный `Mods/WoG/Data/radar.def` имеет 29 кадров и холст 144×144.
Он отличается от штатного DEF из `H3sprite.lod` (14 кадров, холст 148×132):
игра ожидает кадры XL/L/M/S под номерами 1/2/3/4, а XXL-файл содержит S–G
под номерами 1–7. Смещения спрайтов являются частью кадра, а не координатами
миникарты. Полное декодирование RLE строк прошло без ошибок; используются
индексы палитры 0 (прозрачность) и 2 (пунктирная рамка).

| Карта | Кадр XXL | Размер спрайта | Смещение |
| --- | --- | --- | --- |
| S | 1 | 76×68 | 0,0 |
| M | 2 | 38×34 | 0,0 |
| L | 3 | 25×23 | 1,0 |
| XL | 4 | 19×17 | 0,0 |
| H | 5 | 15×13 | 1,1 |
| XH | 6 | 13×11 | 1,1 |
| G | 7 | 11×9 | 1,1 |

«Обзор мира»: кадры 8–14 для масштаба 16, 15–21 для 11.84,
22–28 для 7.68. Пустые 15/22/23 соответствуют режимам, где карта помещается
целиком. Хук `0x41336E` распознаёт этот набор по числу кадров и геометрии,
выбирает подходящий кадр и задаёт масштаб координат. Готовые рамки XXL
не уменьшаются повторно: штриховку, палитру, смещения и обрезку у краёв
рисует штатная функция. При обычном 14-кадровом DEF карты S–XL сохраняют
исходный выбор кадров, а для больших карт применяется уменьшение рамки XL.
Сам DEF не изменяется.

Хук `0x40A0AD` задаёт правильный делитель координат для клика и всего цикла
перетаскивания миникарты; `0x5FCCA4` исправляет делитель в «Обзоре мира».
Округление делителя вверх компенсируется на один шаг float, чтобы штатное
x87-усечение не смещало точные границы пикселей на одну клетку назад.
Изменения ввода выполняются только для больших карт без загруженного HD_WOG.
HD_WOG заменяет вход `0x412BA0`, поэтому его собственное рисование не проходит
через хуки пикселей и рамки XXL.

Инструкции всей `0x412BA0` сверены с локальными `h3era.exe` и `h3era HD.exe`
(SHA-256 `451E208CB2985BCA75330F0E3C52F89F9219C0C3701BC6E1F354217890C36181`
и `CA47B6406FB064AECACFD4620C3A0DE190A4A37D97A313D66E1F9AAF95A9D594`):
расхождений с IDA-экспортом нет. Проверка `verification/RadarChecks.cpp`
читает метаданные обоих настоящих DEF и проверяет все размеры и режимы
обзора, пустые кадры, покрытие 144×144 для H/XH/G и сохранность окружения
буфера с нестандартным шагом строки.
`RadarNativeChecks.h` исполняет извлечённые инструкции локального EXE с настоящим
`patcher_x86` и штатным x87-преобразованием: воспроизводит старую ошибку G,
проверяет клик и перетаскивание во всех 144 позициях на семи размерах карт,
а также штатный расчёт кадра, положения и обрезки рамки. Вызов графического
вывода в этой проверке заменён записью параметров; визуальная проверка
в игре и совместная работа с загруженным HD Mod остаются необходимыми.

Совместимость диалога ГСК с HD Mod реализована отдельно в
`HdTemplateCompatibility.cpp`. При первом создании настроек случайной карты
модуль ищет уникальные сигнатуры в исполняемых секциях уже загруженного
`HD_WOG.dll`. Проверяются таблица нормализации, эпилоги, вызовы преобразования
размера в ID кнопки, границы глобальных данных и отсутствие чужих патчей в
точках HD. Все патчи создаются после проверок и применяются одним набором;
при отказе любой операции созданные патчи откатываются и уничтожаются.
Результат подключения записывается через `Era::WriteLog` в журнал ERA.
Неизвестная версия HD не получает частично установленной совместимости.

Исправляются ограничение 144→252, нормализация площадей до H/XH/G и их
подземных вариантов, ID кнопок 3003/3004/3005 и обновление диалога HD.
Активный `rmg.txt` читается через ресурсный менеджер игры. Каждый именованный
блок добавляет собственный диапазон допустимых размеров: промежутки между
блоками не заполняются. Поверхность и подземелье проверяются отдельно.
Для островов диапазон удваивается так же, как в нормализаторе HD; случайная
вода допускает обычный и островной варианты. Число игроков и прочие условия
шаблона по-прежнему проверяет HD: этот модуль не реализует их собственный разбор.

После обработки нажатия и проверки шаблона HD модуль обновляет доступность
S–G. Размер остаётся доступен, если подходит хотя бы одно число уровней;
переключатель подземелья разрешён, только если другой вариант допустим для
выбранного размера. При недопустимой комбинации сначала сохраняется размер,
если для него есть другое число уровней; иначе выбирается ближайший размер
с текущим числом уровней, затем с альтернативным. Переключение выполняется
штатными сообщениями диалога, без прямой подмены полей генератора. На время
этой короткой транзакции вложенная проверка HD откладывается, чтобы не отменить
промежуточную комбинацию. Пустой набор разрешённых размеров блокирует запуск.
Изменения доступности и выделения кнопок запоминаются до вызова обработчика
HD, включая изменения при предварительной коррекции. Завершающая перерисовка
выполняется при возврате в основной диалог, после восстановления фона закрытого
HD-дропдауна. Она работает и для сообщения кастомного виджета, не являющегося
обычным кликом. Перерисовываются только изменившиеся видимые кнопки; очередь
очищается после вывода и при закрытии диалога.
Локально и на сетевом хосте ограничения применяются; гостю модуль не меняет
параметры. Без HD или при неподтверждённых сигнатурах этот слой не активен.
Список шаблонов HD и сохранение их индексов не изменяются.

Проверено с локальной `HD_WOG.dll`, SHA-256
`AB601899F1862C7283C57A28101428FDF3040FE69B628C3620D418AA8FDA84A1`.
Найденные RVA: нормализатор `0xA2190`, преобразователь размера `0xA27D0`,
обновление диалога `0xA27F0`; в рабочем коде эти RVA не зашиты.
`verification/HdChecks.cpp` выполняет 141 проверку: загружает PE-образ без
вызова DllMain HD, исполняет его настоящие нормализатор и преобразователь до
и после хуков `patcher_x86`, проверяет сигнатуры, отказы без частичной записи,
откат набора патчей, реальные файлы шаблонов, маски уровней/воды, переключение
через сообщения, запрет отключённых кнопок и права хоста/гостя. Отдельная
регрессия воспроизводит кастомный виджет HD: обновление из вложенного диалога,
восстановление его сохранённого фона и вывод окончательных состояний после
возврата. Повторные сообщения без изменений не вызывают перерисовку.
В этой проверке графические элементы, загрузка таблицы и исходный обработчик
обновления диалога заменены локальными заглушками. Живая проверка с HD Mod
не выполнена: нужно сменить шаблоны, воду и подземелье, выбрать H/XH/G,
запустить карту и повторно открыть диалог.

Для новой **случайной или обычной карты** в дополнительных параметрах можно выбрать город,
а затем стартового героя ИИ обычными стрелками возле портрета. Герои, уже
выбранные другим игроком, пропускаются. Выбор передаётся загрузчику карты,
а не только отображается в диалоге. При случайном городе герой остаётся случайным.
На обычных картах учитываются ограничения автора: нельзя заменить фиксированного
героя; запрещённые и уже размещённые герои исключаются штатным списком игры.
При фиксированной фракции её тип берётся из маски доступных городов карты.

После успешного запуска случайной карты сохраняются только город, ID героя и бонус каждого цвета.
Параметрами генерации и таймерами занимается HD-мод; XXL их не сохраняет и
не восстанавливает. Прежняя секция `[RandomMap]` в INI игнорируется.
При открытии случайной карты в новом диалоге параметры выбора игроков
восстанавливаются один раз, поэтому последующие изменения пользователя не
перезаписываются. Запрещённые города, недоступные и повторяющиеся герои
не восстанавливаются. Неудачный запуск не заменяет настройки предыдущей игры.

Настройки хранятся в `Runtime/PluginSettings/MapSelection.ini` через Era API:
`ReadStrFromIni`, `WriteStrToIni` и `SaveIni`. Сохранение включено по умолчанию.
Чтобы отключить сохранение и восстановление, установите:

```ini
[XXL]
RememberSettings=0
```

Для сброса настроек удалите `Runtime/PluginSettings/MapSelection.ini`.
Предыдущий выбор не сохраняется и не
восстанавливается для обычных карт и сетевых партий. Кампании и загрузка
сохранений используют прежнее поведение.

В сетевой игре героев ИИ выбирает хост. Гости видят выбранных героев, но не
могут изменять их; пересланные гостем нажатия на стрелки ИИ также отклоняются.
Поддерживаются обычные и случайные карты, с теми же ограничениями автора карты.
Для сетевой игры установите одинаковую версию XXL у всех участников.
Синхронизация использует штатное сообщение `1039` длиной 2004 байта: заголовок
20 байт, 8 слотов людей и 8 слотов ИИ по 124 байта. После изменения хост
отправляет полное состояние через `NetworkSendData4(0x554950)` с теми же
флагами сжатия и доставки, что и штатный диалог дополнительных параметров.
Клиент получает слоты ИИ в `0x58BDCF..0x58BDE7`; отдельного формата пакетов нет.
Новая игра создаётся хостом, а гости загружают переданное им состояние через
штатный сетевой путь `0x589DF0`. Локальный INI в сетевой партии не применяется.

Из `HotAPatcher.exe` извлечён AutoIt-скрипт и разобран его машинный код:
сохранение города/ID героя/бонуса по цвету и восстановление ID через актуальный
список героев. Адреса HotA и запись патча в EXE не переносились. Новые места
хуков сверены с локальными `h3era.exe` и `h3era HD.exe`.

Цепочка выбора стартового героя:

| Данные | Адрес/смещение | Назначение |
| --- | --- | --- |
| Слоты людей / ИИ | Диалог + `0x1064` / `0x1444` | `selectedHeroIndex` + `heroes[]`; поиск слота человека по `player2` (цвет) |
| `startingHeroOfPlayer[8]` | `0x69FB80` | ID героев по цветам; передаётся в `LoadScenario(0x4C01E0)` и `GameMgr::StartNewGame(0x4BFB30)` |
| `playersInfo.heroMaybe[8]` | `H3Main + 0x1F844` | Выбранный стартовый герой игрока |
| `heroOwner[156]` | `H3Main + 0x4DF18` | Резервирование героя, исключающее его из случайного выбора других игроков |

Одного заполнения `0x69FB80` недостаточно. В `0x4BFC27` игра проверяет
`player.isHuman` перед резервированием выбранного героя и записью в
`heroMaybe`. В `LoadMap_CreateTownRandHeroes(0x4C9D00)` повторная проверка
человека в `0x4C9E03` заставляет ИИ игнорировать переданный массив и выбирать
случайного героя. XXL обходит обе проверки только во время запуска новой
случайной или обычной карты локально либо на хосте сетевой партии.
Остальные проверки, включая `-1` для случайного
героя, выполняет штатный код. Для случайного героя, размещённого на карте,
`0x50293D` читает `startingHeroOfPlayer[color]`, а `0x50294A` сбрасывает
использованную ячейку в `-1`.

Сборка: `XXL.vcxproj`, `Release|Win32`, локальный toolset `v141_xp`.
Результат — `XXL.era`, PDB и штатные MAP/DBGMAP. Для установки замените
`Mods/WoG/EraPlugins/XXL.era` при закрытой игре. Требуются графические ресурсы
размеров карт и переводы установленного XXL; они уже присутствуют в локальном WoG.

Проверки логики выполняются отдельной локальной программой из игнорируемого
каталога `verification/`: ABI, выбор героев людей/ИИ, конфликты, восстановление,
недопустимые настройки, INI и успешный/неудачный запуск. Отдельная регрессия
исполняет фрагменты машинного кода из локального EXE с настоящим `patcher_x86`:
без исправления выбранный герой ИИ игнорируется, с обоими хуками резервируется
и используется; случайный выбор и поведение человека сохраняются.
Формат сетевого сообщения и роль хоста/гостя проверяются отдельно, а перенос
слотов ИИ на клиента выполняется извлечённым из EXE штатным машинным кодом.
Проверка непосредственно в игре, включая живую сетевую партию, остаётся
необходимой: выбрать героя ИИ, запустить карту, проверить героя
на карте, затем открыть новую игру после перезапуска и сверить параметры.
