# Фазы подготовки карты WoG

Координатор — `WOG_IFY_Begin` в `78 wog - wogify_merged.erm`, тело фаз — `WOG_IFY_RunPreparationPhases`. Пользователь перенёс автоматический вызов на `OnAfterErmInited`; исправление звука сохраняет эту точку вызова. ОХ, общий диалог и передача готовой карты в эту работу не входят.

| Фаза | Действия |
| --- | --- |
| 1 — options | Выбор правил карты и плотности гарнизонов; размещения ещё нет. |
| 2 — replacements | Нейтральные жилища, применение правил, сброс интервалов мифрила, общий обход объектов, геометрические замены, артефакты, монстры и свитки. |
| 3 — rule_objects | Размещение знамён из правил карты. |
| 4 — garrisons | Сбор и распределение гарнизонов по секторам, повторная проверка мест, размещение и заполнение войсками. |
| 5 — special_terrain | Генерация почв после всех блокирующих объектов, отдельно для поверхности и подземелья. Количество попыток передаёт ERM. |
| 6 — finalization | Обновление квестов и итоговая перерисовка. |
| 7 — completed | `wog_wogification_completed = TRUE`. |

Перенесённые процедуры больше не вызываются независимо из старых стартовых обработчиков. Повседневные правила и еженедельный рост гарнизонов сохранены. Обычные сетевые вызовы `P/D` правил сохранены. `wog_ify_phase` сохраняет последнюю начатую фазу; строки `WoGify / Phase` записываются в ERA log. Повторный вход после начавшейся, но не завершённой подготовки запрещён. Отрицательный результат геометрической замены или генерации почв прерывает подготовку без признака завершения.

На время ранней подготовки в `OnAfterErmInited` `WOG_IFY_Begin` сохраняет пять байтов `0x4AA9C4` и ставит `E9 87 00 00 00` — переход к эпилогу `0x4AAA50`. Удаление и обновление клеток выполнены до этой точки; пропускаются формирование пакета удаления `0x422`, вызов его отправки `0x481CB0` и обновление фоновых звуков. Пропуск действует и в multiplayer: штатный первоначальный `TransmitSaveGame` после возврата из `NewMap` передаёт итоговую карту.

В установленной ERA 3.9.31 дополнительно меняется только `JE +0x3D` на `JMP +0x3D` по `era.dll + RVA 0x71625`. Символ `Tweaks.Hook_ZvsPlaceMapObject` начинается с RVA `0x7160C`; цель перехода `0x71664` продолжает обычное локальное размещение. Пропускаются заполнение параметров и отправка `OnRemoteCreateAdvMapObject`, а не общий обработчик удалённых событий. База DLL получается через `GetModuleHandleA`; размер образа и сигнатуры проверяются до применения всех патчей. Для страницы кода DLL используется `VirtualProtect`, после записи — `FlushInstructionCache`.

Звуковой пропуск по `0x4AA9EF` сохраняет совместимость с вложенной защитой общего обхода. Внешняя функция восстанавливает все исходные байты и защиту страницы после возврата тела фаз, в том числе после его досрочного `FU:E`. Неизвестные сигнатуры отменяют подготовку до изменения кода. В логе — `WoGify / Preparation send guard`, начало и восстановление. C++ и DLL плагина этим исправлением не меняются.

После вылета 29.10.2026 в 10:46:02 добавлен пропуск `EB 0E` по `0x7133C7 → 0x7133D7` на то же время фаз. Внутренний helper WoG после создания монстра принудительно отрисовывал Adventure Manager, несмотря на `UN:I ... /0`; ранняя отрисовка рамки `agemul.def` обращалась к неготовому DEF. Пропускается только подготовка/вызов отрисовки, с сохранением предшествующего `setupAdjacentMons(0x4CA0D0)`, локального создания и штатного эпилога. Дополнительные байты также проверяются и восстанавливаются внешней обёрткой.

Причина исправления: вылет 29.10.2026 в 08:56:12 при `UN:O` из замены артефакта `(11,35,1)`. Удаление вызвало `0x418330`, где `0x418375` читает `[ecx+0x1C]` при `ecx=0`: активный индекс фонового звука ещё существует, а указатель WAV отсутствует. Это обновление выполняется и при флаге перерисовки 0. Контракты хвоста удаления и переход к эпилогу проверены в локальных `h3era.exe` и `h3era HD.exe`; повторный игровой запуск нужен для подтверждения исправления.

## Общий API почв городов и героев

`Erm_PlaceSpecialTerrain(x, y, z, type)`, `__stdcall`, недекорированный экспорт. Координаты — нижний правый угол DEF, как у генератора почв. Возврат: `1` — поставлено, `0` — отказ без размещения, `-1` — ошибка нативной операции или смена карты; продолжать пакет после `-1` нельзя. Подготовка шаблона может заполнить штатный кэш DEF и при возврате `0`.

Используется штатный селектор шаблона данного типа и подтипа 0. Принимаются только наземные специальные почвы с `flat`, полностью проходимой маской и без входов. Проверяются полный размер DEF, границы, ландшафт и отсутствие другой специальной почвы на всей площади. После нативного размещения проверяются экземпляр и рисунки всех клеток; только затем новый рисунок перемещается в начало каждого списка отрисовки. Проходимость соседних объектов вручную не изменяется.

Потребитель `Erm_PlaceSpecialTerrain` — `WOG_36_UpgradeTown`. Улучшение города размещает один целый проверенный DEF вместо двух старых перекрывающихся копий; мифрил списывается только при результате `1`. При отсутствии API оплата не производится. Интервалы замены ресурсов мифрилом сбрасываются в том же пространстве `wog_36_*_interval`, которое читает обход; рассчитанный `wog_170_*_maxStep` больше не обнуляется.

`Erm_PlaceSmallestSpecialTerrain(x, y, z, type)` принимает центральную клетку. `WOG_101_PlaceMagicPlains` передаёт координаты героя без смещения; правило продолжает действовать со второго дня на обоих уровнях карты. API перебирает каталог DEF с атрибутами, загружает их штатным селектором и выбирает подходящий шаблон с минимальной площадью. Для магической почвы рассматриваются оба штатных типа `MAGIC_PLAINS1` (46) и `MAGIC_PLAINS2` (230), для проклятой — 21 и 223; фактический тип выбранного DEF сохраняется. При равной площади предпочтителен более компактный прямоугольник, затем порядок определяется размерами, типом и именем DEF. Для чётного размера герой может занимать любую из двух центральных клеток; у границы нечётный шаблон не сдвигается от центра. Действуют те же проверки проходимости, ландшафта, перекрытий и порядка отрисовки, что описаны выше; возвраты `1/0/-1` имеют тот же смысл.

Новый API выполняет только локальное размещение. Ежедневный ERM-вызов сохраняет существующую репликацию `P/D`, предварительно сортируя список героев по ID. В сетевой игре на время единственного нативного размещения сохраняется и обнуляется собственный флаг ERA, управляющий отправкой `OnRemoteCreateAdvMapObject`, затем восстанавливается. Это исключает повторное создание через второй канал, который не передаёт точный DEF. Расположение флага проверяется по сигнатурам установленной ERA 3.9.31 (RVA `0xB0008`, обращение `0x7161E`); неизвестная реализация вызывает отказ до размещения с записью в лог. Сетевое поведение требует проверки на двух процессах.

## Сетевое ограничение текущей реализации

Геометрическая замена, генератор почв и прежний `Erm_PlaceSpecialTerrain` пока сохраняют запрет multiplayer. Исключение — описанный выше локальный `Erm_PlaceSmallestSpecialTerrain` с репликацией через вызывающий ERM-код. Штатный `Hook_ZvsPlaceMapObject` из локальных исходников ERA 3.9.16 (`tweaks.pas`) передаёт координаты, типы/подтипы и terrain; выбранный DEF и порядок отрисовки не передаёт. Это ограничивает замену во время партии, но не означает обязательность отдельного протокола DEF при раннем создании новой карты: `OnAfterErmInited` выполняется внутри `NewMap`, а штатный начальный `TransmitSaveGame` вызывается после возврата из `NewMap`. Он сохраняет и отправляет текущее полное состояние, включая конкретные шаблоны и порядок объектов на клетках. Клиент принимает и загружает сохранение; PI при загрузке пропускается.

ERM-обёртка теперь подавляет оба объектных канала на время ранней подготовки: штатный хвост удаления и отправку размещения установленной ERA 3.9.31. Вызовы `FU:D` она не подавляет. Прежний предложенный патч C++ отклонён автоматической проверкой и не включён. Контекст ранней подготовки в API v1 пока не реализован, поэтому ограничения самого API сохранены; нужна проверка на двух процессах. Для поздних замен нужен механизм передачи выбранного шаблона или эквивалентная синхронизация состояния.

В `WOG_IFY_MapRulesPhase` удалено внешнее условие `timerOnce`: координатор уже вызывает фазу один раз, а Framework заполняет переменные таймера только в `OnEveryDay`. Остальные зависимости одноразовых фаз от `timerOwner` требуют отдельной адаптации к раннему старту.

Проверочная сборка и статические проверки не заменяют игровой запуск, особенно для хуков сторонних модов. DLL не устанавливается в игру.
