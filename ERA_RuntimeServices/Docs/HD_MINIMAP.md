# Совместимость с мини-картой HD_WOG

В исследованном `D:/games/HoMM 3 ERA/HD_WOG.dll` штатная функция мини-карты `0x412BA0` заменяется обработчиком с RVA `0x628C0`. Поэтому LoHook плагина в EXE на `0x412F33` не вызывается при работе этого HD-рисования.

Исследованный файл: SHA-256 `90a645471f1ba50150dd9a76d7f27218aa53638b52e4a7b79e8c09d7fe3ecd3e`, preferred ImageBase `0x10000000`, SizeOfImage `0x2B1000`. Все адреса HD ниже — **RVA от фактического адреса загрузки DLL**.

## Связанные хуки HD

Регистрация группы находится около RVA `0x84297..0x84346`: видны адреса EXE, указатели обработчиков внутри DLL и вызовы через интерфейс патчера.

| Адрес EXE | RVA обработчика HD | Действие |
|---|---|---|
| `0x412BA0` | `0x628C0` | Замена рисования мини-карты целиком; отдельные ветки 16/32 бит |
| `0x40A077` | `0x62420` | Расчёт масштаба из высоты карты; продолжение на `0x40A0AD` |
| `0x5FD156` | `0x62450` | Такой же расчёт для другого вызывающего контекста; продолжение на `0x5FD187` |
| `0x5FCCD6` | `0x623E0` | Подстановка размера `144` в контекст View World |
| `0x5FCCEE` | `0x62400` | Подстановка второго размера `144` в контекст View World |

`0x628C0` проверяет диалог менеджера приключений, а затем выбирает формат по байту игры на `0x5FA22B`: сдвиг на 3 даёт 16 или 32. Ветки находятся в одной функции и имеют разные смещения локальных переменных. Размер мини-карты читается из текущего элемента диалога, а не принимается равным 144.

## Точки подключения плагина

| Режим | Вход в выбор цвета объекта | Указатель клетки | Цвет маркера | Продолжение |
|---|---|---|---|---|
| 16 бит | RVA `0x63025` | `[EBP-0x84]` | word `[EBP-0x58]` | RVA `0x6324C` |
| 32 бита | RVA `0x64301` | `[EBP-0x88]` | word `[EBP-0x48]` | RVA `0x64522` |

Обе точки находятся после проверки видимости и выбора цвета героя/выбранного героя. Оригинальные инструкции в этих местах вызывают `GetRealObjectTypeOfMapItem` по адресу `0x4FD220`, затем выбирают обычную ветку объекта.

Плагин проверяет регистрацию типа/подтипа и `drawOnMinimap`, получает вход из реально рисуемого DEF и читает владельца через общий кэш API. Цвет наносится только на клетки самого объекта: реальный тип клетки должен совпадать с типом DEF, а клетка должна быть недоступна для копания (`mirror & 0x40 == 0`) либо быть входом (`access & 0x10 != 0`). Это соответствует штатной проверке шахты в HD на RVA `0x631A8`/`0x6447E` и исключает фон/проходимые клетки большого DEF, из-за которых маркер получался слишком крупным на увеличенной мини-карте.

Если объект подходит, цвет из игровой палитры записывается в указанный локальный word, и выполнение продолжается **после** штатного вычисления цвета шахты, на добавлении её маркера. Для остальных объектов выполняется исходный код HD. Размер и координаты маркеров рассчитываются исходными инструкциями HD.

Это позволяет использовать существующие массивы X/Y/цветов HD. При карте меньше мини-карты HD также обновляет исходный пиксель; при уменьшении большой карты он наносит цветной маркер уже после масштабирования. Поэтому зарегистрированный объект не теряет цвет из-за усреднения при уменьшении, а плагину не требуется заново рисовать мини-карту, её рамку или экран. В 32-битном режиме HD самостоятельно преобразует RGB565. Индекс шахты и её игровая структура не подменяются.

## Обнаружение и установка

`HdMinimapLayout.h` ищет уникальные сигнатуры в исполняемой секции загруженной DLL. Проверяются обе ветки, их локальные поля, относительные расстояния до продолжений, проверки видимости и героев. Адреса DLL в сигнатуры не включены; относительные операнды вызовов игнорируются. Проверенная функция может переместиться вместе с DLL или внутри секции без изменения контракта.

Если контракт не распознан или неоднозначен, HD-хуки не устанавливаются. Оба LoHook устанавливаются вместе; при неуспехе один уже установленный откатывается. Уже занятые другим плагином частные точки HD не заменяются. На диск `HD_WOG.dll` не переписывается: хуки принадлежат экземпляру патчера `EraPlugin.ERA_RuntimeServices.daemon_n` и меняют код загруженного модуля в памяти.

HD-мод в некоторых конфигурациях загружается после `OnAfterWoG`. Поэтому проверка повторяется при инициализации/загрузке карты и регистрации типов до появления DLL; после проверки обнаруженного модуля повторного сканирования при перерисовке нет. Диагностические записи об установке/пропуске HD-хуков удалены; отрисовка не вызывает ERM.

Вся отрисовка флагов, обычной мини-карты и мини-карты HD вынесена в `ObjectRendering.cpp`. `ObjectRendering.h` задаёт внутренний интерфейс компонента и правило выбора занятых клеток. Данные владения, экспортируемые функции, жизненный цикл карты и replay остаются в `dllmain.cpp`; графический компонент получает их через интерфейс чтения `erm_functions::runtime`.

## Проверки

`Verification/inspect_hd_wog.py` выполняет чтение PE и дизассемблирование без загрузки DLL. C++-тесты используют тот же поиск сигнатур, что и плагин, на реальном PE-образе: подтверждены RVA, распознавание после применения ASLR-релокаций и отказ при изменении проверок видимости/героя/ABI либо дублировании функции.

```text
ERA_RuntimeServices\run-tests.cmd "D:\games\HoMM 3 ERA\HD_WOG.dll"
```

`Verification/verify_hd_marker_path.py` исполняет исходные инструкции HD в Unicorn, а вызовы увеличения массивов заменяет буферами заранее выделенного размера. 48 случаев проверяют оба формата графики, цвета нейтрали и игроков, размеры карты 36/144/252 и мини-карты 144/300, добавление координат и цвета маркера, изменение исходного пикселя только при увеличении, туман, приоритет двух веток героев и штатное правило занятых клеток. C++-регрессия дополнительно проверяет DEF 3×3 с двумя занятыми клетками и проходимым входом: окрашиваются три клетки, а фон DEF и соседний объект — нет. Это проверяет совместимость локальных полей и продолжений на реальном машинном коде, но не заменяет визуальную проверку всей игры.

Для Python-проверок использован уже имеющийся локальный набор `pefile`, `capstone`, `unicorn` из `Graphics_BikVideo/build/python` и Python из рабочего runtime Codex. При отсутствии этого набора нужно указать собственные установленные библиотеки; самим плагином Python не используется.

Для проверки установленной версии перезапустите игру. Сравните владельцев объектов при двух размерах мини-карты, в 16/32-битной графике, на верхнем/подземном уровне и при replay. Под героем должен оставаться цвет героя, а скрытый туманом объект не должен раскрывать владельца.

При прежней локальной проверке совпадение установленного Release со сборкой подтверждалось SHA-256. Это исторический результат, а не подтверждение установки текущего RC: актуальный комплект и порядок проверки описаны в [RELEASE_CHECKS.md](RELEASE_CHECKS.md).
